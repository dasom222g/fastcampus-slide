# 토큰 사용량 원인 중심 최종본

## 2차 구성 기준

- 사용자 승인 비교안을 최종본으로 채택. Anthropic 배수 비교 유지.
- 원본의 「늘어나는 지점」으로 맥락 파악·실행과 조율·재작업을 먼저 개괄하고 뒤에서 하나씩 설명한다.
- 마지막은 「토큰 최적화 전략」. 실습 예고 삭제.
- API를 사용하지 않는 강의 범위에 맞춰 「사용량과 이용 한도」 삭제.
- 모든 타이틀 아래 한 줄에 해당 페이지의 헤드메시지를 쓴다.

최적화 판단은 강의용 적용이며 연구 측정 결과로 주장하지 않는다.

## 페이지별 헤드메시지

1. **팀을 굴리면 토큰이 몇 배로 드는가** — 멀티에이전트는 제작뿐 아니라 자료 읽기·조율·재작업에도 토큰을 씁니다.
2. **멀티에이전트의 토큰 사용량** — Anthropic의 리서치 시스템 개발 보고에서는 멀티에이전트가 일반 채팅보다 약 15배의 토큰을 사용했습니다.
3. **입력과 출력 토큰** — 모델이 읽는 자료는 입력 토큰, 중간에 생성한 내용과 최종 답변은 출력 토큰에 포함됩니다.
4. **늘어나는 지점** — 멀티에이전트에서는 워커마다 맥락을 파악하고 작업을 조율하며 수정을 반복하는 과정에서 토큰 사용량이 늘어납니다.
5. **워커마다 읽는 맥락** — 각 워커는 맡은 작업뿐 아니라 프로젝트의 구조와 지침도 처음부터 파악해야 합니다.
6. **작업 수행 외의 조율** — 워커의 작업 수행에 코디네이터의 배정·결과 확인·취합과 워커의 보고가 더해집니다.
7. **수정과 재평가** — 반려가 반복될수록 수정과 재평가에 쓰는 토큰이 추가됩니다.
8. **토큰 최적화 전략** — 결과 품질에 필요한 작업은 유지하고, 불필요한 읽기·배정·재작업을 줄입니다.

## 마지막 페이지 하단 메시지

멀티에이전트는 아무리 낭비를 줄여도 단일 에이전트보다 토큰을 더 쓸 수밖에 없습니다.
