## 시각·애니메이션 계약

- 워커는 Part 5 승인 로봇을 재사용하고 이름·역할을 아이콘 아래 배치한다. A=brand, B=purple, 결과=green, 반려=orange.
- 3·7·8장은 같은 워커 이름·색을 유지한다. 4장은 모델 비교이므로 모델 A/B로 명확히 구별한다.
- 문서는 기존 paper-fold·문서 카드 문법. 의미 없는 설명 박스나 세 칸 순서 나열을 만들지 않는다.
- CSS grid로 대상 배치, DOM 실제 경계로 선 끝점 계산. 선은 요소에서 여유 있게 떨어지고 반환선은 아래 곡선으로 동일 작성 워커를 향한다.
- 위치 이동 없는 opacity 페이드. 주체/문서→연결·다음 주체→반환선·반환 라벨→하단 설명. 같은 의미의 선·라벨은 같은 등장 단계.
- 1920×1080·1280×800에서 전 장 경계·겹침·최종 화면, 진입·중간·재진입·내비게이션 확인.

## 7장 수정 — 2026-10-06

제목: 통과·반려 판단. 부제: 기준으로 검사하고, 반려 항목에는 근거와 고칠 내용을 남깁니다.
기록물 해부 대신 체크리스트 → 평가자 → 통과/반려 분기. 통과 조건은 전 항목 Y·독립 검산 완료. 반려에는 항목·근거·고칠 내용. 평가보고서 제작이 아닌 기준에 따른 판단과 후속 수정 연결이 핵심이다. 이 수정은 앞선7장 구성 설명보다 우선한다.


8장 배치 확정: 작성자는 왼쪽, 평가자는 오른쪽. 중앙 수정 요청서(피드백)는 유지. 평가자 → 문서 → 작성자 방향으로 주황 점선과 해당 라벨이 함께 등장한다.


역할 표기 확정 (2026-10-06): 이 영상의 화면 역할명은 Generator / Evaluator로 통일. Worker A/B 및 작성자/평가자 역할 라벨을 교체하며, 첫 등장 설명에만 한글 역할을 병기한다.


6번 통과 분기 반영: Generator → Evaluator 초안 전달 후 평가 결과는 통과·반려 모두 파일에 기록. 통과 → 최종본은 초록 실선, 반려 피드백 → Generator는 주황 점선. 파일 저장은 공통 단계이므로 실선.
