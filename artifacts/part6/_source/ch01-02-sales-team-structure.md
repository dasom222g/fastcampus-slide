# 영업팀 구조 살펴보기 — 현행 구성

슬라이드: 9장. 대본 미변경.

근거: `../fastcampus-orca-course/edu-note/output/[Part 6] 클라이언트 제안서 교차 검증 가이드.md` 및 `../⭐fastcampus-orca-projects/part6/ads-proposal-boilerplate/prompts/loop.md`.

Generator(Codex)는 요구사항과 초안·수정본을 작성한다. Evaluator(Claude Code)는 고정 체크리스트로 원문 대조·독립 검산하고 평가 기록과 수정 요청서를 만든다. 전체 루프에서 Coordinator가 역할별 자료 전달·진행 확인·종료를 관리한다. 첫 평가부터 최대 3라운드이며 미해결 시 최종본을 만들지 않는다. 통과 시 제안서·견적서와 교차 검토 보고서를 남긴다.

체크리스트는 현행 C01~C12 양식이다. 기존 소스의 '항목 수가 실행마다 다르다'는 표현은 폐기한다. 화면에서는 불필요한 항목 수·계산 지표 전체를 나열하지 않는다. 상세 구성은 짝 스토리보드 참조.

최종 순서: 표지 → 최종 결과물 두 가지 → 광고 의뢰 구조 → Generator의 작업 → Evaluator의 작업 → 원문 대조와 독립 검산 → 반복 종료 조건 → 영업팀의 구조. 오케스트레이션 실행 장은 삭제.

최신 사용자 승인: 영업팀의 구조는 4번 유지, 마지막 9번은 「교차 검증 영업팀」. 간단한 Generator → Evaluator → 최종본 / 반려·수정 점선으로 실습에 연결. 대본은 자동 수정하지 않음.
