# Ch01-02. 영업팀 구조 살펴보기 (교차 검증)

제작 목표: 광고주·대행사·두 에이전트의 관계를 이해하고, 무엇을 입력으로 주고 무엇이 기록으로 남는지 본다.

- `../fastcampus-orca-course/edu-note/output/[Part 6] 클라이언트 제안서 교차 검증 가이드.md` — 전체 구조 이해 / 폴더 구조 / 1~6절

## 사실과 제작 범위

- 무브펫은 광고주, 포커스온은 광고대행사다. 우리는 대행사 쪽에서 문서를 만든다.
- 회사 문서(회사 소개서·업무 사규·작업 지침)는 Part 4에서 만든 본인 회사 문서로 대체할 수 있다.
- 검산 스크립트는 값을 코드에 넣지 않고 실행할 때마다 입력받는다. 특정 고객의 수치를 정답으로 고정하지 않는다.
- 체크리스트 항목 수와 라운드 수는 실행마다 다르다. 캡처의 숫자를 목표로 제시하지 않는다.

## 화면 구성

### 1. 영업팀 구조 살펴보기 (교차 검증)

역할: COVER_SCENE

> 의뢰가 들어오면 작성자와 평가자가 나눠 맡아 고객에게 낼 문서를 만듭니다.

화면: 광고주가 의뢰서를 건네고, 대행사 담당자를 거쳐 작성 로봇과 검사 로봇으로 이어지는 장면 이미지 1점.

슬라이드: 1장
근거: 실습자료 「전체 구조 이해」

### 2. 누가 누구에게 내는가

역할: PROCESS_STRIP

> 광고주의 의뢰를 대행사가 받아 제안서와 견적서로 답합니다.

화면 문구·요소:
```json
{
  "items": [
    ["무브펫", "광고주 · 의뢰", "gray"],
    ["포커스온", "광고대행사 · 우리", "brand"],
    ["제안서·견적서", "고객에게 내는 문서", "green"]
  ]
}
```

슬라이드: 1장
근거: 실습자료 「전체 구조 이해」

### 3. 영업팀의 구조

역할: SEMINAR_ROLE_MAP_PARALLEL 변형

> 같은 입력을 보고 한쪽은 쓰고 한쪽은 판정합니다.

화면: 브리프·회사 문서 → 작성자(Codex)·평가자(Claude Code). 작성자 → 평가자로 초안, 평가자 → 작성자로 반려. 통과하면 최종본.

슬라이드: 1장
근거: 실습자료 「전체 구조 이해」

### 4. 작성자가 읽는 것

역할: SEMINAR_IO_FLOW

> 브리프와 회사 문서를 읽고 요구사항 정의서부터 만듭니다.

화면 문구·요소:
```json
{
  "inputs": ["클라이언트 브리프", "회사 소개서 · 업무 사규 · 작업 지침", "제안·견적 양식과 샘플"],
  "output": "요구사항 정의서 → 제안서·견적서 초안"
}
```

슬라이드: 1장
근거: 실습자료 1·2절

### 5. 평가자가 보는 것

역할: SEMINAR_IO_FLOW

> 초안을 체크리스트와 요구사항에 대조해 판정합니다.

화면 문구·요소:
```json
{
  "inputs": ["제안서·견적서 초안", "체크리스트", "요구사항 정의서와 원문"],
  "output": "판정과 이유가 적힌 평가 기록"
}
```

슬라이드: 1장
근거: 실습자료 3·4절

### 6. 숫자는 다시 계산한다

역할: SCENE_COMPARE

> 금액과 성과는 평가자가 검산 스크립트로 다시 계산해 문서의 값과 맞춰 봅니다.

말할 내용

- 읽어서 판단할 것과 계산해서 확인할 것을 나눈다
- 스크립트는 값을 입력받고, 특정 고객의 수치를 코드에 넣지 않는다
- 스크립트가 오류 없이 끝난 것을 문서 전체 통과로 보지 않는다

슬라이드: 1장
근거: 실습자료 4절 Step 1

### 7. 한 라운드의 모양

역할: REVIEW_LOOP

> 초안 또는 수정본 → 평가·검산 → 판정까지가 한 라운드입니다.

화면: 라운드 루프 도식. 반려면 수정 요청서를 거쳐 작성자에게 돌아간다.

슬라이드: 1장
근거: 실습자료 용어표·5절

### 8. 남는 기록

역할: SCENE_COMPARE

> 라운드별 초안·평가·수정 요청과 최종 문서가 파일로 남습니다.

화면: 최종 제안서와 교차 검토 보고서의 실제 화면 캡처 두 장.

슬라이드: 1장
근거: `project2-ads-proposal/final/proposal-quote-final.html`, `cross-review-report.html`

### 9. 루프는 한 번에 돈다

역할: SCENE_PAIR

> 작성부터 평가·수정까지를 코디네이터가 하나의 실행으로 돌립니다.

말할 내용

- 처음에는 한 단계씩 직접 요청해 본다
- 마지막에는 준비된 실행 프롬프트 하나로 전체를 돌린다
- 통과하면 최종 제안서와 교차 검토 보고서가 함께 나온다

슬라이드: 1장
근거: 실습자료 6절
