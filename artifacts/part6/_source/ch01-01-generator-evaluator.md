## 앞 파트와 겹치지 않게

Part 5 Ch01-02에서 **검증 오류**를 실패 세 가지 중 하나로 다뤘다. 거기서는 "작성자의 설명에 동의하는 것만으로는 오류가 드러나지 않는다"까지였고, 해결로 생성과 평가의 분리를 한 장에 보여줬다.
이 클립은 그 해결을 펼치는 자리다. **같은 설명을 반복하지 않고 한 줄로 회수한 뒤**, 기준을 언제 정하는지·판정을 어떻게 남기는지·반려가 어떻게 다음 입력이 되는지로 바로 들어간다.

## 사실과 제작 범위

- 다른 모델의 관점으로 다시 검토하는 목적을 설명한다. 같은 모델이 항상 같은 오류를 놓친다거나 다른 모델이면 정확하다고 단정하지 않는다.
- 체크리스트 항목 수는 프로젝트마다 다르다. 특정 개수를 정답으로 고정하지 않는다.
- 검산 스크립트·역할 분리 실행은 Part 6 실습(Ch03~04)에서 한다. 이 클립은 구조만 다룬다.
- 완성 프로젝트의 라운드 기록은 실제 실행 결과이며, 반려 횟수를 목표치로 제시하지 않는다.

## 화면 구성

### 1. Generator–Evaluator 패턴이란

역할: COVER_SCENE

> 만드는 에이전트와 평가하는 에이전트를 나눠, 결과물을 반복 개선하는 워크플로우입니다.

화면: 왼쪽 로봇이 제안서를 작성하고 오른쪽 로봇이 체크리스트와 돋보기로 검사하는 장면 이미지 1점.

슬라이드: 7장
근거: 실습자료 「전체 구조 이해」

### 2. 자기 결과는 자기가 통과시킨다

역할: CONTAINED_STRUCTURE — 작성자의 완료 판단만으로 검증을 끝내는 구조

> 만든 쪽에게 다시 물으면 대개 문제없다는 답이 돌아옵니다.

화면: Worker A 한 명의 범위 안에 초안 작성 → 스스로 평가 → 통과 처리. 다음 3장의 역할 분리와 대비한다. 설명 박스의 문제/해결 비교는 제거한다.

슬라이드: 1장. 근거: 사용자 승인, Part 5 검증 오류.

### 3. 작성과 평가의 분리

역할: STRUCTURE_EXCHANGE — 역할과 결과·피드백 방향 이해

> 작성 워커는 만들고 고치며, 평가 워커는 검사하고 피드백합니다.

화면: Worker A(Generator·작성·수정) → 초안·수정본 → Worker B(Evaluator·평가·피드백). 반려·수정 요청은 점선으로 A에게 돌아온다. 하단: 평가 워커는 초안을 직접 고치지 않는다.
슬라이드: 1장. 근거: 실습 가이드 전체 구조·4절 역할.

### 4. 다른 모델로 평가하는 이유

역할: OPERATING_DEFAULT_COMPARE — 모델 분리의 목적

> 작성 때의 판단을 다른 모델의 관점으로 다시 살펴봅니다.

화면: 동일한 구조로 모델 A→A / 모델 A→B 비교. 같은 모델은 작성 때의 판단이 반복될 수 있고, 다른 모델은 다른 관점으로 재검토한다. 하네스 이름을 모델 이름처럼 쓰지 않고, 다른 모델의 정확성을 보장하지 않는다.
슬라이드: 1장. 근거: 실습의 다른 모델 평가·사용자 확정 핵심.

### 5. 고정된 평가 기준

역할: SPACE_TRANSFER — 반복에 쓰이는 기준

> 첫 평가 전에 저장한 체크리스트를 매 라운드 동일하게 적용합니다.

화면: 평가 체크리스트(검사 항목·통과 조건·원문 위치) → 평가 Worker B. 작성자 비공개는 이 실습의 운영 규칙으로 명시하며 모든 작업의 보편 원칙처럼 쓰지 않는다.
슬라이드: 1장. 근거: 가이드3절·현재 boilerplate 체크리스트 양식.

### 6. 평가 기록과 피드백

평가 결과를 파일로 저장하고 Generator에게 피드백으로 전달한다. 상단 왼쪽 Generator → 오른쪽 Evaluator의 초안 전달 실선. 하단 파일 아이콘이 있는 평가 기록으로 저장한 뒤, 반려 시 Generator에게 점선 피드백을 돌려준다. 초안 전달부터 파일 저장·피드백까지 한 장에 보여준다.

### 7. 영업팀에 적용

역할: SCENE_PAIR — 패턴의 실제 적용·산출물

> 제안서·견적서와 교차 검토 보고서까지 완성합니다.

화면: 고객 제출 전 / 작성과 교차 검증. 오른쪽 제안서·견적서(통과본), 교차 검토 보고서(반려·수정·최종 평가) 문서2개. 학습 내용에 제작 안내나 다음 영상 안내 목록을 섞지 않는다.
슬라이드: 1장. 근거: 가이드6절·loop 최종 산출물.


## 역할 표기 — 2026-10-06 사용자 수정

구조 소개인 현재3·4장에서만 Worker A/B를 사용한다. 그 외2·6·8·9장에서는 작성자/평가자로 표시한다. 5장의 모델 A/B는 모델 비교를 나타내며 아래 작성/평가 역할 설명을 유지한다.


## 7장 수정 — 2026-10-06

제목: 통과·반려 판단. 부제: 기준으로 검사하고, 반려 항목에는 근거와 고칠 내용을 남깁니다.
기록물 해부 대신 체크리스트 → 평가자 → 통과/반려 분기. 통과 조건은 전 항목 Y·독립 검산 완료. 반려에는 항목·근거·고칠 내용. 평가보고서 제작이 아닌 기준에 따른 판단과 후속 수정 연결이 핵심이다. 이 수정은 앞선7장 구성 설명보다 우선한다.


8장 배치 확정: 작성자는 왼쪽, 평가자는 오른쪽. 중앙 수정 요청서(피드백)는 유지. 평가자 → 문서 → 작성자 방향으로 주황 점선과 해당 라벨이 함께 등장한다.


역할 표기 확정 (2026-10-06): 이 영상의 화면 역할명은 Generator / Evaluator로 통일. Worker A/B 및 작성자/평가자 역할 라벨을 교체하며, 첫 등장 설명에만 한글 역할을 병기한다.


6번 통과 분기 반영: Generator → Evaluator 초안 전달 후 평가 결과는 통과·반려 모두 파일에 기록. 통과 → 최종본은 초록 실선, 반려 피드백 → Generator는 주황 점선. 파일 저장은 공통 단계이므로 실선.


## 2026-10-06 — 통과 분기 위치 정정
사용자 지시: 통과 → 최종본은 6번이 아니라 3번 「작성과 평가의 분리」에 표시한다. 3번에 초록 실선·최종본 추가, 6번에서 해당 분기 제거. 6번은 파일 저장과 반려 피드백을 설명한다. 대본 변경 없음.
