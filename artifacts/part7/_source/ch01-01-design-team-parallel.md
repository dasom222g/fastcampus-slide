# Ch01-01. 디자인팀 구조 살펴보기 (병렬 실행)

제작 목표: 같은 의뢰를 두 에이전트에게 동시에 맡기려면 작업 공간부터 나눠야 한다는 것을 이해하고, 비교와 선택으로 끝나는 병렬 실행의 구조를 본다.

## 앞 파트와 겹치지 않게

**Part 3 Ch01-03에서 브랜치·워크트리의 정의와 둘의 관계, Orca의 작업 단위까지 이미 다뤘다.** 이 클립에서 개념을 다시 가르치지 않는다.
여기서 새로 말하는 것은 **그 워크트리를 왜 지금 쓰는가** 하나다 — 같은 의뢰를 두 에이전트에게 동시에 맡기려면 각자의 작업 공간이 있어야 한다.
정의 복습은 한 줄 회수로만 처리하고(`워크트리가 무엇인지는 Part 3에서 봤습니다`), 분기·커밋·이력 그림은 다시 그리지 않는다.

## 사실과 제작 범위

- 완성 프로젝트의 두 시안은 실제 실행 결과이며, 특정 하네스가 더 낫다는 결론은 내지 않는다.
- 하네스는 Claude Code와 Codex 두 가지를 쓴다. 모델 이름·버전은 화면에 넣지 않는다.
- 머지는 선택한 시안 하나만 메인으로 보내고 나머지는 브랜치에 남긴다. 두 시안을 섞지 않는다.
- 디자인 모드·개발자도구·GitHub 업로드는 이 클립의 범위가 아니다 (Ch04~05 실습).

## 화면 구성

### 1. 디자인팀 구조 살펴보기 (병렬 실행)

역할: COVER_SCENE

> 같은 의뢰를 두 에이전트에게 동시에 맡기고, 나온 시안 중에서 하나를 고릅니다.

화면: 가운데 사람이 의뢰서 한 장을 들고, 좌우로 분리된 두 책상에서 에이전트 둘이 각자 화면을 만드는 장면 이미지 1점.

슬라이드: 9장
근거: 실습자료 「전체 구조 이해」

### 2. 한 폴더에서 동시에

역할: SCENE_COMPARE

> 같은 폴더에서 두 에이전트가 같은 파일을 고치면 한쪽 결과가 덮입니다.

말할 내용

- 지금까지는 작업을 순서대로 넘겼다. 이번에는 같은 일을 동시에 시킨다
- 그런데 작업 폴더가 하나면 두 에이전트가 같은 `index.html`을 연다
- 워크트리가 무엇인지는 Part 3에서 봤다. 여기서는 그것을 실제로 쓴다

슬라이드: 9장
근거: 실습자료 「전체 구조 이해」 및 Part 3 Ch01-03

### 3. 작업 공간을 나눈다

역할: STRUCTURE_BRANCH

> 같은 시작 커밋에서 워크트리를 하나씩 만들어 각자의 폴더에서 작업하게 합니다.

화면 문구·요소:
```json
{
  "root": "시작 커밋 하나",
  "branches": [
    ["워크트리 A", "Claude Code 하네스"],
    ["워크트리 B", "Codex 하네스"]
  ],
  "note": "서로의 폴더를 보지 않으니 결과가 섞이지 않습니다."
}
```

슬라이드: 9장
근거: 실습자료 Step 3 「워크트리 만들기」

### 4. 디자인팀의 구조

역할: SEMINAR_ROLE_MAP_PARALLEL

> 코디네이터가 같은 요청을 두 워커에게 동시에 배정합니다.

화면: 사람 → 코디네이터 → 워커 A(Claude Code) · 워커 B(Codex). 각 워커 아래에 자기 워크트리.

슬라이드: 9장
근거: 실습자료 「전체 구조 이해」, 1절 프롬프트

### 5. 같아야 하는 것과 달라도 되는 것

역할: TRANSITION_COMPARE

> 행사 조건은 고정하고 디자인은 각자 정하게 해야 비교할 수 있습니다.

화면 문구·요소:
```json
{
  "fixed": ["기간·할인율·중복 적용 규칙", "담을 정보와 결과물 형식", "반응형·잘림 없음"],
  "free": ["색상과 레이아웃", "카피와 이미지", "구성 순서"],
  "note": "조건이 서로 다르면 무엇 때문에 결과가 갈렸는지 알 수 없습니다."
}
```

슬라이드: 9장
근거: 실습자료 `AGENTS.md` 지침과 1절 공통 요청 사항

### 6. 병렬 실행이란

역할: SEMINAR_DEPENDENCY_COMPARE

> 같은 요청을 여러 에이전트에 동시 배분하는 구조입니다.

화면: 순차(앞 결과가 다음 입력)와 병렬(같은 입력에서 갈라짐)을 같은 시각 구조로 대비한다. 색은 순차 brand, 병렬 yellow.

슬라이드: 9장
근거: `docs/patterns.md` 병렬 실행

### 7. 사람이 고른다

역할: PROCESS_STRIP

> 두 시안을 비교해 추천까지는 에이전트가 하고, 결정은 사람이 합니다.

화면 문구·요소:
```json
{
  "items": [
    ["두 시안", "같은 조건, 다른 결과", "yellow"],
    ["비교", "기준별 차이를 표로", "purple"],
    ["선택", "쓸 시안을 사람이 결정", "gray"]
  ]
}
```

슬라이드: 9장
근거: 실습자료 2절 「두 시안 비교하고 고르기」

### 8. 선택한 시안만 메인으로

역할: STRUCTURE_EXCHANGE

> 고른 시안만 메인에 머지하고 나머지는 브랜치에 남겨 둡니다.

말할 내용

- 두 시안을 섞지 않는다. 하나를 고르고 그것만 메인으로 보낸다
- 머지한 워크트리는 정리하고, 고르지 않은 시안은 브랜치에 남는다
- 메인에서 다시 열어 화면과 버튼 동작을 확인한다

슬라이드: 9장
근거: 실습자료 3절 「선택한 시안 머지하기」

### 9. 만들 것

역할: SCENE_IMAGE

> 무드온 블랙프라이데이 상세페이지를 두 시안으로 받아 하나를 고릅니다.

화면: 실제 완성 시안 캡처 한 장과 프로젝트 이름.

슬라이드: 9장
근거: `project3-blackfriday-landing/final/`
