## 2차 — Task와 의존 관계 표시 (2026-09-09)

- 4번 제목을 ‘Task의 의존 관계’로 변경해 예시가 설명하는 개념을 명시.
- 자료 정리에 Task A, 블로그 초안에 Task B, 카드뉴스 초안에 Task C 라벨을 문서 아이콘 옆에 추가. 색상과 기존 예시는 유지.
- 하단 Task C와 ‘이후 나란히 진행할 작업’ 설명이 겹치지 않게 노드와 연결선 위치를 함께 조정.
- 소스·스토리보드와 대본의 장 제목을 동기화. 대본 본문과 다른 7개 장은 그대로 유지.
- 804×512, 1280×800, 2133×1200에서 세 라벨과 본문이 영역 안에 표시되고 이미지 깨짐·브라우저 오류 없음 확인.

## 3차 — 병렬 작업 문구와 정렬 수정 (2026-09-09)

- ‘이후 나란히 진행할 작업’을 ‘두 작업은 동시에 진행 가능’으로 변경해 두 후속 Task의 관계를 명확히 표시.
- 오른쪽 설명이 Task 중심(84%)과 다른 78%에 놓여 있던 원인을 수정. 두 제목·아이콘·하단 설명을 같은 세로축으로 정렬. 왼쪽 선행 작업 설명도 해당 Task 축에 맞춤.
- 804×512, 1280×800, 2133×1200에서 각 열의 중심 오차 0.01px 이내, 본문 넘침 없음 확인.

## 4차 — 선행 Task 완료 조건으로 핵심 복원 (2026-09-09)

- 하단 문구를 ‘Task A 완료 후 시작 가능’으로 수정. 두 후속 Task가 병렬로 일할 수 있다는 부가 정보보다, 선행 Task가 끝나야 시작할 수 있다는 의존 관계를 강조.
- 소스·스토리보드 문구 동기화. 기존 정렬 유지, 804×512에서 문구 넘침 없음 확인.

## 5차 — 의존 관계 부제의 확정 문구 반영 (2026-09-09)

- 4번 부제를 ‘이전 작업의 결과물이 필요한 작업은, 그 작업이 끝나야 시작할 수 있습니다.’로 변경. 예시 설명을 개념 설명으로 바꾸고 사용자 지정 ‘이전 작업의 결과물이 필요한’ 표현을 반영.
- 소스·스토리보드 동기화. 제목·도식·대본은 변경하지 않음.

## 6차 — 전체 오케스트레이션 흐름을 앞부분에 배치 (2026-09-09)

- 기존 8번 ‘한 번의 실행 흐름’을 ‘오케스트레이션 실행 흐름’으로 바꾸고 3번으로 이동. 목표 예시를 받은 다음 전체 흐름을 먼저 보여준다.
- 최종 순서: 1 표지, 2 목표와 완료 기준, 3 오케스트레이션 실행 흐름, 4 Run과 Task, 5 Task의 의존 관계, 6 배정과 실행, 7 실행 중의 조율, 8 다음 단계의 판단.
- 단계별 도식과 애니메이션은 유지. 부제는 목표가 작업으로 나뉘어 실행·검토·정리되는 과정을 설명. 작은 화면에서 마지막 명령이 본문 경계를 넘지 않도록 흐름 전체의 좌우 여백을 확보.
- 소스·스토리보드·대본 순서와 제목 동기화. 대본의 마지막 요약을 앞부분의 전체 흐름 안내로 전환하고 앞뒤 연결 문장 조정.
- 804×512, 1280×800, 2133×1200에서 3번 본문 넘침·이미지 깨짐·브라우저 오류 없음. 다른 7개 장은 순서 외 화면 변경 없음. 대본 장수·제목 일치 확인.

## 7차 — 명령어 표기 안내를 대본으로 이동 (2026-09-09)

- 전체 실행 흐름 장의 ‘orca orchestration 뒤에 이어지는 명령명’ 안내 문구를 화면에서 삭제. run-create 등 단계별 명령 이름은 유지.
- 소스·스토리보드의 화면 문구도 제거하고, 명령의 공통 접두사를 생략해 표기했다는 설명은 대본에 반영.

## 8차 — Run·Task 정의 후 전체 흐름 설명 (2026-09-09)

- 사용자 확정 순서: 목표와 완료 기준 → Run과 Task → 오케스트레이션 실행 흐름 → 각 단계 상세. 표지 뒤 2~4번에 해당하며 총 8장 유지.
- 정확한 용어를 없애지 않고, 전체 흐름에서 사용할 Run과 Task를 먼저 소개해 낯선 개념이 갑자기 등장하지 않도록 한다.
- HTML은 3·4번 위치만 교환. 소스·스토리보드·대본 번호와 순서 동기화. 대본은 목표→용어, 용어→전체 흐름, 전체 흐름→의존 관계로 연결 문장 수정.
- 직전에 제거한 명령어 표기 안내는 복구하지 않고 대본 설명을 유지.

## 9차 — Run의 목표·Task·수신함 비교안 추가 (2026-09-09)

- 기존 3번 ‘Run과 Task’를 보존하고 바로 뒤 4번에 ‘Run에 담기는 것’ 비교안 추가. 목표(Objective)를 상단, Task A·B·C를 하단 왼쪽, 코디네이터 메시지 수신함을 하단 오른쪽에 배치.
- 비교안에만 사용자 확정 부제 적용: ‘Run은 하나의 목표와 그에 속하는 Task, 메시지를 통합 관리하는 단위입니다.’
- 기존 4~8번은 5~9번으로 이동, 총 9장. 원래 슬라이드 8개의 내용은 유지. 소스·스토리보드·인덱스에 비교안만 추가하고, 선택 전 대본은 기존 상태를 유지.
- 804×512, 1280×800, 2133×1200에서 목표·Task·수신함이 Run 경계 안에 표시됨을 확인. 본문 넘침·이미지 깨짐·브라우저 오류 없음.

## 10차 — 비교안에 Task의 정의 추가 (2026-09-09)

- 새 4번 비교안의 Task 영역 제목을 ‘Task · 실행할 작업 하나’로 변경. 상단의 Run 정의와 각 Task의 의미가 함께 보이도록 함.
- 부제와 기존 3번은 유지. 소스·스토리보드의 해당 문구만 동기화.

## 11차 — Run 정의 장 확정과 배정 도식 정리 (2026-09-09)

- ‘Run에 담기는 것’을 ‘Run이란’으로 변경하고 기존 ‘Run과 Task’ 장 삭제. 목표·Task·메시지를 함께 보여주는 정의 장을 3번으로 확정, 총 8장으로 정리.
- ‘Task · 실행할 작업 하나’와 사용자 확정 Run 정의를 유지. 소스·스토리보드·대본·인덱스의 순서와 장수를 동기화.
- ‘배정과 실행’은 구체 작업 예시 대신 Task A → Dispatch → Worker A, Task B → Dispatch → Worker B 두 행으로 표시. 작업과 담당자를 연결하는 배정에 집중.
- 804×512에서 두 수정 장의 시각 검수 완료. 배정 도식은 1280×800, 2133×1200에서도 본문 넘침과 푸터 겹침 없음. 이미지 누락·브라우저 오류 없음.

## 12차 — 판단 흐름의 Task 매핑과 재작업 명시 (2026-09-09)

- 마지막 장의 ‘초안 결과 → 다음 작업’을 ‘Task A → decision gate → Task B’로 변경. 기존 Task A(노랑)·Task B(브랜드)의 색과 이름을 유지.
- ‘보완’을 ‘재작업’으로 변경. 반환 화살표는 Task A 라벨 아래에서 끝나도록 조정.
- 소스·스토리보드·대본에도 Task A 결과 확인 → 통과 시 Task B 실행 / 미충족 시 Task A 재작업을 명시.
- 804×512에서 라벨과 흐름 검수. 총 8장과 기존 등장 순서 유지.

## 13차 — 사람의 소통 창구로 전체 구조 마무리 (2026-09-09)

- 기존 8장을 유지하고 9번 ‘목표는 오케스트레이터에게’ 추가. 앞 클립의 ‘에이전트 오케스트레이션의 시대’에서 사용한 사람·Coordinator·Worker 캐릭터와 색을 이어받음.
- 사람 ↔ Coordinator ↔ Worker A·B 구조. 목표·기준은 Coordinator에게 전달하고, 진행·결과는 사람에게 돌아온다. Coordinator는 Task 분할·배정과 결과 취합을 맡는다.
- 배정은 실선, 보고는 점선. 아이콘의 실제 외곽을 기준으로 곡선과 화살촉을 배치하고, 왕복 선이 교차하지 않도록 분리. Worker 옆에 Task A·B를 표시.
- 목표 전달 → Coordinator → 두 Worker 배정 → 보고 → 사람에게 결과 반환 순으로 등장. reduced-motion에서는 정지 화면.
- 소스·스토리보드·대본·인덱스 모두 9장으로 동기화. 8번 대본 끝은 새 마지막 장으로 연결하고, 설치 예고는 9번 마지막으로 이동.
- 804×512, 1280×800, 2133×1200에서 콘텐츠 영역 넘침·이미지 누락·브라우저 오류 없음. 검수: `_qa/ch01-02-goal-task-flow--orchestrator-handoff-report.json`.

## 14차 — 실행 흐름의 주체 복원 (2026-09-09)

- 최초 부제는 ‘코디네이터가 스킬의 절차에 따라 생성부터 정리까지 이어갑니다.’였다. 전체 흐름 장을 앞쪽으로 옮길 때 에이전트가 ‘목표를 작업으로 나누고, 실행·검토·정리를 거쳐 결과를 완성합니다.’로 변경하면서 주체가 빠졌음.
- 사용자의 지적에 따라 공식 공개 가이드의 `Classify the role`, `Canonical supervised loop`, `Worker obligations`를 다시 대조. Coordinator가 Run 생성·작업 배정·메시지 처리·정리를 조율하며, 실제 Task 수행과 완료 보고는 Worker가 맡는다.
- 부제: ‘Coordinator가 목표를 Task로 나누고, Worker 배정부터 결과 확인·정리까지 맡습니다.’로 변경. 소스·스토리보드·대본에 같은 주체 구분 반영.
- 근거: https://github.com/stablyai/orca/blob/main/skill-guides/orchestration.md#canonical-supervised-loop

## 15차 — 배정 도식의 세로 간격과 Dispatch 라벨 (2026-09-09)

- Task–Worker 두 행의 간격을 1.8rem → 3.2rem, 아이콘과 제목 간격을 .65rem → 1rem로 확대. 하단 worker-start 설명과 도식 사이도 3rem 확보.
- Dispatch를 각 화살표 중앙 위에 배치하고, 글자와 선 사이 .65rem 간격을 유지. 항목 제목 행에 배치해 선과 떨어져 보이던 구조 제거.
- 낮은 화면에서는 행 간격과 하단 설명 간격을 각각 1.75rem로 조정. 글자·아이콘 크기는 유지.
- 804×512, 1280×800에서 시각 검수. 본문과 푸터 겹침 없음. 화면 문구·대본·장수는 유지.

## 16차 — Dispatch 이전 배치 비교안 보존 (2026-09-09)

- 현재 6번 수정본을 그대로 두고 7번에 직전 배치 비교안 추가. Dispatch는 화살표 아래, 기존 행 간격과 아이콘–제목 간격으로 복원.
- 8~10번은 기존 후속 장. 총 10장으로 소스·스토리보드·인덱스 동기화. 비교 CSS는 새 장의 data-visual 범위로 제한해 현재 6번에 영향을 주지 않는다.
- 선택 전 대본은 기존 9장 기준을 유지한다. 채택 후 비교 후보 정리와 함께 동기화한다.

## 17차 — Task는 쪼개고, 설명에서는 워커 (2026-09-09)

- 4번 부제를 사용자 확정 문장 ‘Coordinator가 목표를 Task로 쪼개고, 워커 배정부터 결과 확인·정리까지 맡습니다.’로 변경.
- 이 덱의 설명 문장에서는 ‘워커’, 도식 역할 라벨에서는 Worker A/B, 명령·메시지는 worker-start/worker-release/worker_done 원문으로 구분. 배정 장 두 버전과 마지막 장의 부제도 같은 기준 적용.
- 대본의 Task 분할 동작은 ‘쪼개다’로 통일. 낭독 문장에서 워커·코디네이터 한글 표기 사용. 명령어는 보존.
- 기준을 docs/confirmed-copy.md에 강사 채팅 출처로 추가. 기존 인용 문구나 다른 덱은 변경하지 않음.
- 비교안 미선택 상태이므로 대본은 기존 9장 구성을 유지하며 내용만 수정.

## 18차 — 행 간격 1.6배와 묶음 기준 수직 정렬 (2026-09-09)

- 현재 6번의 dispatch-pairs gap을 3.2rem → 5.12rem, 낮은 화면에서는 1.75rem → 2.8rem로 각각 정확히 1.6배 확대.
- Dispatch 라벨과 화살표를 flex 묶음으로 구성해 각 행의 Task·Worker 전체 높이를 기준으로 중앙 정렬. 아이콘 영역만 기준으로 상단에 붙던 위치 지정 제거.

## 19차 — 최종본 확정 (2026-09-09)
