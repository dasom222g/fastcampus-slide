## 슬라이드 3 / 9 — Run이란

**역할:** Run의 전체 목표·개별 Task·메시지 수신함을 함께 설명하고 다음 장의 실행 흐름으로 연결한다.

**핵심 메시지:** Run은 목표(objective)를 등록하고, 그 목표에 속한 개별 Task와 코디네이터의 메시지 수신함을 연결하는 관리 단위다. 물리적 폴더 구조가 아니다.

**근거:** 사용자 요청 및 공식 가이드의 run-create --objective, durable namespace / coordinator inbox 정의. https://github.com/stablyai/orca/blob/main/skill-guides/orchestration.md

**화면 문구**
- 상단 라벨: Part 4 · ch01-02 · 목표와 작업, 실행의 흐름
- 제목: **Run**이란
- 부제: Run은 하나의 목표와 그에 속하는 Task, 메시지를 통합 관리하는 단위입니다.
- Run
- 목표 · Objective
- 회사 소개 자료로 블로그와 카드뉴스 초안 만들기
- Task · 실행할 작업 하나
- Task A / 자료 정리
- Task B / 블로그 초안
- Task C / 카드뉴스 초안
- 메시지
- Coordinator 수신함
- 질문 · 완료 보고

**구조:** 하나의 회색 Run 경계 상단에 목표를 명시한다. 하단 왼쪽에 세 Task를 문서 도식으로 나란히 배치하고, 오른쪽에 메시지 수신함을 둔다. 수신함 그림에는 질문과 완료 보고를 상징하는 말풍선·체크를 표시한다. 목표는 상단의 전체 폭을 차지하고 Task와 수신함은 같은 목표 아래의 대등한 구성으로 구분한다. 물리적 폴더 아이콘이나 실행 순서 화살표는 사용하지 않는다.

**디자인·등장:** Run은 회색, Task A는 노랑·B는 brand·C는 purple로 다음 의존 관계 장과 연결한다. 수신함은 회색, 질문은 orange, 완료 보고는 green. Run·목표 → Task 그룹 → Task A·B·C → 메시지 수신함 순서로 제자리 등장. 단순한 포함 관계를 보여준다.

**구조·색:** 열린 두 행, 세 열. Task는 문서 아이콘, Worker는 기존 로봇 아이콘. Task A/B와 Worker A/B는 각 행에서 같은 기준선에 놓는다. Dispatch는 화살표 바로 위에 붙여 하나의 묶음으로 만들고, 양옆 Task·Worker 전체 묶음의 수직 중앙에 맞춘다. 앞 장에서 정의한 Task A 노랑·Task B brand를 유지하고 Worker A brand·Worker B purple를 사용한다. 구체적인 업무 예시는 넣지 않는다.

**애니메이션:** Task 두 개 → Dispatch 두 연결 → Worker 두 명 → worker-start 설명. 서로 다른 역할이 시간차로 나타나며 동일 역할은 함께 등장한다. 모션 감소 시 즉시 표시.

**발표 노트**
> 앞에서 나눈 작업에 담당자를 붙입니다. 왼쪽 Task A와 B가 각각 Dispatch를 통해 오른쪽 Worker A와 B에게 배정됩니다. Task는 할 일, Worker는 담당자, Dispatch는 둘을 연결하는 배정입니다.

**2026-09-09 간격·정렬 확정:** 현재 수정본의 두 행 간격은 5.12rem(직전 3.2rem의 1.6배), 낮은 화면에서는 2.8rem(직전 1.75rem의 1.6배). Dispatch 텍스트와 화살표를 하나의 묶음으로 구성해 Task·Worker 전체 묶음의 수직 중앙과 맞춘다.

| 사람 ↔ Coordinator | 목표·기준 / 진행·결과 |

**구조·색:** 사용자가 제시한 계층 구조를 따른다. 위쪽에서 사람→Coordinator로 목표를 전달한 뒤, Coordinator 아래로 세 갈래의 곡선이 내려가 나란히 놓인 세 Worker로 분기하고, 보고와 결과는 반대 방향으로 돌아온다. 사람과 Worker는 직접 연결하지 않는다. Coordinator 노랑, Worker A 브랜드, Worker B 보라, Worker C 중립 회색, Task A 노랑·Task B 브랜드·Task C 보라의 기존 매핑을 유지한다. 열린 도식이며 장식 박스를 추가하지 않는다. 선은 실제 아이콘 외곽에 맞추며, 라벨을 가로지르지 않는다. Coordinator의 이름과 설명은 아이콘 오른쪽에 배치해 아래로 내려가는 선의 공간을 확보한다. 워커는 세 명을 두며 추가 하위 에이전트는 그리지 않는다. 각 워커의 라벨은 Worker 타이틀 → Task 표기 → ‘작업 수행’ 순서로 세로 중앙 정렬한다. ‘작업 수행’은 공통 copy 규격을 따른다. 낮은 화면에서는 상·하단 주체 위치를 함께 조정해 추가 설명과 연결선 공간을 확보한다. 주체와 화살표 끝 사이에 여백을 두고, 배정선과 보고선도 간격을 둔다. Coordinator 아이콘과 오른쪽 라벨, 제목과 설명, Worker·Task·설명 사이 간격을 확보한다.

**애니메이션 순서:** 사람 → 목표 전달 → Coordinator → 배정 선 → Worker A·B·C → 보고 선 → 사람에게 진행·결과 반환. 같은 관계의 세 워커는 함께 등장하며 선은 출발 방향을 따른다. reduced-motion에서는 정지 화면.

**발표 노트:** 앞의 과도기 대비를 회수한다. 사람은 목표·기준과 필요한 판단에 집중하며, Coordinator가 작업을 쪼개고 담당 워커와 소통해 결과를 모은다. 이 장에서 다음 클립의 스킬 설치로 넘긴다.
