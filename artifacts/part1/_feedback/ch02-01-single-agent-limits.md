## 3장 첫 항목의 인과관계 수정 — 2026-09-09

- 기존 3장 ‘셋 다 어정쩡’은 품질 문제인데 4장의 원인과 5장의 대응은 기다림을 설명하고 있었다.
- 4장 순차 처리 → 5장 독립 작업의 병렬 처리는 이미 대응하므로 유지한다. 3장 첫 항목만 ‘한꺼번에 맡겨도 / 결과는 하나씩 기다림’으로 수정하고 소스·스토리보드·대본을 맞췄다.
- 검수 실패: 번호와 주제가 같다는 이유로 인과관계까지 맞는 것으로 취급했다. 지적받은 뒤에도 3장 표현을 기준으로 고정해, 잘 연결된 4·5장까지 바꾸는 안을 제시했다.

## 3. 다음부터 이렇게 해 ★

- 문제·원인·해결을 같은 항목끼리 한 줄로 읽는다. 품질·시간·조건 유지·검증 등 설명 대상이 중간에 바뀌지 않는지 확인한다.
- 원인이 그 문제를 설명하는지, 해결이 그 원인을 줄이는지 각각 확인한다. 같은 번호·주제·단어만으로 대응한다고 판단하지 않는다.
- 이미 인과관계가 맞는 구간을 먼저 찾고, 사용자 의도에 맞춰 어긋난 항목만 수정한다. 기존 문구 하나를 지키려 전체 구조를 불필요하게 다시 쓰지 않는다.

## 긴 작업에서 맥락이 흐릿해지는 문제 — 2026-09-09

- 3·4장 두 번째 항목은 개별 조건 누락으로 좁히지 않고, 긴 작업에서 앞의 방향과 맥락이 흐릿해지는 문제로 수정한다.
- 3장: ‘뒤로 갈수록 / 앞의 맥락이 흐릿해짐’. 예시는 ‘자료 조사 · 스타일 · 최종 원고’.
- 4장: ‘작업이 길어지면 앞의 맥락이 흐릿해진다 / 처음 잡은 방향이 최종 결과까지 이어지지 않는다’.
- 5장 대응도 역할에 필요한 맥락을 전달하는 것으로 맞춘다. 역할 분리만으로 맥락이 자동 보존된다고 설명하지 않는다.
- 사용자 제공 3·4장 대본을 해당 문단에 반영하고 요약·5장 연결을 동기화한다. 디자인과 다른 두 항목은 유지한다.
