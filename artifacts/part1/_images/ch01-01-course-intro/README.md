# ch01-01 생성 이미지

HTML에는 아직 반영하지 않았다. 확정 후 슬라이드 8에 적용한다.

## 캐릭터 기준 — 두 개다

**로봇:** `pattern-2-cross-check.png` 나머지 세 장은 이 이미지를
`image_references`로 물려 생성했으므로 머리·바이저·몸통·팔 형태가 동일하다.
새 패턴 이미지를 추가할 때도 이 파일을 레퍼런스로 쓴다.

**사람:** `character-person-reference.png`
굵은 검은 외곽선 + 거의 음영 없는 플랫 채색(볼드 라인아트). **사람 비율 그대로** — 머리가 몸의 1/5 정도.
짧은 갈색 머리, 최소한의 이목구비, 밝은 회색 긴팔 상의. 기본은 **허리 위까지만** 그린다.
치비·큰머리 마스코트로 그리지 않는다.
사람이 나오는 장면은 **로봇 레퍼런스와 이 파일을 `medias`에 함께** 넣어야 둘 다 고정된다.

### 단계가 올라갈수록 사람이 편해진다

이 감정 곡선이 3장을 관통하는 축이다. 그림체는 같고 **자세와 표정만** 바뀐다.

| 단계 | 사람의 상태 |
|---|---|
| 1 | **평범.** 서서 어깨 힘 빼고 한 손으로 지시. 아무것도 들고 있지 않다 |
| 2 | **허덕임.** 서류 더미를 끌어안고 어깨가 솟고 눈썹이 찌푸려지고 땀방울이 튄다 |
| 3 | **여유.** 소파에 앉아 다리를 꼬고 기대앉아 웃으며 종이 한 장만 건넨다 |

3단계만 **앉아 있고**, 그래서 의자와 다리가 보인다. 1·2단계는 서 있고 허리 위까지만 그린다.

- 바이저 발광색과 화살표 색이 패턴 색을 따른다 (brand / purple / yellow)
- **단 `pattern-4`만 예외** — R&R은 "역할마다 다른 일"이 요점이라 가지별로 색을 나눴다.
  위 mint green `#4ade80` · 가운데 cyan `#22d3ee` · 아래 periwinkle `#818cf8`.
  각 가지의 색이 그 로봇의 바이저·화살표·결과물에 함께 쓰인다
- 배경은 덱 배경과 같은 `#0d1117`
- 라벨 텍스트를 넣지 않는다 — 한글이 뭉개지고, 이 슬라이드는 패턴 이름을 쓰지 않는다

### 에이전트 진화 3단계 (슬라이드 3·4·5)

세 장이 **같은 로봇 + 같은 사람**으로 통일되어 있고, 사람의 위치와 색만 바뀐다.
넘길 때 사람의 자리가 `옆 → 한가운데 → 맨 위 한 번만`으로 바뀌는 것이 이 블록의 메시지다.
3단계는 사람이 지시만 하고 빠지며, 일을 나누는 주체가 **지휘자 로봇**으로 옮겨간다.

정사각형이라 구도를 이렇게 잡았다 — 1단계는 **대각선**(좌상 사람 → 우하 로봇),
2단계는 **방사형**(가운데 사람, 둘레에 로봇 셋), 3단계는 **위에서 아래로 3단 트리**.

| 파일 | 단계 | 색 | 사람의 위치 | 무엇이 읽혀야 하나 |
|---|---|---|---|---|
| `stage-1-agent-born.png` | 에이전트의 탄생 | gray `#8b949e` | 왼쪽, 서서 빈손으로 지시 | 로봇이 창 안의 문서에 **직접 손을 얹고** 있다. 로봇 하나, 화살표 하나 |
| `stage-2-multi-agent.png` | 멀티 에이전트 | orange `#ff6d3b` | **한가운데**, 서류에 파묻혀 땀 | 로봇 셋이 서로 연결되지 않고 **전부 사람을 거친다**. 사람이 병목 |
| `stage-3-orchestration.png` | 오케스트레이션 | brand `#fc1c49` | **왼쪽 위**, 목표 종이만 건네고 | **지휘자 로봇**(망토·지휘봉·반짝임, 다른 로봇보다 큼)이 받아서 리드 3대로 내려보내고, 각 리드가 다시 작은 에이전트들에게 나눈다 |

| `multi-agent-carrier.png` | (구) 슬라이드 4용 | orange | — | **`stage-2`로 대체됨.** 아직 HTML이 이 파일을 참조 중이라 지우지 않았다 |

`discarded/`는 확정 전 버전들이다(캐릭터 통일 전 1차본, 현실적 남성 버전, 치비 버전). 참고용으로만 남겨둔다.
`_person-candidates/`는 사람 그림체를 고를 때 뽑은 4개 시안이며 **B가 채택**됐다.

## 구조를 그릴 때 지킬 것

- **병렬은 두 에이전트가 정면을 본다.** 마주보게 그리면 교차 검증처럼 읽힌다.
  둘 사이에 화살표·선을 절대 넣지 않는다 — 접점이 없는 것이 이 패턴의 정의다
- **결과물은 회색 빈 네모로 두지 않는다.** 무엇을 만드는 패턴인지에 맞는 형태로 그린다.
  병렬은 서로 다른 색의 디자인 시안, R&R은 종류가 아예 다른 산출물 셋
- **선택/미선택은 형태로 구분한다.** 고른 쪽은 체크 배지 + 선명하게, 안 고른 쪽은 점선 테두리
- **색을 지정하지 않은 요소가 남으면 모델이 마음대로 칠한다.** 3단계 1차본에 보라색 화살표가
  끼어들었다. `STRICT COLOR RULE`로 "이 색만 쓰고 보라·파랑·주황·초록은 쓰지 마라"까지 못 박는다
- **사람이 나오는 장면은 `stage-2`를 레퍼런스로 함께 물린다.** 로봇 레퍼런스(pattern-2)만으로는
  사람 모습이 매번 달라진다. 두 장을 `medias`에 같이 넣으면 로봇과 사람이 동시에 고정된다
- **오케스트레이션은 지휘자가 있어야 한다.** 사람 → 로봇들이 아니라
  `사람 → 지휘자 → 리드 → 하위 에이전트` 계층으로 그린다. 사람이 직접 여러 로봇에게
  나눠주면 2단계(멀티 에이전트)와 구분이 안 된다
- **로고와 브랜드 마크를 넣지 않는다.** 지휘자는 망토·지휘봉·반짝임으로만 구분한다

## 생성 설정

- 모델 `nano_banana_pro`
- **비율:** 진화 3단계(`stage-*`)는 **1:1 정사각형**, 패턴 4장(`pattern-*`)은 `4:3`
- 2048~2400px로 생성한 뒤 긴 변 1400px로 축소
- 1·3·4는 `medias: [{value: <pattern-2 job id>, role: "image_references"}]`
- 프롬프트에 반드시 넣을 것: `no text, no letters, no numbers, no logos, no typography anywhere`
  그리고 **프레이밍 규칙** — 피사체를 작게 그리고 사방에 여백을 남기라고 명시하지 않으면 가장자리가 잘린다
