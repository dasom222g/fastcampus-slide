## 저장소와 작업흐름 슬라이드 대본 (8장)

## 슬라이드 1/8 — 저장소와 작업흐름 (표지)

앞에서 Git은 파일의 변경 이력을 기록하고 관리하는 시스템이라고 했죠. 이번에는 그 기록을 어디에 두고, 어떻게 남기는지 보겠습니다.

지금 수정하는 파일이 있고, 그 파일을 바꾸면서 남긴 이력이 있습니다. 파일을 저장하는 것과 Git에 새 기록을 남기는 것은 별개의 동작이에요. 평소처럼 저장했다고 변경 이력이 자동으로 만들어지는 것은 아닙니다.

먼저 저장소가 일반 폴더와 어떻게 다른지 보고, 문서를 고친 뒤 기록으로 남기는 과정을 따라가 보겠습니다.

## 슬라이드 2/8 — 저장소란

저장소는 영어로 Repository라고 합니다. 이름이 낯설 수 있는데요. 일반 폴더와 나란히 놓고 보면 차이를 이해하기 쉽습니다.

왼쪽 일반 폴더는 파일을 담아두는 곳입니다. 문서나 코드, 이미지를 넣고 열어서 고칩니다. 예전 내용을 따로 남기고 싶다면 파일을 복사해두는 식으로 직접 관리할 수 있죠.

오른쪽은 Git으로 관리하는 프로젝트입니다. 같은 파일들 아래에 .git이 하나 더 보이죠. 일반적인 Git 프로젝트에서는 .git이라는 숨김 폴더에 Git이 변경 이력과 설정을 보관합니다. 우리가 수정하는 파일과 함께, 그 파일들을 관리하기 위한 Git의 기록이 있는 거예요.

그래서 파일을 담아둔 일반 폴더와 달리, Git으로 관리하는 프로젝트는 기록한 버전과 변경 이력을 확인할 수 있습니다. .git은 직접 문서를 작성하는 곳이 아니라 Git이 관리하는 폴더라고 보시면 됩니다.

그래서 저장소는 프로젝트의 기록을 관리하는 바탕이라고 이해하시면 됩니다. 파일을 담는 것에 더해 변경 이력을 함께 관리한다는 차이가 있어요.

다만 Git이 파일을 저장할 때마다 새 버전을 자동으로 남겨주는 것은 아닙니다. 필요한 내용을 골라 기록하는 과정이 있습니다. 그 과정을 세 영역으로 나누어 보겠습니다.

## 슬라이드 3/8 — 버전 관리를 위한 3 단계

Git의 기본 작업은 작업, 스테이징, 커밋의 세 단계로 이루어집니다.

먼저 작업 디렉토리입니다. 영어로 Working Directory라고 하는데요. 우리가 컴퓨터에서 직접 보고 편집하는 파일들이 있는 폴더입니다. 지금은 왼쪽 영역이 강조되어 있죠.

여기에서 코드를 작성하거나 문서를 고치고, 파일을 새로 만들거나 삭제합니다. 실제로 작업을 하는 자리인 거예요.

예를 들어 소개 문서를 열어 내용을 바꾸고 저장했다고 해보겠습니다. 현재 파일의 내용은 바뀌었지만, Git의 변경 이력에 새 버전을 남긴 것은 아닙니다. 파일을 저장하는 일과 Git에 기록하는 일을 구분하시면 됩니다.

위의 세 영역은 모두 내 컴퓨터 안에 있습니다. 지금은 첫 번째 영역에서 파일을 편집하는 역할부터 보시면 됩니다.

## 슬라이드 4/8 — 버전 관리를 위한 3 단계

이제 같은 그림에서 가운데 영역이 강조됩니다. 스테이징 영역이고, Index라고도 부릅니다. 다음 커밋에 담을 내용을 준비하는 자리예요.

작업 디렉토리에서 여러 파일을 고쳤더라도 전부 한꺼번에 기록하고 싶지는 않을 수 있습니다. 그중 이번 커밋에 담을 내용을 골라 준비합니다. 왼쪽 화살표의 git add가 그 명령어입니다. 관련 있는 변경끼리 하나의 기록으로 묶기 위한 중간 단계인 거죠.

파일 자체가 작업 폴더에서 사라져 이곳으로 이동하는 것은 아닙니다. 작업 파일은 그대로 있고, 선택한 시점의 내용이 다음 기록을 위해 준비됩니다. 아직 기록을 남기는 단계까지 끝난 것은 아니에요.

그래서 가운데 영역의 역할은 다음 커밋에 무엇을 담을지 정하는 것입니다.

## 슬라이드 5/8 — 버전 관리를 위한 3 단계

마지막으로 오른쪽 Git 저장소가 강조됩니다. 이 그림은 내 컴퓨터 안을 보고 있으므로 로컬 저장소입니다. 준비한 변경이 커밋으로 기록되어 보관되는 곳이에요.

이렇게 남기는 기록 하나가 커밋입니다. 오른쪽 화살표의 git commit 명령어로, 스테이징 영역에 준비한 변경을 반영해서 프로젝트 버전을 남깁니다. 그 커밋에는 고유한 식별자가 붙는데, 이를 해시라고 부릅니다. 서로 다른 기록을 구분하는 이름이라고 이해하시면 됩니다.

커밋 히스토리가 남아, 언제든지 이전 버전으로 되돌릴 수 있습니다. 파일을 고치는 자리, 기록할 내용을 준비하는 자리, 버전과 이력을 남기는 자리가 이렇게 구분되는 거예요.

이제 하나의 커밋에 무엇이 남는지를 조금 더 살펴보겠습니다.

## 슬라이드 6/8 — 기록으로 남는 순간 - commit

이제 준비한 내용을 실제 이력으로 남깁니다. 이렇게 남긴 기록 하나를 커밋이라고 합니다.

커밋에는 선택한 변경을 반영한 프로젝트 버전이 남습니다. 바꾼 문장 몇 개만 따로 적어둔 메모가 아니라, 그 시점의 프로젝트 내용을 다시 확인할 수 있는 기록이에요.

커밋 메시지는 그 커밋에서 어떤 작업을 했는지 설명하는 글입니다. 작업 내용과 변경 이유를 적어두면 나중에 히스토리를 살펴볼 때 맥락을 알 수 있습니다. 작성자와 시간 정보도 함께 남습니다.

앞 클립에서 파일명에 최종, 진짜최종을 붙이는 대신 이력으로 관리한다고 했죠. Git으로 관리하는 폴더에서도 파일을 고치고 저장하는 것만으로 새 버전이 기록되지는 않습니다. 변경은 감지되지만, 커밋한 시점이 곧 돌아갈 수 있는 버전입니다. 이 기록은 먼저 내 컴퓨터의 로컬 저장소에 남습니다.

## 슬라이드 7/8 — 내 기록과 원격 기록

왼쪽은 내 컴퓨터의 로컬 저장소이고, 오른쪽은 원격 저장소입니다. 둘 다 프로젝트의 기록을 관리하지만 놓인 위치가 다릅니다. GitHub는 원격 저장소를 두는 서비스의 한 예예요. 여기에 기록을 올려 다른 사람과 공유하고 함께 작업할 수 있습니다.

위쪽 화살표는 내 컴퓨터에 남긴 기록을 원격에 공유하는 방향입니다. 이때 쓰는 명령어가 git push입니다. 아래쪽의 git pull은 원격의 변경을 받아와 현재 작업에 반영하는 동작이고요.

내 컴퓨터에 커밋했다고 원격도 저절로 바뀌는 것은 아닙니다. 기록을 남기는 일과 다른 곳에 공유하는 일은 별개예요. 그래서 지금 내 컴퓨터에만 기록한 상태인지, 원격에도 공유했는지 구분해야 합니다.

이제 파일을 고치는 순간부터 원격 공유까지 전체 흐름을 한 번에 이어보겠습니다.

## 슬라이드 8/8 — 한 번의 작업 흐름

지금까지 본 과정에 이름을 붙이면 이 그림이 됩니다. 작업 디렉토리에서 파일을 고치고, git add로 이번 기록에 담을 내용을 고릅니다. git commit으로 로컬 저장소에 기록하고요. 원격에 공유할 때 사용하는 이름이 git push입니다.

큰 글자를 왼쪽부터 읽어볼까요. 고친다, 고른다, 남긴다, 올린다. 네 단계가 하나의 흐름으로 이어집니다. 각 단계 아래에는 그 일이 이루어지는 영역 이름이 있고, 사이의 화살표 위에는 명령어가 붙어 있습니다. add는 선택, commit은 기록, push는 원격 공유입니다.

위의 작은 딱지도 보세요. 고치고, 고르고, 기록하는 세 단계는 내 컴퓨터에서 일어납니다. 마지막 공유 단계에서 원격 저장소로 기록을 올립니다.

먼저 이 흐름을 이해하고, 실제 입력 방법과 옵션은 실습에서 보겠습니다. 고치는 자리, 다음 기록을 준비하는 자리, 이력이 남는 자리를 구분하고, 원격 공유는 별도의 동작이라는 점을 기억하시면 됩니다.

다음 클립에서는 같은 프로젝트에서 작업의 줄기를 나누고, 서로 다른 폴더를 동시에 열어 작업하는 방법을 보겠습니다. 브랜치와 워크트리가 어떻게 다른지 이어서 살펴볼 겁니다.
