## Git이란 - 버전 관리가 없다면 슬라이드 대본 (5장)

## 슬라이드 1/5 — Git이란 - 버전 관리가 없다면 (표지)

이번에는 Git이 뭔지 볼건데

Orca 배우러 왔는데 왠 갑자기 Git이냐 하실 수 있는데요. 앞에서 Orca의 작업 단위가 워크트리라고 했잖아요. 그 워크트리를 만들어내는 게 Git입니다. Orca 자체가 Git 기반으로 만들어진 도구라서, 이걸 모르면 Orca를 제대로 이해하기가 어려워요.

Git은 버전 관리 시스템인데, Orca뿐만 아니라 클로드 코드 같은 에이전트를 쓸 때는 이 버전 관리가 필수입니다. AI가 파일을 직접 고치는데 뭐가 어떻게 바뀌었는지 못 보면 통제가 안 되거든요. 이번에 Git 개념을 확실히 잡고 가시면 앞으로 에이전트 쓰실 때 큰 무기가 될 겁니다.

## 슬라이드 2/5 — 이름으로 남긴 버전

먼저 버전 관리가 왜 필요한지부터 볼게요.

버전 관리라는 게 없을 때 우리는 이렇게 했죠. 최종, 최최종, 진짜최종. 저도 Git을 알기 전까지는 이렇게 관리했어요.

근데 이름을 길게 붙이는 것 자체는 문제가 아닙니다. 이름으로 최신본이 뭔지는 알 수 있잖아요.

진짜 문제는 그 안에서 뭐가 바뀌었는지를 모른다는 겁니다. 그래서 이전 버전으로 되돌려야 할 때 답이 없어요. 내가 원하는 버전이 어느 파일에 있는지 모르니까 결국 하나씩 다 열어보고, 어디가 어떻게 다른지 직접 찾아내야 하거든요.

## 슬라이드 3/5 — Git의 역할

이 문제를 해결해주는 게 Git입니다. 사람이 파일 이름으로 관리하던 걸 시스템이 대신 기록해주는 거예요. 지금 작업하는 파일 하나만 저장하는 게 아니라, 그 파일이 어떻게 바뀌어왔는지 그 이력까지 같이 기록합니다.

그래서 예전처럼 파일을 늘릴 필요가 없어요. 파일은 최종본 하나로 두고, 중요한 지점마다 명령어 한 번만 치면 지금 상태가 그대로 기록됩니다. 복사본을 따로 만들 필요가 없는 거죠.

그리고 이렇게 남겨둔 기록은 언제든 다시 되돌릴 수 있습니다. 아까처럼 파일을 하나씩 열어서 뭐가 다른지 찾을 필요 없이, 특정 시점을 기준으로 그때 상태로 되돌리면 되는 거예요.

## 슬라이드 4/5 — Git이 바꾸는 것

그럼 Git을 쓰면 실제로 뭐가 바뀌는지 볼게요.

첫째, 파일 이름이 안 늘어나요. 폴더에는 최신 파일 하나만 있고, 버전은 이력에서 봅니다. 폴더 열 때 뭐가 최신인지 고민할 일이 없는 거죠.

둘째, 변경 사항을 기록할 때 왜 바꿨는지를 같이 남깁니다. 이걸 커밋 메시지라고 하는데요. 뭘 왜 고쳤는지 적어둬야 나중에 이력을 봤을 때 어느 시점으로 돌아가야 하는지가 바로 보입니다. 아까처럼 파일을 하나씩 열어서 뭐가 달라졌는지 찾아볼 필요가 없어지는 거죠.

셋째, 특정 시점의 상태로 돌아갈 수 있습니다. 작업하다가 전에 게 더 좋았던 것 같으면 손쉽게 그 시점으로 되돌릴 수 있거든요. 직접 비교하고 손으로 옮기던 과정이 통째로 없어집니다.

## 슬라이드 5/5 — Git과 GitHub

우리 강의에서도 작업한 걸 GitHub에 올려서 관리할 건데요. 그 전에 Git이랑 뭐가 다른지 보고 가겠습니다.

Git은 앞에서 본 것처럼 파일의 변경 이력을 기록하고 관리하는 시스템이고, GitHub는 그 기록을 온라인에 올려두는 클라우드 호스팅 서비스입니다. 여기 올려두면 누구나 내 작업물에 접근할 수 있어서 협업이 가능해지고, 내 컴퓨터가 아닌 다른 컴퓨터에서 이어 작업할 수도 있어요.

우리 프로젝트도 GitHub로 공유해드릴 건데, 직접 써보시면 금방 감이 잡히실 거예요.

또, AI가 발전하면서 개발자들이 새로 만든 도구나 스킬을 오픈소스로 공개하잖아요. 그게 전부 GitHub에 올라옵니다. 그래서 GitHub를 이해하고 쓸 수 있으면 최신 기술을 남들보다 빠르게 가져다 쓸 수 있어요.

그럼 Git이 실제로 기록을 어디에 남기고 어떻게 동작하는지 알아야겠죠. 다음 영상에서 저장소가 뭔지, 그리고 파일을 고쳐서 기록으로 남기기까지 어떤 단계를 거치는지 보겠습니다.
