# 저장소와 작업흐름 — V1·V2·V3 비교와 취합 결정

대상: artifacts/part3/outputs/ch01-02-repo-and-flow.html. codex-v2의 HTML·소스·스토리보드·대본·피드백은 이 정식본에 연결되어 있다.

| 버전 | 장점 | 한계 | 반영 |
|---|---|---|---|
| V1 | 3번에서 내 컴퓨터 안의 세 영역이 모두 보인다. 5번은 동작을 영역 사이에 둔다. | 용어·설명·동작이 같은 카드 안에서 경쟁하고, 마지막 pull 화살표의 시작과 끝이 모호하다. | 내 컴퓨터 경계, 고정된 영역 순서, 화살표 위의 명령어 |
| V2 | 문서 수정부터 선택·커밋까지 하나의 사례로 이어간다. 스테이징 장면과 커밋 묶음이 이해를 돕는다. | 첫 단계에만 세 영역이 보이고 뒤 장에서 위치를 놓친다. 마지막에 다음 강의 예고가 중복된다. | 기본 전개, 승인 이미지, 선택과 기록의 분리, 커밋 정보 묶음 |
| V3 | 서로 다른 개념을 나누려는 접근과 add/commit 대비가 좋다. | ‘내 컴퓨터 안의 상태’에서 실제로 영역을 나열한다. ‘고친다·고른다·남긴다’는 동작이며 상태명이 아니다. | 구분 관점만 채택하고, 영역·상태·동작을 정확히 다시 정의 |

## 표현 규칙

- 영역: 작업 디렉토리 / 스테이징 영역 / 로컬 저장소. 같은 위치와 중립 경계를 유지한다. 이는 세 개의 실제 폴더를 뜻하지 않는다.
- 상태: 수정됨 Modified / 선택됨 Staged / 기록됨 Committed. 문서 내용에 붙인다. 수정됨은 orange(연필), 선택됨은 yellow(선택 표시), 기록됨은 green(체크)이다.
- 동작: 수정 / git add / git commit. 동작은 화살표와 동작 설명으로 표현하며 상태 라벨과 구분한다.
- 위치: 위 세 영역은 내 컴퓨터 안에 있다. 원격 저장소는 별도 경계로 표현한다.
- 파일이 다음 영역으로 이동해 사라지는 도식은 쓰지 않는다. 내용이 선택되고 버전으로 기록되는 흐름이다.
- 같은 파일을 선택한 뒤 다시 수정할 수 있다는 주의점은 대본에서 설명한다. 상세 문장 비교를 화면에 반복하지 않는다.
- 커밋은 변경분만 담은 봉투가 아니라 선택한 변경을 반영한 프로젝트 버전과 메시지·작성자·시간 등의 기록이다.
- pull은 단순 다운로드나 add·commit의 역순이 아니다. 원격 변경을 받아 현재 작업에 반영한다.
