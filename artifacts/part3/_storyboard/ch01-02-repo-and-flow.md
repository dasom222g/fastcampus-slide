# 저장소와 작업흐름 — V2 기반 취합 스토리보드

총 8장. 3~5번 화살표 위에 git add·git commit을 표시한다. commit은 6번 제목에서 개념으로 강조하고, push·pull은 7번에서 소개한다. 8번에서 전체 명령 흐름을 정리한다. 최신 사용자 지시에 따라 2번은 일반 폴더·Git 저장소의 50:50 비교다.

## 슬라이드 2/8 — 저장소란

시각 장치: 일반 폴더와 Git 저장소를 동일한 50:50 영역·폴더 모양으로 비교. 일반 폴더는 중립색, Git 저장소 패널은 옅은 브랜드색 배경·테두리·제목으로 강조한다. 저장소 안에만 작은 `.git` 숨김 폴더를 추가한다. 숨김 폴더는 기존보다 폭·높이를 약 30% 줄여 바깥 폴더 안쪽 오른쪽 아래에 둔다. 중립색 점선과 0.38 불투명도로 옅게 표시하고, `.git` 이름을 넣는다. 일반 파일 세 개와 바깥 폴더의 크기·위치는 양쪽에서 동일하다.

## 슬라이드 8/8 — 한 번의 작업 흐름

애니메이션 순서: 작업 디렉토리 → git add 화살표·명령어 → 스테이징 영역 → git commit 화살표·명령어 → 로컬 저장소 → git push 화살표·명령어 → 원격 저장소. 단계 안의 위치 딱지·그림·제목·영역 이름은 한 묶음으로 나타난다. 전체 가로 흐름을 통째로 움직이지 않는다. 첫 요소는 150ms 후 시작하고 요소 간 260ms, 단계 간 520ms의 시간차로 등장한다. 이동·페이드는 기존 480ms를 유지한다. 재진입하면 첫 단계부터 다시 재생한다.

시각 장치: 같은 크기의 네 단계가 같은 높이의 화살표로 이어지는 열린 가로 흐름. 큰 외곽 프레임 없이 단계마다 그림·제목의 색을 구분한다. 위치 딱지는 중립색을 유지한다.

배치: 네 단계 모두 위치 딱지 → 같은 크기 도식 → 행동 동사 → 영역 이름의 순서다. 세 연결선은 각 도식의 중앙 높이에서 충분한 길이로 이어지고, 위에 동작의 명령어가 붙는다. ‘고친다·고른다·남긴다·올린다’의 크기·굵기를 통일한다. 하단 pull 행은 제거한다. 편집은 브랜드 빨강, 선택은 노랑, 기록은 초록, 원격 공유는 보라로 표현한다. 연결 화살표와 명령어는 도착 단계의 색을 따른다. 이는 네 작업 단계의 구분이며 파일 상태 색을 뜻하지 않는다.

| 순서 | 위치 딱지 | 그림 | 큰 행동 | 보조 영역 이름 | 다음 단계로 연결 |
| --- | --- | --- | --- | --- | --- |
| 1 | 내 컴퓨터 | 문서와 편집 도구 | 고친다 | 작업 디렉토리 | git add → |
| 2 | 내 컴퓨터 | 기록할 문서를 선택하는 트레이 | 고른다 | 스테이징 영역 | git commit → |
| 3 | 내 컴퓨터 | 기록을 담은 저장소 폴더 | 남긴다 | 로컬 저장소 | git push → |

근거: 참고 이미지에서 흐름이 읽히는 원인(동일 위계·정렬·연속된 방향)을 적용한다. Git 개념의 근거는 소스와 별첨 버전 분석의 공식 Git 자료다. 하단의 역방향 흐름 없이 네 단계의 한 방향 연결을 보여준다.
