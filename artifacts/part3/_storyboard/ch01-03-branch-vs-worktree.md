## 슬라이드 2/7 — 한 폴더에서 겹치는 작업

서브설명: 같은 파일을 동시에 수정하면, 서로의 작업을 덮어쓸 수 있습니다.

화면 문구: 에이전트는 둘, / 작업 폴더는 하나 / 동시에 일하려면, 각자의 작업 공간이 필요합니다.

시각 장치: 한 책상에서 같은 문서를 건드리는 두 에이전트의 기존 투명 이미지를 사용한다. 왼쪽 공통 statement와 짧은 설명, 오른쪽 장면을 둔다. 이미지의 실제 알파·전체 피사체를 유지하고 테두리·마스크·크롭은 추가하지 않는다. 과거 「한 폴더의 한계」에서 다뤘던 브랜치 수 제약 대신, 같은 파일을 동시에 수정하는 문제를 보여준다.

이미지: /artifacts/part3/_images/shared-desk-transparent.png

전환: 워크트리로 작업 공간을 나눠야 하는 필요를 먼저 말한다. 각 폴더에서 어떤 이력으로 작업할지 이해하기 위해 다음 장에서 브랜치를 설명한다.

근거: 사용자 최신 요청 — 한 폴더에서 여러 에이전트가 같은 파일을 수정하는 문제에서 출발한다. 작업 공간 분리의 필요 → 그 구조를 이해하기 위한 브랜치 → 워크트리의 동시 작업 순서다.

## 슬라이드 3/7 — 따로 이어가는 작업 이력

서브설명: 브랜치는 작업을 나누어 이어가는 이력의 줄기입니다.

화면 문구: 기준 브랜치 / 작업 브랜치 / 분기 / 병합 / 점 하나 = 커밋 하나 / 완성한 작업은 병합해 반영할 수 있습니다.

시각 장치: 기존 정의와 분기·합류를 한 장으로 합친다. 넓은 커밋 그래프에 두 줄기를 이름으로 구분한다. 커밋 점의 의미를 범례로 표시한다. 기준 이력→분기한 작업→선택적 병합 순서로 나타난다. 병합은 점선·초록으로 가능성을 표현하며 자동 합류로 설명하지 않는다.

## 슬라이드 4/7 — 한 번에 한 시점만

서브설명: 타임머신으로 10살의 나에게 돌아가, 새로운 삶을 시작한다면

화면 문구: 10살 / 20살 / 30살 / 원래의 삶 / 새로운 삶 / 타임머신 / 한 폴더에서는 한 번에 하나의 시점만 엽니다.

시각 장치: 원래 삶의 10살·20살·30살 중 10살에서 새 시간선이 갈라져 새로운 삶의 20살로 이어진다. 3번과 같은 분기 구조다. 한 대의 차가 원래 삶의 30살 → 10살 → 새로운 삶의 20살로 이동한다. 원래 삶의 시간선은 남아 있고 현재 위치 표시는 하나만 움직인다.

배치: 기존의 단순한 자동차형 SVG를 사용한다. 차체·창문·운전자·두 바퀴와 「타임머신」 이름만 남기고 별도 시간 이동 장치·안테나·배선 등 복잡한 요소를 넣지 않는다. 생성한 PNG는 이 장에서 사용하지 않는다. 10살에서 갈라지는 곡선과 기존 나이 라벨·하단 문장은 원래 배치로 복원한다.

애니메이션: 기존 8초 이동을 유지한다. 원래 30살에서 잠시 머문 뒤 10살로 돌아가고, 새 줄기를 따라 새로운 20살로 이동한다. 재진입하면 처음부터 재생하고, 모션 감소 설정에서는 최종 관계를 정적으로 표시한다.

비유의 범위: 시간선은 브랜치, 나이 점은 커밋한 시점에 대응한다. 작업 폴더 하나는 한 번에 하나의 시점만 연다는 제약을 설명한다.

근거: 사용자 최신 확정 — 기존처럼 단순한 차로 복원하고, 분기는 다시 10살에서 시작한다.

## 슬라이드 5/7 — 워크트리란

서브설명: Git 저장소에 연결된 실제 작업 폴더입니다.

화면 문구: main / v1 시점 / 작업 A / 작업 폴더 A / 작업 B / 작업 폴더 B / 각 워크트리의 작업 파일은 서로 영향을 받지 않습니다.

시각 장치: 상단의 작은 main 폴더에서 아래의 큰 작업 폴더 A·B로 갈라지는 수직 화살표. 세 폴더의 브랜치 아이콘과 이름은 모두 폴더 안 같은 상대 위치에 둔다. main 옆에는 「v1 시점」만 표시한다. A의 마지막 파일은 빨강, B는 보라로 구분한다. 아래 두 폴더 밑에는 작업 폴더 A·B 제목만 표시한다. 생성 이후 서로 다르게 작업한 결과라는 점은 대본에서 설명한다.

배치: 공통 헤더·본문·푸터 사이 기본 행 간격과 패딩을 복원한다. 본문은 최대 40rem 높이 안에서 도식과 하단 문장을 중앙에 모으고 두 요소 사이에는 1rem을 둔다. 도식의 행은 폴더와 제목의 실제 높이만 차지한다. main과 아래 폴더 행 사이 간격은 3rem, 높이 850px 이하에서는 0.75rem으로 줄여 A·B 화살표의 세로 길이를 종전의 절반 정도로 맞춘다. 남는 높이를 폴더 행에 배분하지 않는다. A·B 폴더는 확정된 실제 크기를 유지한다. 최대 너비 21rem, 좁은 화면에서는 콘텐츠 가용 너비의 3분의 1을 기준으로 제한한다. 선 두께와 글자 크기는 기존 규격을 유지한다. 도식의 전체 너비는 최대 60rem으로 제한한다. 폴더 아래에는 제목만 남겨 높이를 확보한다. 작은 main과 v1 시점 라벨은 상단 중앙, A·B는 하단 두 열에 놓는다. 화살표는 main과 A·B 폴더의 실제 SVG 좌표를 기준으로 연결한다. main의 아래쪽 경계에서 8px 띄워 시작하고, 각 화살촉은 A·B 폴더 중앙의 위쪽 경계에서 12px 위에 놓는다. 고정 높이 컨테이너에서 화살표가 먼저 끝나지 않도록 연결선을 도식 전체에 겹쳐 그린다. 화면 크기·폰트·등장 위치가 바뀌면 폴더 위치를 다시 측정해 선 길이를 갱신한다. 본문 전체를 무한히 채우거나 모든 여백을 없애지 않는다. 공통 글자 크기와 문구는 유지한다.

애니메이션: main 폴더→분기 연결→A 폴더→B 폴더→하단 핵심 문장. 연결선은 제자리에서 나타난다.

범위와 근거: 공유 저장소 구조 장은 삭제하고 이 생성 흐름 장을 유지한다. main의 v1은 예시이며, 미커밋 파일을 복사하는 흐름이 아니다. 같은 버전에서 출발한 뒤 각자의 작업 파일을 수정하는 과정을 설명한다. Git 공식 문서 https://git-scm.com/docs/git-worktree#_commands

## 슬라이드 6/7 — 브랜치와 워크트리의 관계

서브설명: 서로 다른 브랜치를 각자의 워크트리에서 열어두고 동시에 작업합니다.

화면 문구: 브랜치 / 작업 이력 / main / 작업 B / 워크트리 / 실제 작업 공간 / 작업 폴더 A / 작업 폴더 B / 에이전트는 각자의 워크트리에서 작업하고, 검토한 결과만 main에 병합합니다.

시각 장치: 왼쪽의 공유된 커밋 줄기에서 위쪽 main은 직선으로 이어지고, 아래쪽 작업 B 브랜치는 보라색으로 갈라진다. 각 줄기의 오른쪽 끝에 해당 워크트리 폴더를 붙인다. main → 작업 폴더 A는 포인트색(brand), 작업 B → 작업 폴더 B는 보라색으로 매핑한다. 브랜치 이름·줄기·커밋 점·폴더 외곽·폴더 이름·마지막 파일의 색을 각 행에서 일치시킨다. 폴더 안 실제 파일을 함께 표시한다. 각 폴더의 오른쪽 위 옆에 기존 에이전트 아이콘을 같은 색으로 붙여 각자 자기 작업 폴더에서 일함을 보여준다. 선은 생성 순서가 아닌 브랜치와 폴더의 연결 관계다.

배치: 브랜치·작업 이력 표제는 왼쪽, 워크트리·실제 작업 공간 표제는 오른쪽. 아래 두 폴더의 실제 위치에 맞춰 커밋 줄기와 분기 곡선을 그린다. 채택한 관계 장의 타이포·핵심 문장은 유지하고, 폴더는 종전보다 약 20~25% 크게 한다. 최소 너비 15rem, 본문 높이에 비례하는 36cqh, 최대 20rem을 기준으로 한다. 폴더 오른쪽 위 옆에 3.5rem 크기의 에이전트를 붙인다. 폴더·에이전트가 두 행에서 겹치지 않도록 도식에 본문 가용 높이를 배정하고 표제와 하단 문장 간격을 조정한다. 장식 박스는 추가하지 않는다. 애니메이션은 브랜치 표제 → main 선이 시작점에서 오른쪽으로 그려짐 → 작업 B 선이 분기점에서 이어짐 → 워크트리 표제 → A 폴더·에이전트 A → B 폴더·에이전트 B → 하단 문장 순서다. 브랜치와 실제 작업 공간을 동시에 등장시키지 않는다. main 선은 410ms부터 900ms 동안, 작업 B 선은 1450ms부터 1000ms 동안 왼쪽에서 오른쪽으로 드러낸다. 커밋 점도 선과 같은 마스크 안에 있어 선이 도달하는 순서로 나타난다. 워크트리 표제는 2490ms, A 폴더는 2750ms, B 폴더는 3270ms, 하단 문장은 3790ms에 등장한다. 폴더와 해당 에이전트는 함께 나타난다. 재진입하면 처음부터 재생하고, 모션 감소 설정에서는 선과 점을 모두 펼쳐 즉시 표시한다.

범위: 사용자가 분기형 관계도를 최종 선택했다. 이전 관계 도식과 별도의 「각자의 작업 공간」은 삭제하고 이 장을 6번으로 둔다. 에이전트 적용 설명은 이 장의 대본 끝에서 Orca로 연결한다. 작업 폴더 A가 main을, 작업 폴더 B가 작업 B 브랜치를 여는 예시다. 직선의 브랜치명은 main으로 유지한다. 브랜치마다 폴더가 자동 생성된다는 의미로 설명하지 않는다.

핵심: 에이전트가 워크트리에서 독립적으로 작업하고, 작업 브랜치에 커밋한 결과를 검토한 뒤 main에 병합한다. 검토는 강의에서 권하는 작업 흐름이며, 병합의 대상은 커밋된 작업 결과다. 근거: https://git-scm.com/docs/git-worktree#_description · https://git-scm.com/docs/git-merge#_description

## 슬라이드 7/7 — Orca의 작업 폴더

서브설명: Part 2에서 본 작업별 공간의 정체가 워크트리입니다.

화면 문구: Orca / 생성 / Git 워크트리 / 클릭으로 만드는 / 독립된 작업 폴더

시각 장치: 같은 3폴더 구조도를 반복하지 않는다. 왼쪽 Orca 로고→생성→작업 폴더의 짧은 도식, 오른쪽 statement. 실제 작업 캡처·오케스트레이션·명령어 안내 없음. 실습 예고는 대본으로만 한다.
