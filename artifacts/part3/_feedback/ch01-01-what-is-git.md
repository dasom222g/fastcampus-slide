### 2026-09-08 — 양쪽을 같은 거리로 중앙 이동 / 배경 복원

### 2026-09-08 — 이미지 끝이 드러나는 문제 수정

이미지와 글을 개별적으로 이동하던 6% 오프셋을 제거했다. 검정 배경은 유지하고 전체 scene을 너비 70%로 중앙 배치한다. 이미지 원본의 오른쪽 끝이 박스 안쪽에 노출되지 않도록 기본 object-fit:contain, object-position:right center 배치를 복원했다.

### 2. 개별

#### 슬라이드 1 — Git이란 - 버전 관리가 없다면 (표지)
- 제목·부제·한 문장과 파일 이력 도식. 목차·학습 항목 없음.

#### 슬라이드 2 — 이름으로 남긴 버전
- 기존 파일명 장면 유지. 복사본이 있어도 이름만으로는 변경점을 알기 어렵다는 설명.

#### 슬라이드 3 — Git의 역할
- 확정된 투명 이미지와 배치 유지. 큰 본문은 표지와 같은 타이포 역할.

#### 슬라이드 4 — Git이 바꾸는 것
- 카드·번호·중복 소제목 제거. 이력·변경 이유·복원의 세 도식과 설명.

#### 슬라이드 5 — Git과 GitHub
- 도구와 서비스를 같은 행 높이의 열린 두 열로 비교.

#### 슬라이드 6 — 각자의 작업 공간
- 에이전트 카드 대신 작업 폴더 A/B/C를 중심으로 분기. 한 폴더 한 에이전트 규칙을 만들지 않음.

#### 슬라이드 7 — 필요한 만큼만
- 기존 투명 이미지·범위 안내 유지. 다음 클립을 저장소와 작업흐름으로 정확하게 연결.

검수: 2133×1200·1280×800의 14개 화면에서 이미지 로딩·본문 넘침 확인. 표지 도식은 본문 컨테이너 높이를 기준으로 크기 조정. 버튼·점·키보드 이동, 첫/끝 버튼, 본문 클릭 시 유지 확인. HTML·스토리보드·대본 모두 7장. artifacts 파일은 수정 전과 동일.

## 4차 — Git·GitHub 역할 명칭과 설명 — 반영완료

- 기존 카드 크기·도식·배치 유지.
- Git: ‘버전 관리 시스템’ / ‘파일의 변경 이력을 기록하고 관리합니다.’
- GitHub: ‘Git 저장소 호스팅 서비스’ / ‘프로젝트와 기록을 온라인에 보관하고 공유합니다.’
- 설명은 각 두 줄로 정렬. 부제와 대본도 같은 개념으로 맞춤.
- 다음부터: 위치를 대충 나타내는 ‘클라우드의 장소’ 대신 정확한 역할 명칭을 쓰고 쉬운 설명을 붙인다.
