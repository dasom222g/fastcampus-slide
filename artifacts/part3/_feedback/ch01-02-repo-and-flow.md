## 쓰는 법

- **피드백은 차수로 쌓는다.** 새 피드백은 파일을 새로 만들지 말고 **이 파일 아래에 `## N차`를 추가**한다. 한 산출물의 이력이 한 파일에 모여 있어야 골든셋 단계에서 전체를 훑을 수 있다
- 반영이 끝난 차수는 제목에 `— 반영완료`를 붙이고, 그 아래 **반영 결과**를 짧게 남긴다. 무엇을 못 했는지도 적는다
- `## 3. 다음부터 이렇게 해`와 `## 4. 골든셋`은 **차수와 무관하게 파일 맨 아래 하나만** 둔다. 차수마다 반복하지 않는다

## 4차 — Git 저장소 색상과 .git 표시 — 반영완료

- 2번 비교 장의 Git 저장소 영역만 옅은 브랜드색 배경·테두리·제목·폴더 윤곽으로 구분했다.
- 일반 파일 세 개와 바깥 폴더의 크기는 양쪽에서 유지한다. 오른쪽 폴더 안에만 `.git` 숨김 폴더를 추가했다.
- 버전 이력 점 표시는 `.git` 폴더로 대체하고, 아래 문구는 ‘.git 폴더에 변경 이력 보관’으로 정리했다.
- `.git`은 일반적인 Git 프로젝트의 숨김 폴더로 설명한다. 모든 저장소 구조에서 반드시 디렉토리라는 식으로 일반화하지 않는다.
- 대본에 .git이 변경 이력과 설정을 보관한다는 설명을 반영했다. 다른 7개 슬라이드의 본문은 그대로다.

## 5차 — .git 숨김 속성 시각화 — 반영완료

- 선명한 브랜드색 실선만으로는 일반 폴더와 구분되지 않았다.
- `.git`만 중립색 점선·0.62 불투명도·가벼운 글자로 옅게 표시한다. 일반 파일과 Git 저장소 영역의 강조는 그대로 유지한다.
- 사용자 정정: 그림 수정을 요청했으므로 하단 문구는 원래 ‘파일과 변경 이력을 함께 관리’로 복원한다. 숨김 표현은 그림에만 적용한다.

## 6차 — 세 영역의 단계별 설명 — 반영완료

- 사용자 제공 설명에 맞춰 기존 3번을 같은 배치의 3장으로 확장했다. 전체는 10장이다.
- 3번: 작업 디렉토리 활성 / 하단 ‘파일을 만들고, 수정하고, 삭제하며 실제 작업을 진행합니다.’
- 4번: 스테이징 영역 활성 / 하단 ‘변경한 내용 중 다음 커밋에 담을 것만 골라 준비합니다.’
- 5번: Git 저장소 활성 / 하단 ‘선택한 변경을 커밋으로 기록하고, 이전 버전을 다시 확인합니다.’
- 영역 이름·영문 용어·역할과 위치는 세 장 모두 고정한다. 활성 영역만 브랜드색으로 강조하고 하단 한 줄만 바꾼다.
- 파일의 실제 이동이라는 오해를 피하도록 스테이징은 선택한 내용을 준비하는 역할로 설명한다. 커밋 해시는 대본에서 짧게 설명한다.
- 나머지 7개 슬라이드의 본문은 그대로 유지했다. 소스·스토리보드·전체 대본·인덱스의 번호와 장수를 맞췄다.

## 7차 — 전체 흐름의 연결과 위계 — 반영완료

- 사용자 참고 이미지의 장점은 네 단계의 같은 크기·높이, 큰 행동 동사, 한 방향으로 이어지는 화살표다. 카드 디자인 자체는 복제하지 않았다.
- 10번의 로컬 3개 / 원격 1개 큰 프레임을 없애고, 네 단계를 같은 폭의 열린 도식으로 배치했다. 위치는 ‘내 컴퓨터’·‘원격’ 딱지로 표시한다.
- ‘고친다 → 고른다 → 남긴다 → 올린다’를 같은 크기로 크게 쓰고, 영역 이름은 아래에 보조로 표시했다. add·commit·push는 충분한 길이의 연결선 위에 둔다.
- pull은 하단의 돌아오는 흐름으로 유지한다. 반복되던 각 영역 설명과 하단 요약 문장은 걷어냈다.
- 소스·스토리보드·대본을 동기화했다. 1~9번 HTML은 수정 전과 동일하고, 덱은 10장이다.
- 검수: 2133×1200·1280×800 화면 확인, 이미지 정상·본문 넘침 없음. 네 단계의 크기·위치와 제목 글자 크기가 같고, 세 연결선도 같은 높이·길이다. 명령어 네 개는 덱 전체에서 각각 한 번만 표시한다.

- 소스·스토리보드·대본에 반영했다. 명령어 소개는 7번의 push·pull에서 시작하고 8번에서 전체 흐름을 정리한다.
- 검수: 2133×1200·1280×800에서 이미지 정상·본문 넘침 없음. 카드 배치 CSS와 다른 7장 HTML은 수정 전과 동일하다.

## 15차 — 원격 저장소의 공유·협업 목적 — 반영완료

- 7번 ‘GitHub 등에 보관’을 ‘GitHub에 올려 공유하고 협업’으로 변경했다. 보관 위치보다 원격 저장소를 쓰는 목적이 드러나도록 한다.
- 소스·스토리보드·대본에 반영했다.

## 16차 — 커밋 시점과 복원 가능한 버전 — 반영완료

- 6번 하단을 사용자 확정 문구 ‘커밋한 시점이 곧 돌아갈 수 있는 버전이 됩니다.’로 변경했다.
- 소스·스토리보드·대본에 동일하게 반영했다.

## 17차 — 커밋 문구와 세 영역의 명령어 표기 — 반영완료

- 6번 하단을 ‘커밋한 시점이 곧 돌아갈 수 있는 버전입니다.’로 수정했다.
- 3·4·5번 모두 첫 화살표 위에 git add, 두 번째 화살표 위에 git commit을 추가했다. 아래 ‘선택’·‘기록’은 유지한다.
- 명령어를 기존 화살표 위에 배치해 영역·화살표·설명의 좌표와 글자 크기를 유지했다. 4·5번은 애니메이션 없이 즉시 표시된다.
- 소스·스토리보드·대본에 반영했다. 2133×1200·1280×800에서 본문 넘침 없음. 3→4→5→4와 6→5의 즉시 표시·고정 좌표를 확인했다.

## 18차 — 전체 흐름의 단계 색상과 pull 행 제거 — 반영완료

- 8번 하단의 ‘현재 작업에 반영 ← git pull / 원격 변경을 받아’ 행 전체를 제거했다. 7번의 pull 설명은 유지한다.
- 모든 단계가 같은 중립색이라 순서가 구분되지 않는다는 사용자 지적을 반영했다. 8번의 그림·큰 제목을 빨강(편집)·노랑(선택)·초록(기록)·보라(원격 공유)로 구분한다.
- 화살표와 명령어는 도착하는 단계의 색을 따른다. 단계 위치·크기·타이포는 유지하고 위치 딱지와 영역 이름은 중립색으로 둔다.
- 단계명 후보는 사용자 선택 전이므로 그대로 유지했다. 소스·스토리보드·대본을 동기화했다.
- 검수: 2133×1200·1280×800 화면 확인, 이미지 정상·본문 넘침 없음. 네 단계 그림과 제목의 색 일치, 연결선·명령어의 도착 단계 색 일치, 8번 pull 행 제거 확인. 1~7번 HTML 동일.

## 19차 — 세 영역 도입 문장과 상태·단계 구분 — 반영완료

- 3~5번 서브설명을 ‘Git의 기본 작업은 작업 → 스테이징 → 커밋의 3단계로 이루어집니다.’로 변경했다.
- ‘버전관리를 위한 세가지 상태’라는 제목 제안에는 상태와 작업 단계를 구분해 설명했다. 상태는 Modified·Staged·Committed이며, 현재 작업 흐름에는 ‘버전 관리를 위한 세 단계’를 추천했다. 제목은 선택 전이므로 변경하지 않았다.
- 소스·스토리보드·대본에 반영했다.

## 20차 — 세 단계 제목과 커밋 메시지 정의 — 반영완료

- 3·4·5번 제목을 ‘버전 관리를 위한 3 단계’로 확정하고 ‘3 단계’만 브랜드색으로 강조했다.
- 6번의 ‘메시지 / 소개 문구를 구체화’ 예시를 ‘커밋 메시지 / 작업 내용과 변경 이유’로 변경했다. ‘프로젝트 버전 / 선택한 변경을 반영’ 설명은 유지한다.
- 소스·스토리보드·대본을 동기화했다. 2133×1200·1280×800에서 제목·필드 문구·이미지 정상, 본문 넘침 없음.

## 21차 — 전체 흐름의 단계별 순차 등장 — 반영완료

- 8번 전체 도식에 붙은 단일 애니메이션을 제거하고, 네 단계와 세 연결선에 각각 적용했다. 한 단계 안의 위치 딱지·그림·제목·영역 이름은 함께 나타난다.
- 순서는 작업 디렉토리 → git add → 스테이징 영역 → git commit → 로컬 저장소 → git push → 원격 저장소다. 요소 간 260ms, 단계 간 520ms의 시간차를 둔다.
- CSS 지연으로 재생해 다시 진입해도 이전 예약 타이머가 뒤 단계를 먼저 표시하지 않는다. 최초 진입과 애니메이션 도중 이탈 후 재진입 모두 7개 요소의 등장 순서를 브라우저에서 확인했다.
- 1~7번 HTML·공통 CSS·화면 문구·배치는 유지했다. 소스와 스토리보드에 등장 순서를 기록했다.

## 22차 — 전체 8장 최종 검수 — 완료

- 사용자 요청: 현재 구성으로 마무리하되 전체를 최종 확인한다.
- 2133×1200·1280×800에서 8장씩 총 16개 화면을 렌더했다. 제목·서브설명의 폰트 규격 일치, 본문·헤더 잘림과 겹침 없음, 모든 이미지 정상.
- 3·4·5번 제목의 ‘3 단계’ 강조와 git add·git commit 표시, 5번 히스토리 설명, 6번 커밋 메시지·버전 문구를 확인했다.
- 4·5번: 3→4→5→4 및 6→5 이동에서 단일 화면이 즉시 표시되고 실행 중인 애니메이션이 없으며 도식 좌표가 고정되는지 확인했다.
- 8번: 단계별 색과 순차 등장, 재진입 재생, pull 행 제거를 확인했다. 7번의 pull 설명은 남아 있다.
- 버튼·키보드·스페이스·하단 페이지 이동·첫/마지막 장 경계·본문 클릭 방지·주소와 페이지 번호 동기화 정상. 브라우저 오류 없음.
- HTTP와 HTML 직접 열기에서 로고·에셋 로딩 정상. V2 링크가 정식 HTML을 가리키는 심링크임을 확인했다.
- 대본·스토리보드 8장의 번호·제목 및 현재 화면 내용을 대조했다. 목록의 8장 표기도 일치한다.
- 검수 캡처와 상세 보고서는 `artifacts/part3/_qa/ch01-02-repo-and-flow--final-*`에 저장했다. 현재 HTML을 최종본으로 기록한다.
