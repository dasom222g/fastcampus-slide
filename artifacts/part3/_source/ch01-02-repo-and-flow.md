제작 목표: 하나의 문서를 수정하고 선택해 기록하는 과정을 따라가며 영역·동작·로컬과 원격을 구분한다.

사용자 요청: V1·V2·V3의 장점을 분석해 V2가 승격된 정식 HTML에서 취합한다. 흐름과 각 영역이 명확히 보이고, 영역과 상태의 의미가 명확히 구분되어야 한다.

## 추가 사용자 지시

저장소 정의를 먼저 독립된 장으로 설명한다. 일반 폴더와 Git 저장소를 반반 비교한다. 반복 노출된 명령어·상태 이름과 화면의 설명문을 줄인다. 최종 구성은 스토리보드의 「사용자 정정」을 우선한다.


## 저장소 비교의 강조

2번 Git 저장소 영역은 일반 폴더와 다른 색으로 강조한다. 두 그림의 일반 파일과 폴더 크기는 동일하게 유지하고, Git 저장소 안에만 `.git`을 작은 폴더로 추가한다. 일반적인 Git 프로젝트의 `.git`은 파일이 아니라 기록과 설정을 보관하는 숨김 폴더다. 기존 버전 점선 대신 `.git`을 보여주고 ‘파일과 변경 이력을 함께 관리’으로 짧게 설명한다.

숨김 속성은 그림에서도 구분한다. `.git`만 중립색 점선 윤곽과 0.38 불투명도로 작게 표시하고, 바깥 폴더 안쪽 오른쪽 아래에 보조 요소로 둔다. 일반 파일은 기존의 선명한 실선을 유지한다.

## 세 영역을 한 단계씩 설명 — 사용자 제공 자료 반영

기존 세 영역 슬라이드 하나를 같은 배치의 세 장으로 확장한다. 각 장에서 하나의 영역만 활성화하고 하단에 해당 설명 한 줄을 둔다. 다른 장의 문구·디자인은 유지한다.

- 작업 디렉토리(Working Directory): 실제로 파일을 편집하는 공간. 파일 생성·수정·삭제를 설명한다. 파일 저장과 Git 기록은 구분한다.
- 스테이징 영역(Staging Area / Index): 다음 커밋에 포함할 변경을 준비한다. 고친 것 중 기록할 내용을 선별한다. 실제 파일이 원래 폴더에서 사라져 이동한다고 설명하지 않는다.
- Git 저장소(Repository): 준비한 변경을 커밋으로 기록한다. 각 커밋에는 고유 식별자(해시)가 붙고, 기록한 버전을 다시 확인할 수 있다. 화면의 내 컴퓨터 경계 안에 있으므로 로컬 Git 저장소다.

명령어의 상세 입력 예시와 긴 불릿은 대본에서 풀어 설명한다. 세 장의 화면에는 역할과 하단 한 줄을 두고, 화살표 위에 해당 명령어를 표시한다. push·pull은 로컬·원격 장(7번)에서 소개한다. 전체 흐름 장(8번)은 add·commit·push의 한 방향 흐름으로 정리한다.

## 전체 흐름의 시선 연결 — 사용자 이미지 분석 반영

8번 ‘한 번의 작업 흐름’만 수정한다. 참고 이미지의 장점은 네 단계의 동일한 크기·배치, 행동을 나타내는 큰 동사, 한 높이에서 이어지는 오른쪽 화살표다. 카드의 배경·테두리를 복제하지 않고 이 관계를 적용한다.

네 단계를 같은 폭의 열린 도식으로 배치한다. ‘고친다 → 고른다 → 남긴다 → 올린다’를 주된 읽기 순서로 삼고, 각 단계 아래에 작업 디렉토리·스테이징 영역·로컬 저장소·원격 저장소를 표시한다. 큰 로컬 3개 / 원격 1개 프레임은 없애고 ‘내 컴퓨터’와 ‘원격’ 위치 딱지를 쓴다. add·commit·push는 단계 사이의 연결선 위에 한 번씩 둔다. 하단 pull 흐름은 제거한다. 네 단계는 그림·제목과 연결 화살표의 색으로 구분한다.

## 작업 디렉토리 문구 확정

3~5번의 작업 디렉토리 설명은 사용자 지정 문구 ‘실제 파일을 작업하는 유일한 공간’으로 표시한다.

## Git 저장소 문구 확정

- 3~5번의 Git 저장소 역할: 변경사항이 영구적으로 기록되는 공간
- 5번 하단: 커밋 히스토리가 남아, 언제든지 이전 버전으로 되돌릴 수 있습니다.

## 단계 비교의 움직임

4·5번은 등장·페이지 전환 애니메이션 없이 즉시 표시한다. 앞뒤 이동 모두 도식의 위치를 고정하고 강조 영역과 하단 설명만 바뀐다.

## 구성 축소와 commit 강조 — 최종 적용

기존 6번 ‘이번에 남길 변경’과 8번 ‘영역과 상태의 차이’를 제거해 총 8장으로 줄인다. 기존 7번은 새 6번이 되며, 제목을 ‘기록으로 남는 순간 - commit’으로 변경한다. 제목에서 commit만 브랜드색으로 강조한다.

## 커밋이 버전을 만드는 기준점

6번 하단은 ‘커밋한 시점이 곧 돌아갈 수 있는 버전입니다.’로 표시한다. Git은 커밋 전에도 변경을 감지하지만, 새 버전의 기록은 커밋으로 남긴다는 뜻이다.

## 로컬·원격 그림 복원

7번은 이전 V2의 노트북·클라우드 그림과 git push·git pull의 왕복 화살표를 사용한다. 현재 두 카드의 너비·간격·패딩을 유지하고, 위쪽 작은 제목 ‘내 컴퓨터’·‘원격’, 아래의 ‘로컬 저장소 / 내 컴퓨터의 기록’과 ‘원격 저장소 / GitHub에 올려 공유하고 협업’을 유지한다. 로컬 카드와 push는 브랜드색, 원격과 pull은 중립색으로 표현한다.

## 세 영역의 명령어 표기

3·4·5번 모두 작업 디렉토리 → 스테이징 영역 화살표 위에 git add, 스테이징 영역 → Git 저장소 화살표 위에 git commit을 표시한다. 기존 화살표·‘선택’·‘기록’의 위치는 유지한다. 4·5번의 애니메이션 없는 전환도 유지한다. 명령어는 git을 포함한 실제 입력 형태로 표기한다.

## 전체 흐름의 단계별 색상

8번의 하단 pull 행 전체를 제거한다. 네 단계의 같은 크기·좌표와 열린 배치는 유지하면서, 첫 단계는 브랜드 빨강, 두 번째는 노랑, 세 번째는 초록, 네 번째는 보라로 구분한다. 각 단계의 그림과 큰 제목을 같은 색으로 묶고, 연결선과 명령어는 도착하는 단계의 색으로 표시한다. 위치 딱지와 영역 이름은 중립색으로 유지한다. 이 색은 파일 상태가 아닌 이 장의 작업 단계를 구분한다.

단계명 후보는 적용하지 않았다. 사용자가 현재 구성으로 마무리한 최종본은 ‘고친다 / 고른다 / 남긴다 / 올린다’를 유지한다.

## 세 영역 슬라이드의 도입 문장

3~5번 서브설명: Git의 기본 작업은 작업 → 스테이징 → 커밋의 3단계로 이루어집니다.

3~5번 제목은 ‘버전 관리를 위한 3 단계’로 확정한다. ‘3 단계’만 브랜드색으로 강조한다. 이는 기본 작업 흐름의 단계이며 파일 상태 이름을 뜻하지 않는다.

## 커밋 정보 항목의 정의

프로젝트 버전은 선택한 변경을 반영한 프로젝트 스냅샷이다. 6번의 ‘프로젝트 버전 / 선택한 변경을 반영’ 설명은 유지한다. ‘메시지 / 소개 문구를 구체화’ 예시는 ‘커밋 메시지 / 작업 내용과 변경 이유’로 바꾼다. 커밋 메시지는 해당 커밋에 묶은 작업을 설명하는 글이며, Git이 태스크마다 자동으로 붙이는 항목을 뜻하지 않는다.

## 전체 흐름의 순차 등장

애니메이션 순서: 작업 디렉토리 → git add 화살표·명령어 → 스테이징 영역 → git commit 화살표·명령어 → 로컬 저장소 → git push 화살표·명령어 → 원격 저장소. 단계 안의 위치 딱지·그림·제목·영역 이름은 한 묶음으로 나타난다. 전체 가로 흐름을 통째로 움직이지 않는다. 첫 요소는 150ms 후 시작하고 요소 간 260ms, 단계 간 520ms의 시간차로 등장한다. 이동·페이드는 기존 480ms를 유지한다. 재진입하면 첫 단계부터 다시 재생한다.
