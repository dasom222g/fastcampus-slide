# Ch01-01. Git이란 - 버전 관리가 없다면

제작 목표: 개발자가 아닌 사람이 Git을 "왜 필요한지"부터 납득하게 만든다

> **청중이 개발자가 아니다.** 명령어를 가르치는 클립이 아니다. 이 클립에서 명령어는 한 줄도 쓰지 않는다.
> 이 강의가 Git을 다루는 이유는 단 하나 — 에이전트마다 작업 공간을 나누는 바탕이기 때문이다.

#### 1. 버전 관리가 없으면 이렇게 된다

역할: 누구나 겪은 장면으로 연다. 참고자료의 「버전 관리가 필요한 이유」를 그대로 쓴다.

말할 내용

- 파일 이름으로 버전을 관리하면 이렇게 된다:
  `내프로젝트_최종.zip` → `내프로젝트_최종_진짜최종.zip` → `내프로젝트_최종_진짜최종_완성.zip` → `내프로젝트_최종_진짜최종_완성_수정.zip`
- 파일 이름만으로는 최신 파일과 변경 내용을 판단하기 어렵다. 이전 복사본이 남아 있어도 원하는 상태를 찾아 비교하고 복원하는 일을 사람이 직접 해야 한다.

슬라이드: 1장 — 파일명이 늘어나는 장면. 이 클립에서 가장 공감이 큰 화면이다

#### 2. Git이 대신 하는 일

역할: 정의. 참고자료의 「Git이란」을 쓰되 개발 용어를 덜어낸다.

말할 내용

- Git은 **파일의 변경 이력을 기록하고 관리하는 도구**다.
- 파일 이름에 버전을 붙일 필요가 없다. 변경을 기록할 때 "무엇을 왜 바꿨는지" 메시지를 함께 남긴다.
- 기록해 둔 특정 시점의 상태를 다시 확인하고 되돌릴 수 있다.
- 여러 사람의 변경을 확인하고 합칠 수 있다. 같은 부분을 다르게 수정하면 충돌은 여전히 생길 수 있다.

슬라이드: 2장 — 정의 1장 + 해결되는 것 1장

#### 3. Git과 GitHub는 다르다

역할: 가장 자주 섞이는 두 이름을 갈라놓는다.

말할 내용

- **Git** — 버전 관리 시스템. 파일의 변경 이력을 기록하고 관리한다.
- **GitHub** — Git 저장소 호스팅 서비스. 프로젝트와 기록을 온라인에 보관하고 공유한다.
- Git과 GitHub의 정확한 역할 명칭을 먼저 제시하고 쉬운 설명을 함께 둔다.

슬라이드: 1장 — 좌우 대비

#### 4. 이 강의가 Git을 다루는 이유

역할: 이 강의만의 각도. 참고자료에 없는 부분이고 여기가 이 클립의 존재 이유다.

말할 내용

- 개발을 하려고 배우는 게 아니다.
- 에이전트를 여러 개 돌리려면 **작업 공간을 필요에 따라 나눠야** 하는데, Orca가 그걸 Git 위에서 만든다.
- 앞 클립에서 본 "같은 파일을 동시에 건드린다" 문제가 여기서 풀린다.
- 그래서 필요한 만큼만 배운다. 명령어는 다음 챕터에서 실습으로 다룬다.

슬라이드: 없음 — 공간 분리 구조는 뒤 클립에서 다룬다. 이 덱에서는 도입의 짧은 연결로만 언급한다.
