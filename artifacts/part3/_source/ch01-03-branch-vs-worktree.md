# 브랜치와 워크트리 차이

목표: 브랜치(이력의 줄기)와 워크트리(실제 작업 폴더)를 구분하고, 같은 프로젝트의 서로 다른 작업을 동시에 진행하는 구조를 이해한다. Part 2의 Orca 작업 공간과 연결한다.

사용자 요청: 정식 경로의 현재 덱을 분석하고 부족한 점을 수정한다. 직전 확정 덱의 간결한 문장·의미 있는 경계·같은 역할의 폰트 규격·단계별 등장을 따른다. 표지에는 목차를 넣지 않는다. 이전에 옮긴 ‘각자의 작업 공간’의 승인 도식은 유지한다.

## 현재 구성 방향

- 먼저 같은 작업 폴더에서 여러 에이전트가 파일을 건드리는 문제를 체감시킨다. 해결의 목적은 실제 작업 공간을 나누는 것이다.
- 워크트리의 필요를 먼저 제시하고, 각 공간에서 이어갈 작업 이력을 이해하기 위해 브랜치를 설명한다. 브랜치에서 워크트리로 개념이 확장되는 방식으로 설명하지 않는다.
- 1 표지 → 2 같은 폴더의 문제 → 3 브랜치 → 4 한 시점의 제약·타임머신 비유 → 5 실제 작업 폴더 구조 → 6 생성 흐름 비교안 → 7 워크트리·브랜치의 관계 → 8 분기·폴더 관계 비교안 → 9 에이전트별 작업 공간 → 10 Orca.
- 기존 4·5번은 비교 중인 두 장이므로 새 번호 5·6번으로 함께 보존한다. 공유 저장소 관계와 생성 흐름을 사용자 비교용으로 남긴다.
- 「언제 쓸까?」의 선택지 구성을 없애고, 워크트리 A와 브랜치 A·워크트리 B와 브랜치 B의 연결 관계를 보여준다.
- 정확성 확인용 내부 메모와 초보자용 대본을 구분한다. 원래 폴더도 워크트리라는 부연, 브랜치마다 추가 폴더가 필수인지에 대한 예외는 대본에서 제거한다.

## 기술적 범위

브랜치는 기술적으로 커밋을 가리키는 이름(참조)이다. 화면에서는 ‘이력의 줄기’로 설명하고, 새 커밋을 남기며 그 줄기를 이어간다고 말한다. 브랜치를 만들기만 하면 폴더가 복제되거나 다른 브랜치의 미커밋 작업까지 자동으로 격리된다고 하지 않는다.

워크트리는 같은 저장소에 연결된 실제 작업 폴더다. 저장소의 커밋·브랜치 정보는 공유하고 각 폴더의 작업 파일·스테이징 상태는 별도다. 원래 작업 폴더도 워크트리에 포함된다. 기본적인 사용 예로 폴더마다 서로 다른 브랜치를 열어둔다.

워크트리가 파일 접근을 강제로 차단하거나 병합 충돌을 없애는 것은 아니다. 각자 지정된 폴더에서 작업하면 같은 작업 파일을 동시에 건드리는 문제를 줄인다. 작업 결과를 기록하고 합치는 과정은 별도로 진행한다. 워크트리당 에이전트가 반드시 한 명이어야 하는 것은 아니다.

상세 명령어·포인터/HEAD 내부 구조·detached HEAD·clone 비교·충돌 해결은 이 클립 화면 범위에서 제외한다. 실습 예고는 마지막 대본으로만 연결한다.

## 슬라이드 4/10 — 한 번에 한 시점만

서브설명: 타임머신으로 10살의 나에게 돌아가, 새로운 삶을 시작한다면

화면 문구: 10살 / 20살 / 30살 / 원래의 삶 / 새로운 삶 / 타임머신 / 한 폴더에서는 한 번에 하나의 시점만 엽니다.

시각 장치: 원래 삶의 10살·20살·30살 중 10살에서 새 시간선이 갈라져 새로운 삶의 20살로 이어진다. 3번과 같은 분기 구조다. 한 대의 차가 원래 삶의 30살 → 10살 → 새로운 삶의 20살로 이동한다. 원래 삶의 시간선은 남아 있고 현재 위치 표시는 하나만 움직인다.

배치: 기존의 단순한 자동차형 SVG를 사용한다. 차체·창문·운전자·두 바퀴와 「타임머신」 이름만 남기고 별도 시간 이동 장치·안테나·배선 등 복잡한 요소를 넣지 않는다. 생성한 PNG는 이 장에서 사용하지 않는다. 10살에서 갈라지는 곡선과 기존 나이 라벨·하단 문장은 원래 배치로 복원한다.

애니메이션: 기존 8초 이동을 유지한다. 원래 30살에서 잠시 머문 뒤 10살로 돌아가고, 새 줄기를 따라 새로운 20살로 이동한다. 재진입하면 처음부터 재생하고, 모션 감소 설정에서는 최종 관계를 정적으로 표시한다.

비유의 범위: 시간선은 브랜치, 나이 점은 커밋한 시점에 대응한다. 작업 폴더 하나는 한 번에 하나의 시점만 연다는 제약을 설명한다.

근거: 사용자 최신 확정 — 기존처럼 단순한 차로 복원하고, 분기는 다시 10살에서 시작한다.

## 슬라이드 5/10 — 같은 저장소, 서로 다른 폴더

서브설명: 워크트리는 같은 Git 저장소에 연결된 실제 작업 폴더입니다.

화면 문구: 공유하는 Git 저장소 / 원래 작업 폴더 / 작업 폴더 A / 작업 폴더 B / main / 작업 A / 작업 B / 워크트리는 물리적으로 분리된 작업 폴더이므로, 각 폴더의 작업 파일은 서로 영향을 받지 않습니다.

시각 장치: A 폴더의 마지막 파일은 빨강, B 폴더의 마지막 파일은 보라로 표시해 폴더마다 서로 다른 작업 파일임을 보여준다. 나머지 파일은 중립색을 유지한다.

## 슬라이드 6/10 — 워크트리란

서브설명: Git 저장소에 연결된 실제 작업 폴더입니다.

화면 문구: main / v1 시점 / 작업 A / 작업 폴더 A / 작업 B / 작업 폴더 B / 각 워크트리의 작업 파일은 서로 영향을 받지 않습니다.

시각 장치: 상단의 작은 main 폴더에서 아래의 큰 작업 폴더 A·B로 갈라지는 수직 화살표. 세 폴더의 브랜치 아이콘과 이름은 모두 폴더 안 같은 상대 위치에 둔다. main 옆에는 「v1 시점」만 표시한다. A의 마지막 파일은 빨강, B는 보라로 구분한다. 아래 두 폴더 밑에는 작업 폴더 A·B 제목만 표시한다. 생성 이후 서로 다르게 작업한 결과라는 점은 대본에서 설명한다.

배치: 공통 헤더·본문·푸터 사이 기본 행 간격과 패딩을 복원한다. 본문은 최대 40rem 높이 안에서 도식과 하단 문장을 배치하고 두 요소 사이에는 1rem을 둔다. A·B 폴더는 5번 슬라이드의 워크트리 폴더와 같은 실제 크기로 맞춘다. 최대 너비 21rem, 좁은 화면에서는 5번의 세 열 너비 계산을 그대로 적용한다. 선 두께와 글자 크기도 5번의 규격을 유지한다. 도식의 전체 너비는 최대 60rem으로 제한한다. 폴더 아래에는 제목만 남겨 높이를 확보한다. 작은 main과 v1 시점 라벨은 상단 중앙, A·B는 하단 두 열에 놓는다. 화살표는 main과 A·B 폴더의 실제 SVG 좌표를 기준으로 연결한다. main의 아래쪽 경계에서 8px 띄워 시작하고, 각 화살촉은 A·B 폴더 중앙의 위쪽 경계에서 12px 위에 놓는다. 고정 높이 컨테이너에서 화살표가 먼저 끝나지 않도록 연결선을 도식 전체에 겹쳐 그린다. 화면 크기·폰트·등장 위치가 바뀌면 폴더 위치를 다시 측정해 선 길이를 갱신한다. 본문 전체를 무한히 채우거나 모든 여백을 없애지 않는다. 공통 글자 크기와 문구는 유지한다.

애니메이션: main 폴더→분기 연결→A 폴더→B 폴더→하단 핵심 문장. 연결선은 제자리에서 나타난다.

범위와 근거: 비교용 공유 저장소 구조 장은 보존하고 이 생성 흐름 장만 수정한다. main의 v1은 예시이며, 미커밋 파일을 복사하는 흐름이 아니다. 같은 버전에서 출발한 뒤 각자의 작업 파일을 수정하는 과정을 설명한다. Git 공식 문서 https://git-scm.com/docs/git-worktree#_commands

## 슬라이드 7/10 — 브랜치와 워크트리의 관계

서브설명: 서로 다른 브랜치를 각자의 워크트리에서 열어두고 동시에 작업합니다.

화면 문구: 워크트리 / 실제 작업 공간 / 작업 폴더 A / 작업 폴더 B / 브랜치 / 작업 이력 / 작업 A / 작업 B / 파일은 각자의 폴더에서 수정하고, 기록은 각자의 브랜치에 남깁니다.

시각 장치: 왼쪽 열은 실제 파일을 가진 워크트리 A·B, 오른쪽 열은 각 작업의 브랜치 A·B를 커밋 줄기로 표현한다. 같은 행의 폴더와 브랜치를 선으로 연결한다. A는 빨강, B는 보라로 폴더·마지막 파일·연결선·이력을 일관되게 표시한다. 폴더 안 라벨은 「작업 폴더 A/B」, 이력 쪽 라벨은 「작업 A/B」로 대상을 구분한다.

배치: 위에 두 열의 공통 heading과 설명, 아래에 두 행의 대응 도식. 폴더 경계 외 장식 박스 없음. 연결선은 생성 순서나 택일 화살표가 아닌 관계선이다. 공통 heading·copy·eyebrow 규격을 유지한다.

애니메이션: 두 열의 표제→A 작업의 폴더·연결·이력→B 작업의 폴더·연결·이력→하단 핵심 문장. 각 행은 연결이 끊겨 보이지 않도록 제자리에서 나타난다.

근거: 사용자 최신 요청과 Git 공식 문서. 워크트리로 실제 작업 공간을 나누고, 각 작업 공간에서 서로 다른 브랜치의 이력을 이어간다. https://git-scm.com/docs/git-worktree#_description · https://git-scm.com/book/en/v2/Git-Branching-Branches-in-a-Nutshell

## 슬라이드 8/10 — 브랜치와 워크트리의 관계 (분기 비교안)

서브설명: 서로 다른 브랜치를 각자의 워크트리에서 열어두고 동시에 작업합니다.

화면 문구: 브랜치 / 작업 이력 / main / 작업 브랜치 / 워크트리 / 실제 작업 공간 / 원래 작업 폴더 / 추가 작업 폴더 / 파일은 각자의 폴더에서 수정하고, 기록은 각자의 브랜치에 남깁니다.

시각 장치: 왼쪽의 공유된 커밋 줄기에서 위쪽 main은 직선으로 이어지고, 아래쪽 작업 브랜치는 보라색으로 갈라진다. 각 줄기의 오른쪽 끝에 해당 워크트리 폴더를 붙인다. main과 원래 작업 폴더는 회색, 작업 브랜치와 추가 작업 폴더는 보라색이다. 폴더 안 실제 파일을 함께 표시한다. 선은 생성 순서가 아닌 브랜치와 폴더의 연결 관계다.

배치: 브랜치·작업 이력 표제는 왼쪽, 워크트리·실제 작업 공간 표제는 오른쪽. 아래 두 폴더의 실제 위치에 맞춰 커밋 줄기와 분기 곡선을 그린다. 기존 7번의 공통 타이포·폴더 크기·핵심 문장을 유지한다. 장식 박스는 추가하지 않는다. 관계를 한눈에 비교할 수 있도록 도식은 정적으로 표시한다.

범위: 기존 7번은 덮어쓰지 않고 바로 다음에 추가한다. 두 장은 사용자 비교용으로 보존한다. 원래 폴더가 main을 열고, 추가 폴더가 작업 브랜치를 여는 예시다. 브랜치마다 폴더가 자동 생성된다는 의미로 설명하지 않는다.
