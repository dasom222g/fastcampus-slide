## 슬라이드 5 / 13 — 출력부터 정하는 설계

- 타입: INPUT_OUTPUT_FLOW의 출력 우선 설계 변형. 템플릿의 자료·요청·AI·화면 요소를 사용한다.
- 수강생의 질문: 발표자료를 맡기려면 AI에 무엇을 줘야 하는가?
- 핵심 메시지: 산출물에 담을 내용을 먼저 정하면 필요한 자료와 요청이 명확해진다.
- 왼쪽 01 산출물 결정: 월간 실적 발표자료. 실적 요약·주요 성과·다음 달 계획을 세 장의 슬라이드 형태로 보여준다.
- 오른쪽 02 자료·요청 준비: 월간 실적표와 업무 성과·추진 계획 메모. 요청은 ‘실적 요약·주요 성과·다음 달 계획 순서로 월간 실적 발표자료를 만들어 줘’.
- 가운데: 산출물에서 필요한 자료·요청으로 향하는 오른쪽 화살표. 설계 순서만 보여주며 AI 작성 단계는 넣지 않는다.
- 정렬: 두 열의 머리말·자료 영역을 같은 행에 둔다. 설계 화살표는 자료 영역의 수직 중앙에 배치한다.
- 타이포·색: 템플릿 flow-heading·artifact-title·copy 규격. 입력 purple, 산출물 green.
- 등장: 왼쪽 산출물 → 가운데 화살표 → 오른쪽 자료 → 오른쪽 요청. 도식의 위치는 고정한다.
- 근거: 사용자의 직장인 업무 사례·발표자료 예시 요청과 기존 출력 우선 설계 교육 목표.

## 슬라이드 6 / 13 — 작업 간 의존 관계

- 타입: ARTIFACT_HANDOFF. 일반적인 멀티에이전트의 작업 간 의존 관계.
- 수강생의 질문: 앞 작업의 결과물이 다음 작업에서는 무엇이 되는가?
- 핵심 메시지: 앞 에이전트가 만든 결과물이 다음 에이전트의 입력 자료가 된다.
- 화면: Worker A(발표자료 제작) → 월간 실적 발표자료 → Worker B(발표 대본 작성).
- 관계: 왼쪽 화살표 Output, 오른쪽 화살표 Input. 앞 워커는 자료를 만들고, 뒤 워커는 그 자료를 읽어 대본을 작성한다.
- 제외: 코디네이터·완료 확인·배정·Orca 오케스트레이션. 이 장은 실행 관리 방법을 설명하지 않는다.
- 색: Worker A brand, 산출물 green, Worker B purple. Output green, Input purple.
- 정렬·동작: 한 줄 수평 흐름, 고정된 위치에서 앞 워커 → 결과물 → 뒤 워커 순서로 등장.
- 하단: 앞 작업의 산출물 = 다음 작업의 입력 자료
- 근거: 사용자가 이 장의 메시지를 작업 간 입출력 관계로 명확히 한 지시.

## 슬라이드 8 / 13 — 협업을 나누는 기준

- 구조: 앞 장과 같은 2열 비교. 패턴별 원본→에이전트→결과의 같은 세로 축을 유지한다.
- 왼쪽 병렬 실행: 같은 요청 → 에이전트 A·B → 결과 A·B 중 사람이 선택. 마지막 사람 노드를 gray로 표시한다.

- 메시지: 같은 작업을 여러 에이전트에게 맡겨 고를지, 서로 다른 역할의 결과를 모두 쓸지 구분한다.

## 협업 기준 비교 장 수정

- 7장 — 협업을 나누는 기준: 다음 작업의 재료로 쓸지, 검토·수정할 대상으로 넘길지 비교한다. 패턴 이름·용어 정의는 넣지 않는다.
- 8장 — 협업을 나누는 기준: 여러 안 중 선택할지, 역할별 결과를 모두 사용할지 비교한다.
- 판단 기준 → 왼쪽 구조 → 오른쪽 구조 순서로 등장한다. 노드와 연결선은 고정 좌표에서 페이드하고 이동시키지 않는다.
- 기존 네 열 비교 장은 삭제하고 두 비교 장을 7·8장으로 확정한다. 뒤의 프로젝트 소개 내용은 유지한다.


### 기준별 화면 문구

- 순서대로 진행 — 앞 작업이 끝나야 다음 작업을 시작
- 작성·검토 분리 — 작성한 결과를 다른 에이전트가 검사
- 같은 작업 비교 — 같은 요청으로 만든 결과 중 하나 선택
- 역할별 분담 — 서로 다른 일을 맡겨 결과를 모두 사용
