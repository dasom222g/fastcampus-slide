# Ch04-04 스토리보드 — 품질 게이트로 통과 기준 세우기

상태: 사용자 검수 전, 16장(본편 12장 + 비교안 4장) / 본편 10분 계획. 실제 낭독 시간 미측정.

## 설계

완료 확인과 품질 검토를 먼저 구분한 뒤 3장에서 앞 수업의 작업 기준과 이번 품질 검토 기준을 대비한다. 두 기준은 실행 전에 정하고, 적용 시점은 작업 중 / 각 단계 결과 후로 나눈다. 이어 실제 문서의 검사 대상과 대조 자료로 통과 조건을 설명하고, 이미 정한 작업 기준을 품질 기준으로 바꾸는 대응 관계를 보여준다.

골든셋 타이포와 역할 색을 유지한다. 사람 gray / 작업 워커 brand / 코디네이터 yellow / 다음 워커 purple / 문서·통과 green / 반려 orange. 작업 기준은 brand, 품질 기준은 yellow로 대응한다. 화살표와 연결선은 작성 규칙의 변환·문서 대조 관계에 사용한다. 제목의 핵심 의미만 강조하고 모든 copy는 두 줄 이내로 쓴다. 하단 보충은 독립 행이다.

본문의 연결선·부등호·문서 경계도 등장 대상이다. 관계의 양쪽 대상이 나타난 뒤 연결한다. 수정 반환선은 노드 설명 및 반환 문구와 간격을 둔다. 2장은 코디네이터의 보고 접수 / 문서 내용 검토만 보여준다.

## 정식 2장 반영

## 3장 재설계 — 생성 기준과 검증 기준의 역할 대비

최신 사용자 요청: 문장형 제목과 하나의 파이프라인처럼 보이는 연결을 제거한다. 제목은 ‘작업 중 생성 기준 / 완료 후 검증 기준’. 두 장면 사이에 연결선이나 단계 번호를 두지 않는다.

- 왼쪽: 작업 중 / 작업 기준. 실행 담당이 규칙을 보면서 문서를 작성하는 생성 이미지. 입력은 작업 기준, 결과는 결과물 생성. 예: 출처를 기록하며 시장 조사 노트 작성.
- 오른쪽: 단계 완료 후 / 품질 검토 기준. 검토 담당이 이미 완성된 문서를 검사표와 대조하는 생성 이미지. 입력은 완료된 결과물, 결과는 기준 충족 여부 검증. 예: 출처와 주장을 대조해 통과·반려 판단.
- 장면 원장: 실행 담당은 작성대에서 규칙을 참조하며 작성 중인 문서에 내용을 더한다. 검토 담당은 별도의 검토대에서 완성 문서를 검사표와 대조한다. 이동·자동 전달·두 장면 사이 경로는 없다. 검토 담당은 이 파이프라인의 코디네이터이며 Part6의 별도 평가 모델로 바꾸지 않는다.
- 생성 이미지에는 라벨·문장·화살표를 넣지 않고, 시간과 역할은 HTML 텍스트로 명시한다. 생성 담당은 brand, 검토 담당은 yellow.
- 두 기준 모두 실행 전에 준비한다는 하단 보충은 유지한다. 두 장면 모두 같은 높이의 제목·이미지·설명으로 정렬하고 각각 등장시킨다.

## 최신 적용 — 2·3장 재설계 우선

앞서 기록된 질문형 제목·2장 기준 설명·3장 연결 파이프라인은 아래 최종 상태로 대체한다.

2장: 완료 확인 ≠ 품질 검토. 코디네이터 한 명, 보고 말풍선, 문서 돋보기. 보고 접수 / 내용·근거 검토만 대비한다.
3장: 작업 중 생성 · 완료 후 검증. 역할과 적용 시점이 다른 두 장면을 분리한다. 생성 담당은 빨간색, 검토 담당은 노란색. 두 기준의 준비 시점은 실행 전이다. 별도 평가 모델을 추가한 것이 아니다.

이미지: `_images/ch04-04-quality-gate--creation.png`, `_images/ch04-04-quality-gate--verification.png`. 내장 image_gen으로 생성. 첫 장면은 규칙책을 보며 작성하는 빨간 로봇, 두 번째는 완료 문서와 검사표를 돋보기로 대조하는 노란 로봇. 텍스트와 연결선은 이미지에 넣지 않았다.

## 3장 최신 용어·강조

제목: 기준의 두 역할. 핵심 대비는 작업 기준(brand) / 품질 기준(yellow). 적용 시점은 작업 중 / 작업 후, 담당은 워커 / 코디네이터로 통일한다. 상태 라벨은 중립색으로 두고 핵심 기준 이름에 키컬러를 적용한다. 두 기준은 작업 전에 준비하며 작업 후는 각 단계 결과 이후를 뜻한다. 기존 생성 이미지와 두 장면 분리는 유지한다.

## 최신 재구성 — 기획 문서와 검증 대상 중심

사용자 요청: 지나치게 구체적인 가상 예시와 세부 조건으로 문맥이 흐려지는 문제를 해결하되 우리 판매 아이템 기획 프로젝트의 기준은 유지한다. 장수는 12장 유지, 기존 비교 후보는 보존. 4~9장 및 11장의 세부 표현을 수정한다.

4. 시장 조사 노트의 통과 기준: 실제 문서의 기재 판단을 검사 대상으로 보여주고 출처 대조 후 통과·보완 조건으로 연결한다. 세 문서 개요만 나열하는 중간안은 사용하지 않는다.
5. 작업 기준을 품질 기준으로: 각 문서별 작성 규칙과 검증 항목을 직접 연결. 출처 기록→주장·출처 대조, 선정 기준으로 비교→추천·선정 기준 대조, 앞 문서 반영→원문·기획서 대조. 막연한 요청이나 수요 증가 가상 주장을 쓰지 않는다.
6. 시장 조사 노트의 근거: 문서의 주장·수치와 출처 자료를 나란히 두고 대조 관계를 보여준다. 범위·사실/추정 구분은 대본에서 설명한다.
7. 아이템 후보 비교표의 선정 근거: 사업 조건과 선정 기준을 최종 추천과 대조하는 두 관계. 임의 점수·재고 충돌 사례 없이 조건 충족과 기준 적용을 보여준다.
8. 판매 아이템 기획서의 일관성: 조사 근거와 선정 결론이 기획서에 같은 내용으로 반영되는 관계. A/B 가상 품목 대신 문서 간 실제 이어지는 정보로 표시한다.
9. 일부 충족 ≠ 전체 통과: 기획서의 예산이라는 대상을 명시하고 금액 근거·합계·한도 검사에서 모두 통과 / 한 항목 반려를 대비한다. 임의 금액 없음.
11. 바뀐 근거는 다시 연결: 공급가·마진 수치 대신 조사 내용→선정 결론→기획서 영향 관계로 표시.

화면에는 문서·검증 대상·관계만 남기고 구체적인 제외 조건, 동점 규칙, 6개 섹션 등은 대본에 둔다. 숫자·개수만으로 품질을 판단하는 뜻이 되지 않도록 한다.

## 최신 정식 반영 — 문맥과 실제 검사 대상

4장은 시장 조사 노트에 있는 반려동물 소모품의 ‘트렌드: 상승’이라는 실제 기재를 보여주고, 출처 자료 대조와 해당 항목의 통과·보완 조건을 연결한다. 이는 문서에 적힌 내용을 검사하는 예이며 해당 시장 판단을 외부 근거로 검증했다는 뜻이 아니다. 근거 원문은 `../fastcampus-orca-course/project1-sidehustle-proposal/research-notes/market-research.md`의 2번 카테고리다. 출처 차트나 판정 근거를 만들어내지 않았다.

5~9장은 같은 프로젝트의 문서 이름과 검증 대상을 유지한다. 가상의 재고 조건 충돌, A/B 품목, 20·30·10·61만 원은 정식 화면에서 제거했다. 실제 기준의 세부 항목은 대본에서 설명한다. 이전 기존/현재 비교 파일은 보존했다.

## 3장 제목·강조·하단 문구 복원

제목은 ‘작업 기준과 품질 기준의 구분’. 제목·본문 모두 공통 단어 ‘기준’은 흰색, 다른 단어 ‘작업’은 brand, ‘품질’은 yellow로 강조한다. 하단은 직전 문구 ‘작업 기준과 품질 검토 기준은 모두 실행 전에 준비합니다.’로 복원한다. 작업 중/작업 후와 워커/코디네이터, 생성 이미지는 유지한다.

## 통합한 비교 파일의 제작 기록

# 문서 검사 두 장 비교 후보

사용자 요청으로 기존 ‘근거를 확인하는 검사’와 ‘점수와 추천의 연결’을 복원한다. 정식 13장 덱과 대본은 그대로 보존하고, 이 비교 파일에서 기존/현재를 연속해서 고른다.

1. 근거를 확인하는 검사 — 기존: 시장 조사 노트의 범위·출처·확인 상태와 검사 질문 대응
2. 근거를 확인하는 검사 — 현재: 출처 없는 주장을 코디네이터가 보완시키는 사례
3. 점수와 추천의 연결 — 기존: 품목 근거·점수 계산·추천 규칙을 함께 검사
4. 사업 조건에 맞는 추천인가? — 현재: 재고 미보유 조건과 대량 매입 추천의 충돌

기존안의 내용·제목·열 배치는 당시 생성 코드에서 복원하고 경계와 머리글도 등장 순서에 포함한다. 선택 전 후보이므로 정식 장수·대본·대시보드를 변경하지 않는다.

## 의미 확인

후보의 우선순위와 최종 1개를 정하는 일은 후보 도출 작업이다. 품질 게이트는 그 결과가 미리 정한 사업 조건·선정 기준·제외·동점 규칙과 근거를 충족하는지 검토한다. 사업 조건도 판단 기준에 포함된다. 품질 게이트가 새로운 조건을 임의로 추가하거나 최적의 추천을 보장하는 뜻이 아니다. 기존 제목은 검사 목적을 충분히 드러내지 못한다는 사용자 지적을 보존한다.

최신 위치: 시장 조사 6~8장, 후보 선정 9~11장. 위 별도 파일 유지 지시는 사용자 최신 통합 요청으로 대체됐다.

## 3장 하단 원문 재복원 · 제목 후보

사용자가 지칭한 이전 하단 문구는 ‘각 단계의 결과가 나온 뒤, 다음 작업을 배정하기 전에 검사합니다.’이다. 중간 수정본을 이전 버전으로 잘못 해석했던 것을 바로잡아 정식 화면에 이 원문을 복원했다. 제목은 사용자가 후보를 요청한 상태로 유지한다. 후보: 기준의 적용 목적(추천) / 기준의 용도 구분 / 기준의 유형. 제목 선택 전 본문의 작업 기준·품질 기준 의미를 바꾸지 않는다.
