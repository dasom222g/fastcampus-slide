# Ch04-04. 품질 게이트로 통과 기준 세우기 — 피드백

## 1. 제작 상태

신규 제작, 사용자 검수 전. 10분 편성의 12장 이론 덱과 전체 대본. 강사 확정·촬영 완료로 기록하지 않는다.

## 2. 이번 요청 반영

- 2장에 “완료 확인 ≠ 품질 검토”. 지정 도입 대본 그대로, 50초 계획 배분.
- 코디네이터의 검토 능력을 인정하고 정해진 기준에 따른 필수 절차와 구분.
- 시장 조사 노트 / 아이템 후보 비교표 / 판매 아이템 기획서의 이름을 유지.
- 기준뿐 아니라 반려 시 담당 워커 수정·전체 재검사, 통과 후 다음 배정을 함께 요청.
- 예산 사례는 실제 오류가 아닌 교육용 가상 수치. 합계 항목 통과와 전체 통과를 구분.
- Part 5 같은 모델 검사, 별도 평가 워커 추가 없음.
- Ch04-04 이론 / Ch05-01 단계별 기준 설정·criteria.md 저장만 / Ch05-02 제공 프롬프트 의미 확인·전체 실행·검사·최종 문서 확인.

## 3. 다음부터 이렇게 해

- 타이틀의 강조는 의미로 정한다. 마지막 단어를 자동 강조하지 않는다.
- 표지는 해당 클립 전체 성격을 보여준다. 품질 검토에서는 문서→검사→통과/반려 관계를 보여준다.
- .p5-note는 본문 카드 사이의 설명이 아니라 하단의 독립 보충 행으로 배치한다. 본문과 충분한 상하 여백을 유지한다.
- copy는 두 줄 이내로 압축하고, 상세 설명은 대본에 둔다.
- 코디네이터가 문서를 검토할 수 있음과 그 검사를 매번 필수로 요청했음을 구분한다. 기본 자동 검사나 검사 정확성을 보장하지 않는다.
- 생성·제작 예시와 과거 실제 오류를 혼동하지 않는다. 통과 기록만 보지 않고 실제 문서의 검사 근거를 확인하게 연결한다.

## 4. 검증

최신 13장 기준으로 2133×1200·1280×800 총 26개 렌더. 넘침·깨진 이미지 없음, copy 두 줄 이내, 하단 본문 간격 최소 31.6px. 제목·대본 13장 일치. 모든 장 및 두 비교 후보의 애니메이션을 0/800/5000ms에서 확인했고, 본문에 애니메이션 없이 나타나는 텍스트·연결선·비교 기호가 없음을 확인했다. 재진입 및 동작 줄이기 설정도 확인했다. 이전 11/12장 검수 기록은 당시 버전의 이력이며 아래 최신 기록이 우선한다. 상세: `../_qa/ch04-04-quality-gate-report.md`.

## 5. 추가 사용자 확정

Ch04-01~03은 일반 에이전트에게 개별 작업을 요청하고, Ch04-04는 품질 게이트 이론을 설명한다. Ch05-01 「단계별 품질 기준 정하기」(14분)는 시장 조사 노트·아이템 후보 비교표·판매 아이템 기획서의 단계별 통과·반려 기준을 정해 `artifacts/quality-gate/criteria.md`로 저장하는 실습만 한다. 프롬프트 작성·실행·반려 시연은 포함하지 않는다. Ch05-02 「목표 하나로 처음부터 끝까지 실행하기」(15분)는 강사가 제공한 프롬프트의 작업 순서·입출력·품질 기준 참조·반려/재검사 규칙을 이해한 뒤 바로 전체를 실행한다. 진행·검사·실제 반려 시 담당 워커의 수정 과정과 최종 세 문서를 확인한다. 프롬프트를 새로 작성하지 않으며, 반려를 만들기 위한 필수 오류 주입·사전 실행은 없다. 실제 반려 기록으로 설명하고 추가 연습은 본 실행 이후 선택사항이다. 코디네이터가 검사하며, 반려하면 원인 문서의 담당 워커가 수정하고 전체 기준을 재검사한다. 통과한 경우에만 다음 작업을 배정하고 상위 문서가 바뀌면 영향받는 후속 문서를 재확인한다. Part 5 같은 모델 기준 검사와 Part 6 다른 모델 교차 검증을 구분한다. 제작 중 상태이며 강사 확정·촬영 완료로 기록하지 않는다.

## 6. 기준 작성법과 정렬 수정

사용자 지적: 모든 장의 수직·수평 정렬, 특히 4·5장 대응 관계가 어긋남. 3장 화살표 나열과 넓은 빈 간격, 기준의 의미와 만드는 방법이 불명확함.

반영: 3장에서 ‘다음에 내릴 판단 → 판단이 틀릴 원인 → 확인할 근거 → 통과/반려 조건’을 한 사례로 만든다. 수치화 가능성으로 기준을 정의하지 않는다. 4·5·6장 대응 항목을 같은 grid 행에 배치하고 7장 합계, 11장 안내 제목·설명도 같은 축을 공유한다. 2장 후보 A/B는 사용자 선택 전 상태로 유지한다.

## 7. 방법과 변환 결과를 함께

사용자 지적: 방법만 나열하지 말고 각 원래 요청과 수정된 기준도 대응시켜야 한다. 3장 안에 한 조사 요청의 원래/수정 문장을 같은 열로 연결하고, 4장에 조사·선정·예산의 변환 결과를 같은 행으로 비교하는 장을 추가했다. 총 12장, 10분 계획은 유지하고 전 대본 번호와 목차 장수를 동기화한다.

## 8. 최신 수정 — 관계와 시점

- 요청→검사 기준은 컬럼 표 대신 말풍선→화살표→문서로 직접 연결한다. 요청 안의 임의 줄바꿈 제거.
- 텍스트 항목표를 출처 누락 문서, 사업 조건과 추천의 충돌, A/B 선정 품목 불일치 사례로 교체했다.
- 반려 문구: **반려 항목·근거 전달 → 담당 워커 수정**. 반환선과 노드 설명·반환 문구 사이 간격을 확보했다.
- ‘기준을 쓰는 시점이 다릅니다’를 완료 확인 대비 다음인 3장에 추가. 작업 기준과 품질 검토 기준은 모두 실행 전에 준비한다. 전자는 작업 중 준수, 후자는 각 단계 결과 후 다음 배정 전 통과·반려 판단에 사용한다.
- 시장조사 기준·판매 아이템 선정 기준과 Ch05-01 기준 설정을 대본에서 연결하고, 수업 순서와 실제 적용 시점을 구분했다. 공식 문서 링크는 소스·대본에 기록했다.
- 전 장 연결선·문서 경계·비교 기호를 등장 순서에 포함. 13장과 대본·소스·스토리보드·목차를 동기화했다. 10분 편성 유지, 실제 낭독 시간은 미측정.

### 앞으로 적용할 원칙

기준을 정하는 시점과 사용하는 시점을 구분한다. ‘작업 전 기준 / 작업 후 기준’처럼 정의 시점을 혼동시키는 이름을 피한다. 기준을 만드는 방법만 나열하지 않고 원래 요청과 수정된 검사 조건을 함께 보여준다. 렌더 완료 화면만으로 애니메이션 검증을 통과 처리하지 않는다.

## 9. 기존 검사 장 보존 요청

사용자가 기존 ‘근거를 확인하는 검사’, ‘점수와 추천의 연결’을 보고 선택하겠다고 요청했다. `outputs/ch04-04-quality-gate-inspection-options.html`에 기존/현재를 각각 연속 배치한 4장 비교본을 만들었다. 정식 덱과 대본은 유지한다.

사용자 질문의 핵심: 후보 선정에서는 우선순위와 최종 1개를 정한다. 품질 검토에서는 그 추천이 조사 근거, 선정 규칙, 사업 조건을 제대로 반영했는지 판단한다. 사업 조건도 미리 정하는 기준의 일부다. 품질 게이트가 새로운 조건을 임의로 추가하거나 최적의 선택을 보장하는 것은 아니다. ‘점수와 추천의 연결’이라는 제목은 검사 목적이 불명확했음을 기록한다.

## 10. 정식 2장에 코디네이터와 대비 반영

사용자가 코디네이터 등장·제목·강조·대비 피드백이 정식 화면에 반영되지 않았음을 지적했다. 별도 후보만 제공한 상태에서 멈춘 것이 원인이다. 정식 2장을 코디네이터가 완료 보고 / 문서와 기준을 각각 확인하는 장면으로 변경했다. 같은 코디네이터를 동일한 크기·색으로 표현하고, 문서 검토 능력과 매번 검사하도록 정한 절차를 구분하는 문구를 유지한다. 제목은 ‘코디네이터는 무엇을 확인할까?’로 변경하고 ‘무엇을 확인’을 강조한다. 지정 도입 대본 본문은 보존하고 제목만 화면에 동기화한다. 이전 A/B는 비교 이력이며 정식 적용의 대체물이 아니다.

정식 2장 최종 재검증: 2133×1200·1280×800에서 코디네이터 대비를 실제 렌더. 대응하는 제목·설명·아이콘·라벨·질문의 Y 좌표 차이 0px, 넘침·깨진 이미지 없음. 연결선 포함 시작/중간/종료 등장 검증 통과. 대본 13장 제목 일치. 검증 기록: `_qa/ch04-04-quality-gate-coordinator-contrast.json`.

## 11. 제목·역할 대비와 2장 과밀 수정

사용자 지적: 3장의 문장형 제목과 하나의 자동 파이프라인처럼 보이는 도식이 메시지를 흐린다. 작업 중 기준으로 생성하는 역할 / 완료 후 결과물을 검증하는 역할을 분리해야 한다. 2장은 질문형 문구와 기준 설명을 넣어 텍스트가 과하다.

반영: 정식 2장의 제목을 완료 확인 ≠ 품질 검토로 바꾸고 보고 접수·문서 검토 두 행동만 남겼다. 3장은 작업 중 생성 · 완료 후 검증으로 바꾸고 작성/검증 삽화 두 개를 생성해 각 독립 장면에 사용했다. 두 장면 사이 연결선 없음. 화면과 대본 동기화. 이전 도입 원문 보존 지침보다 최신 사용자 수정이 우선한다.

### 다음부터 적용

타이틀은 장의 핵심 대비를 짧고 직접적으로 쓴다. 다른 역할의 대비를 순차 파이프라인처럼 연결하지 않는다. 개념 차이를 소개하는 장에 다음 장에서 설명할 검사 기준까지 넣지 않는다.

최신 2·3장 검증: 2133×1200·1280×800 실제 렌더에서 넘침·깨진 이미지 없음. 2장 질문형/기준 설명 제거, 3장 장면 사이 화살표 없음 확인. 새 생성 이미지 로딩 확인. 두 장의 시작/중간/종료 및 재진입 애니메이션 확인, 고정 노출 본문 없음. 전체 13장 대본 제목 일치. `_qa/ch04-04-quality-gate-roles-layout.json` 및 `-roles-motion.json` 참조.

사용자 지시에 따라 13번 중복 요약 장만 삭제했다. 6·9번은 유지하고 4번은 의미와 필요성을 논의하는 단계로 남겼다. 다음 실습 안내는 마지막 장 대본 끝에 축약했다. 1~12장 HTML 해시 보존 확인. 현재 총 12장이다.

## 13. 3장 용어와 강조 통일

사용자 지적: 실행 담당이라는 새 용어, 제목과 상태의 중복, 작업 기준·품질 기준 강조 누락, 작업 중/단계 완료 후의 비대칭 표현.
반영: 제목 ‘기준의 두 역할’, 핵심 이름 ‘작업 기준 / 품질 기준’에 brand/yellow, 시점 ‘작업 중 / 작업 후’, 역할 ‘워커 / 코디네이터’. 대본에서도 같은 용어를 사용한다. 키컬러는 상태보다 이 장의 핵심 비교 대상에 적용한다.

## 14. 기획 문서와 검증 대상 중심으로 정식 수정

사용자가 전체적으로 구체적인 예시·조건이 많아 이해하기 어렵지만 프로젝트의 품질 기준은 직관적으로 남기기를 요청했다. 또 문제를 진단하고도 4장을 그대로 두었다고 지적했다.

4장을 실제 시장 조사 노트의 검사할 문장→출처 자료 대조→해당 항목의 통과/보완으로 교체했다. 5장은 세 문서의 작업 기준과 검증 항목을 직접 대응시켰다. 6~8장은 조사 근거·선정 근거·계획 일관성을 문서 관계로 보여주고 가상 오류 상황을 제거했다. 9장은 가상 예산 금액 대신 예산의 근거·합계·한도 충족 여부로 전체 판정을 설명한다. 11장도 조사 내용·선정 결론·기획서 영향으로 단순화했다. 12장 유지, 비교 후보 보존.

최신 프로젝트 기준 개편 검증: 수정한 4~9·11장 2133×1200·1280×800 렌더 통과. 4장 실제 검사 대상과 8장 원문 연결선을 최종 재검수했다. 넘침·깨진 이미지 없음. 수정 7장의 시작/중간/종료 및 재진입 애니메이션 통과, 고정 노출 본문 요소 없음. 전체 12장 화면·대본 제목 일치. 기록: `_qa/ch04-04-quality-gate-project-criteria-layout.json`, `-recheck.json`, `-final4.json`, `-motion.json`.

## 15. 3장 요청 밖 문구 변경 복원

사용자 지적: 요청하지 않은 하단 문구 변경, 이름 전체를 칠한 강조, ‘두 역할’이라는 모호한 제목. 직전 하단 문구를 복원하고 공통 단어 ‘기준’을 제외한 ‘작업’/‘품질’만 강조했다. 제목은 ‘작업 기준과 품질 기준의 구분’으로 수정했다. 용어·강조 요청을 관계없는 문장 재작성으로 확대하지 않는다.

## 16. 같은 클립의 비교안을 해당 위치에 통합

사용자가 별도 파일로 나누지 말고 같은 클립의 해당 위치에 합치라고 지시했다. 기존 시장 조사 비교 2장과 후보 선정 비교 2장을 현재의 각 해당 장 앞에 통합했다. 각 묶음은 A(기존), B(사례), C(현재 수정)이며 선택 대기다. 기존 정식 본문은 보존하고 대본 번호·소스·스토리보드·목차를 동기화했다. 본편 12장 + 비교안 4장 = 16장으로 표시한다.

### 통합한 비교 파일 피드백 기록

# 문서 검사 비교 후보 — 선택 대기



후보의 우선순위와 최종 1개를 정하는 일은 후보 도출 작업이다. 품질 게이트는 그 결과가 미리 정한 사업 조건·선정 기준·제외·동점 규칙과 근거를 충족하는지 검토한다. 사업 조건도 판단 기준에 포함된다. 품질 게이트가 새로운 조건을 임의로 추가하거나 최적의 추천을 보장하는 뜻이 아니다. 기존 제목은 검사 목적을 충분히 드러내지 못한다는 사용자 지적을 보존한다.

## 3장 하단 원문 재복원 · 제목 후보

사용자가 지칭한 이전 하단 문구는 ‘각 단계의 결과가 나온 뒤, 다음 작업을 배정하기 전에 검사합니다.’이다. 중간 수정본을 이전 버전으로 잘못 해석했던 것을 바로잡아 정식 화면에 이 원문을 복원했다. 제목은 사용자가 후보를 요청한 상태로 유지한다. 후보: 기준의 적용 목적(추천) / 기준의 용도 구분 / 기준의 유형. 제목 선택 전 본문의 작업 기준·품질 기준 의미를 바꾸지 않는다.

비교안 통합 완료: 6~8장 시장 조사 A/B/C, 9~11장 후보 선정 A/B/C. 사용자 선택 전 상태. 원본 비교 4장의 본문을 그대로 보존했고 두 뷰포트 6장 렌더·등장/재진입 확인 통과. 별도 inspection-options HTML과 부속 문서는 내용 통합 후 제거했다. 현재 본편 12장+비교 4장=16장. 3장 하단은 ‘각 단계의 결과가 나온 뒤, 다음 작업을 배정하기 전에 검사합니다.’로 복원.
