## 3. 다음부터 이렇게 해 ★

- 출력 우선 설계에서 작업 간 의존 관계로 넘어갈 때는 ‘필요한 입력 자료가 아직 없다 → 그 자료를 만드는 작업이 먼저다’로 이어간다. 실제로 제시되지 않은 내용 불일치·임의 작성 사례를 원인으로 지어내지 않는다.
- 작업 간 입출력 관계를 설명하는 장에 코디네이터·도구별 실행 관리를 끼워 넣지 않는다. 이 장의 주장에 필요한 주체와 선만 남기고 제목·부제·도식을 같은 관계로 대조한다.

- 작업은 ‘메모 정리’처럼 행동으로, 산출물은 ‘회의록’처럼 문서명으로 구분한다. 카드가 실제 문서의 구성과 내용을 보여주는지 확인한다.
- 출력 우선 설계에서도 입력은 왼쪽, 산출물은 오른쪽에 둔다. 설계 순서는 번호·등장으로, 실행 방향은 화살표로 구분하고 두 열·연결선의 실제 경계를 측정한다.

- 제목 강조는 위치 규칙이 아니라 이 장에서 구분할 개념·주체·조건으로 고른다. “맥락 붕괴” 같은 용어를 마지막 단어만 잘라 강조하지 않는다.
- 하단 보충 문구를 본문 flex gap으로 처리하지 않는다. 본문과 하단 영역을 분리하고 실제 렌더링으로 상하 거리를 확인한다.
- 프로젝트 copy는 결과물·과정 두 줄로 정리한다. 학습자에게 불필요한 제작자 관점의 “완성 예시”는 넣지 않는다.
- 표지의 시각과 메시지는 해당 클립 전체의 성격을 대표해야 한다. 여러 패턴과 프로젝트를 소개하는 클립에 한 팀의 역할도·업무 흐름을 대표 이미지로 쓰지 않는다.
- 추상적인 구호 대신 이 영상에서 무엇을 보여주는지 바로 이해되는 문구를 쓴다. 기존 본문과 동일한 원본 이미지·캐릭터·색·타이포를 우선 재사용한다.

- 지정한 기준 표지의 실제 HTML·원본 이미지를 먼저 열고 비교한다. 공통 템플릿의 기본값만으로 동일하다고 판정하지 않는다.
- 표지 이미지 신규 생성 요청을 기존 이미지 여러 장 조합으로 대신하지 않는다. 제목·부제·본문이 같은 주제를 반복하는지 의미 단위로 확인한다.
- 협업 패턴에 앞서 Input → AI → Output, 원하는 출력에서 필요한 입력을 찾는 설계, 작업 사이 입출력 연결을 설명한다.

- 오른쪽에 실적 요약·주요 성과·다음 달 계획으로 구성된 발표자료를 먼저 보여주고, 왼쪽에 필요한 실적표·업무 메모와 요청을 보여준다.
- 템플릿의 자료·요청·화면 요소를 적용했다. 머리말·자료 영역은 같은 행, AI·연결선은 같은 수직 중앙에 둔다.

## 6번 장 메시지 정리

- 코디네이터와 실행 관리 설명을 제거했다. 발표자료 제작 → 월간 실적 발표자료 → 발표 대본 작성의 입출력 관계만 표시한다.

## 협업 기준과 패턴 소개 구분

- 8장 `작업의 연결 목적`, 9장 `결과의 활용 방식`으로 수정. 패턴 명칭을 큰 제목으로 반복하지 않고 업무를 나누는 판단 기준을 보여준다.
- 두 비교 장에 고정 위치 페이드 전개 추가. 도식의 좌표와 화살표 경로는 등장 중에도 유지한다.
- 기존 7장과 이후 패턴 소개 장은 보존한다.

- 제목 정정: 8·9장 모두 기존 `협업을 나누는 기준` 유지. 본문의 비교 관점을 제목 변경으로 확대하지 않는다.

- 기준별 제목·설명은 추상적인 대상 분류 대신 실제 진행 방식과 행동으로 표현한다. 두 장의 공통 제목은 유지한다.
