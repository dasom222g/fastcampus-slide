## 제작 범위와 사실 구분

- 사용자의 명시적 추가 요청으로 이론 덱과 전체 대본을 새로 만든다. 실습자료는 만들지 않는다.
- 코디네이터는 문서를 열어 검토할 수 있다. 검토 능력과 매번 정해진 기준으로 검사하도록 요청된 절차는 별개다. 기본 자동 검사에 관한 주장은 하지 않는다.
- Part 5는 같은 모델로 실행과 기준 검사를 다룬다. 별도 평가 워커를 추가하지 않는다.
- 작업 전에 검사 기준을 정한다. 작업 후 코디네이터가 검사하고, 반려는 원인 문서 담당 워커에게 돌려보낸다. 수정 뒤 전체 기준을 다시 검사하고 통과해야 다음 작업을 배정하도록 요청한다.
- Ch04-01~03은 일반 에이전트에게 개별 작업을 요청하고, Ch04-04는 품질 게이트 이론을 설명한다. Ch05-01 「단계별 품질 기준 정하기」(14분)는 시장 조사 노트·아이템 후보 비교표·판매 아이템 기획서의 단계별 통과·반려 기준을 정해 `artifacts/quality-gate/criteria.md`로 저장하는 실습만 한다. 프롬프트 작성·실행·반려 시연은 포함하지 않는다. Ch05-02 「목표 하나로 처음부터 끝까지 실행하기」(15분)는 강사가 제공한 프롬프트의 작업 순서·입출력·품질 기준 참조·반려/재검사 규칙을 이해한 뒤 바로 전체를 실행한다. 진행·검사·실제 반려 시 담당 워커의 수정 과정과 최종 세 문서를 확인한다. 프롬프트를 새로 작성하지 않으며, 반려를 만들기 위한 필수 오류 주입·사전 실행은 없다. 실제 반려 기록으로 설명하고 추가 연습은 본 실행 이후 선택사항이다. 코디네이터가 검사하며, 반려하면 원인 문서의 담당 워커가 수정하고 전체 기준을 재검사한다. 통과한 경우에만 다음 작업을 배정하고 상위 문서가 바뀌면 영향받는 후속 문서를 재확인한다. Part 5 같은 모델 기준 검사와 Part 6 다른 모델 교차 검증을 구분한다. 제작 중 상태이며 강사 확정·촬영 완료로 기록하지 않는다.
- 4장은 실제 시장 조사 노트의 문구를 검사 대상으로 인용한다. 해당 시장 판단을 검증한 결과가 아니다. 9장의 충족/미충족은 예산 품질 판정을 설명하는 도식이며 실제 프로젝트의 오류 기록이 아니다. 가상 품목·예산 금액은 정식 화면에서 제거했다.
- 원문 품질 기준의 6개 섹션명: 개요 / 시장분석 / 아이템 선정 근거 / 실행 로드맵 / 예산 / 리스크.
- 2026-09-22 최신 사용자 확정 범위를 우선 적용한다. 오류 주입은 필수 실습이 아니다.
- 600초는 10분 편성을 위한 설명 배분이다. 실제 낭독 시간은 촬영 전 강사가 확인하며 측정 완료로 기록하지 않는다.

## 기준의 정의 시점과 적용 시점 — 공식 자료 확인

- 정의: 작업 지침과 성공·검사 기준은 실행 전에 준비한다.
- 적용: 작업 기준은 작업 중, 품질 검토 기준은 각 단계의 결과 이후 다음 작업 배정 전에 사용한다. 프로젝트 전체가 끝난 후에만 검사하는 뜻이 아니다.
- 수업 순서: Ch03에서 작업 기준 준비 → Ch04에서 개별 작업 경험 → Ch05-01에서 단계별 품질 기준 정리·저장 → Ch05-02 통합 실행. 기준을 배우는 순서와 기준을 실제 적용하는 시점을 구분한다.
- [Anthropic: success criteria and evaluations](https://platform.claude.com/docs/en/test-and-evaluate/develop-tests): 성공 기준을 먼저 정의하고 평가를 설계한다. 수치 외 명확한 정성 척도도 가능하다.
- [Anthropic: prompt engineering overview](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/overview): 성공 기준과 검사 방법을 프롬프트 개선 전에 준비한다.
- [Anthropic: building effective agents](https://www.anthropic.com/engineering/building-effective-agents): 순차 파이프라인의 중간 결과를 검사하고 이후 처리를 진행한다.
- ‘작업 기준 / 품질 검토 기준’은 공식 문서를 우리 수업에 적용한 설명용 구분이다. 모든 종류의 평가·가드레일이 작업 후에만 실행된다는 주장이 아니다.

## 최신 정식 반영 — 문맥과 실제 검사 대상

4장은 시장 조사 노트에 있는 반려동물 소모품의 ‘트렌드: 상승’이라는 실제 기재를 보여주고, 출처 자료 대조와 해당 항목의 통과·보완 조건을 연결한다. 이는 문서에 적힌 내용을 검사하는 예이며 해당 시장 판단을 외부 근거로 검증했다는 뜻이 아니다. 근거 원문은 `../fastcampus-orca-course/project1-sidehustle-proposal/research-notes/market-research.md`의 2번 카테고리다. 출처 차트나 판정 근거를 만들어내지 않았다.

5~9장은 같은 프로젝트의 문서 이름과 검증 대상을 유지한다. 가상의 재고 조건 충돌, A/B 품목, 20·30·10·61만 원은 정식 화면에서 제거했다. 실제 기준의 세부 항목은 대본에서 설명한다. 이전 기존/현재 비교 파일은 보존했다.

## 3장 제목·강조·하단 문구 복원

제목은 ‘작업 기준과 품질 기준의 구분’. 제목·본문 모두 공통 단어 ‘기준’은 흰색, 다른 단어 ‘작업’은 brand, ‘품질’은 yellow로 강조한다. 하단은 직전 문구 ‘작업 기준과 품질 검토 기준은 모두 실행 전에 준비합니다.’로 복원한다. 작업 중/작업 후와 워커/코디네이터, 생성 이미지는 유지한다.

## 비교안 통합

동일 클립의 시장 조사·후보 선정 비교안을 정식 덱의 해당 위치에 통합했다. 현재 16장은 본편 12장과 비교안 4장이다. 사용자가 나중에 선택하며 채택을 임의 기록하지 않는다. 시장 조사 비교 6~8장, 후보 선정 비교 9~11장.

## 3장 하단 원문 재복원 · 제목 후보

사용자가 지칭한 이전 하단 문구는 ‘각 단계의 결과가 나온 뒤, 다음 작업을 배정하기 전에 검사합니다.’이다. 중간 수정본을 이전 버전으로 잘못 해석했던 것을 바로잡아 정식 화면에 이 원문을 복원했다. 제목은 사용자가 후보를 요청한 상태로 유지한다. 후보: 기준의 적용 목적(추천) / 기준의 용도 구분 / 기준의 유형. 제목 선택 전 본문의 작업 기준·품질 기준 의미를 바꾸지 않는다.
