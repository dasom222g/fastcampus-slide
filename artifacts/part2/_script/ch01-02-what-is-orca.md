## Orca는 어떤 도구인가 슬라이드 대본 (5장)

## 슬라이드 1/5 — Orca의 정체

이번에는 Orca가 어떤 도구인지 살펴볼 겁니다. 앞에서 여러 터미널에 에이전트를 띄웠을 때 사람이 중간에서 챙겨야 하는 일들을 봤는데요. 그 에이전트들이 일할 환경을 마련해 주는 도구가 Orca입니다.

Orca는 여러 에이전트가 일하는 작업 환경입니다. 왼쪽 그림을 보시면 에이전트 세 명이 한 사무실 안에서 각자 노트북으로 일하고 있습니다. 각자 맡은 일을 하는 자리가 있고, 뒤쪽 벽에는 전체 진행을 함께 보는 보드와 메시지를 주고받는 영역도 있고요.

사람이 사무실에서 일하려면 의자만 필요한 게 아니잖아요. 작업할 도구와 자료가 있어야 하고, 다른 사람이 어디까지 했는지 확인하고 내용을 전달할 수 있어야 합니다. 에이전트도 마찬가지입니다. 각자 일할 공간에 더해, 여러 작업의 상태를 보고 서로의 결과를 이어갈 환경이 필요합니다. 이 작업실 그림은 그 역할을 보여주는 비유입니다.

여기서 구분해서 보실 게 있습니다. 안에서 일을 하는 에이전트와, 에이전트가 일할 자리를 마련하는 환경은 역할이 다르죠. 그림에서 Orca에 해당하는 것은 로봇 한 명이 아니라, 그 로봇들이 들어 있는 작업 환경입니다.

이 구분을 실제 도구 이름에 연결해 보겠습니다.

## 슬라이드 2/5 — Orca 안에서 일하는 AI

앞에서 본 작업 환경 안에 어떤 에이전트를 연결하는지 보겠습니다. 테두리로 감싼 전체 공간이 Orca입니다. 여러 에이전트를 한곳에 두고 소통하게 하는 작업 공간인 거죠.

그 안에 에이전트 A와 B가 있습니다. A에는 Claude Code, B에는 Codex를 연결한 예시예요. 실제로 요청을 받아 작업하는 쪽은 이 에이전트들이고, Orca는 이들이 함께 일할 환경을 제공합니다.

각 에이전트 아래에는 ‘이미 쓰는 구독을 그대로 연결’이라고 적혀 있습니다. 기존에 쓰고 있던 Claude Code나 Codex를 연결하는 거예요. Orca를 쓰려고 새로운 AI 모델로 바꾸는 것이 아닙니다.

A와 B는 두 에이전트를 구분하는 이름입니다. 어떤 일을 맡길지는 우리가 정하고요. 연결선은 두 에이전트가 같은 공간에서 일한다는 뜻으로, A가 먼저 일하고 B에게 넘긴다는 순서를 나타내지는 않습니다.

이렇게 에이전트가 일할 환경을 따로 두면, 사람이 직접 코드를 작성하던 환경과는 사용하는 방식도 달라집니다. 다음 화면에서 그 차이를 보겠습니다.

## 슬라이드 3/5 — IDE와 ADE

왼쪽의 IDE는 Integrated Development Environment입니다. 사람이 직접 코드를 작성하는 개발 환경을 말해요. 그래서 사람 중심 환경이라고 적었고, 모니터 앞에 사람이 있는 그림을 넣었습니다. 파일을 열고, 내용을 작성하고, 실행하고, 저장하는 흐름이죠. 화면에 나온 순서도 사람이 직접 작업하는 과정을 보여줍니다.

오른쪽의 ADE는 Agent Development Environment입니다. 에이전트에게 일을 맡기고 결과를 검토하는 에이전트 중심 환경이죠. 이번에는 모니터 앞에서 일하는 주체가 에이전트입니다. 먼저 어떤 작업을 맡길지 정하고, 작업할 공간을 만든 다음, 에이전트를 실행하고, 나온 결과를 확인합니다.

달라지는 것은 프로그램 이름만이 아닙니다. 사람이 직접 파일을 작성하는 데서, 작업을 정하고 에이전트의 결과를 검토하는 쪽으로 하는 일이 옮겨가는 거예요. 작업 내용을 설명하고 어떤 결과를 원하는지 정하는 일은 여전히 필요합니다.

이 강의에서는 오른쪽처럼 에이전트에게 맡기는 방식으로 작업할 겁니다. 무엇을 맡길지 정하고 결과를 검토하는 일이 사람의 역할로 남는다는 점을 기억해 두시면 됩니다.

## 슬라이드 4/5 — Orca의 작업 단위

Orca의 기본적인 작업 단위는 워크트리입니다. 이름이 낯설지만, 여기서는 프로젝트 파일을 따로 꺼내 작업하는 폴더라고 이해하시면 됩니다.

그림처럼 실제 파일이 들어 있는 폴더예요. 에이전트는 이 워크트리 안에서 맡은 작업을 진행합니다. Orca에서는 이 폴더를 하나의 작업 공간으로 다루는 거죠.

이 폴더는 Git이 프로젝트의 선택한 버전에서 파일을 꺼내 준비해 줍니다. 그 원리는 다음 Git 파트에서 살펴보고, 지금은 ‘Orca는 워크트리라는 작업 폴더 단위로 일을 나눈다’는 점만 기억하시면 됩니다.

이렇게 일할 공간을 마련했으면, 그다음에는 여러 에이전트의 일을 어떻게 조율하는지 보겠습니다.

## 슬라이드 5/5 — 오케스트레이션까지

Orca에서는 여러 에이전트의 일을 하나의 흐름으로 구성할 수 있습니다. 이렇게 일을 나누고 진행을 살피고 결과를 모으는 것이 오케스트레이션입니다.

그림 왼쪽에는 목표가 하나 있고, 가운데에는 에이전트들이 있습니다. 목표에 필요한 일을 나누어 각 에이전트에게 맡기고, 작업이 어디까지 됐는지 확인한 다음 결과를 모으는 거예요.

에이전트를 여러 개 실행하는 데서 한 걸음 더 나아가는 겁니다. 각각 일을 시키는 것에 더해, 어떤 일을 맡기고 그 결과를 어떻게 모을지까지 흐름을 구성하는 거죠.

지금은 Orca에서 이런 협업 흐름도 구성할 수 있다는 점만 알아두시면 됩니다. 실제로 설정하고 실행하는 방법은 뒤의 실습에서 살펴보겠습니다.
