## Orca는 어떤 도구인가 슬라이드 대본 (5장)

## 슬라이드 1/5 — Orca는 어떤 도구인가 (표지)

그럼 Orca가 어떤 도구인지 볼게요.

먼저 오해하기 쉬운 게 하나 있는데, Orca는 에이전트가 아닙니다. 새로운 AI가 하나 더 생기는 게 아니에요. 여러 에이전트가 각자 일할 수 있게 자리를 마련해주는 작업 환경입니다.

비유하자면 에이전트들의 작업장인 거죠.

## 슬라이드 2/5 — Orca 안에서 일하는 AI

그럼 이 작업장 안에서 실제로 일하는 애들이 누구냐. 클로드 코드나 코덱스 같은 코딩 에이전트입니다. 일은 얘네가 하고, Orca는 얘네가 일할 공간만 제공해주는 거예요.

새로운 모델을 사는 게 아니라 이미 쓰는 에이전트를 연결하는 겁니다. 원래 쓰시던 걸 그대로 가져와서 붙이면 돼요. 저희 강의에서는 클로드 코드랑 코덱스를 메인으로 쓰지만, Gemini CLI나 Cursor CLI를 붙이셔도 됩니다.

그러니까 Orca 쓰려고 뭘 새로 결제하실 필요가 없습니다.

이렇게 에이전트가 일할 환경을 따로 만들어주면, 사람이 직접 코드 쓰던 환경이랑은 쓰는 방식 자체가 달라집니다.

## 슬라이드 3/5 — IDE와 ADE

Orca는 스스로를 ADE라고 소개하는데요. 기존에 쓰던 IDE랑 뭐가 다른지 보겠습니다.

IDE는 우리가 아는 VS Code나 인텔리제이 같은 코드 에디터입니다. 사람이 중심이 돼서 직접 파일 열고 코드 쓰고 실행하는 환경이죠. 그래서 화면 대부분을 코드가 차지합니다. 사람이 코드를 직접 읽고 고쳐야 하는 구조니까요.

반면에 ADE는 Agent Development Environment, 에이전트가 중심이 돼서 파일 만들고 코드 쓰는 환경입니다. 사람은 어떤 일을 맡길지 정하고 나온 결과를 검토하고요.

즉 에이전트용 코드 에디터라고 보시면 됩니다.

근데 여기서 중요하게, 사람이 할 일이 없어지는 게 아닙니다. 하는 일이 달라진 거예요. 직접 코드를 쓰던 일에서, AI에게 무엇을 맡기고 어떤 기준으로 판단할지 정해주는 일로 바뀐 거예요. AI 시대에는 이걸 얼마나 명확하게 정해주느냐가 곧 실력입니다.

## 슬라이드 4/5 — Orca의 작업 단위

그럼 에이전트들은 이 환경 안에서 어디서 일하느냐. Orca의 기본 작업 단위는 워크트리입니다.

이름이 낯설죠. 근데 어렵게 생각하실게 없는게, 프로젝트 폴더를 복사한 작업용 폴더라고 보시면 됩니다. 에이전트는 이 워크트리 안에서 맡은 작업을 합니다.

아까 터미널 여러 개 쓸 때 셋이 같은 폴더에서 일해서 파일이 덮어써진다고 했잖아요. Orca는 이 워크트리 단위로 작업 공간을 나눠주는 겁니다.

워크트리는 원래 Git에서 나오는 개념인데, 이건 다음 파트에서 자세히 보겠습니다. 지금은 Orca의 기본 작업 단위가 워크트리라는 것만 기억하시면 충분합니다.

## 슬라이드 5/5 — 오케스트레이션까지

일할 공간까지 마련했으면, 그다음은 여러 에이전트의 일을 어떻게 조율하느냐를 봐야겠죠.

각자 워크트리를 받아서 자기 자리에서 일하는 것까지는 됐는데, 이것만으로는 부족합니다. 자기 폴더에서 일할 뿐이지 서로 소통을 못 하거든요. 일을 나누고 결과를 다음 에이전트한테 넘기는 건 여전히 사람이 해야 합니다.

근데 이 소통을 가능하게 해주는 게 Orca의 오케스트레이션입니다. 목표 하나를 던지면 필요한 일을 쪼개서 각 에이전트한테 배정하고, 진행을 확인하고, 결과를 모아주는 거죠.

지금은 Orca에서 이런 것까지 된다 정도만 알아두시면 충분합니다. 오케스트레이션은 뒤에서 자세히 다룰 건데, 우리가 만들 프로젝트의 핵심이라 앞으로 계속 쓰게 되실 거예요.

그러면 이제 Orca 설치하고 직접 써볼 건데, 그 전에 뭐가 필요한지부터 보고 갈게요.
