## 터미널 여러 개의 문제 슬라이드 대본 (5장) - 클로드

## 슬라이드 1/5 — 터미널 여러 개의 문제 (표지)

앞에서 멀티에이전트가 필요한 이유를 봤죠. 그럼 실제로 에이전트를 여러 개 띄우면 어떻게 되는지 보겠습니다.

하나 쓸 때는 창 하나만 보고 있으면 됐는데, 여러 개가 되면 화면이 이렇게 바뀝니다. 창은 늘었는데 각 창에서 뭐가 벌어지는지는 여전히 내가 확인해야 하거든요.

에이전트를 늘릴수록 사람이 챙길 일도 같이 늘어나는 겁니다. 왜 그렇게 되는지부터 보겠습니다.

## 슬라이드 2/5 — 에이전트가 일하는 자리

에이전트가 일하는 자리가 터미널입니다. 명령을 넣고 실행되는 내용을 보는 창이라고 생각하시면 돼요. 바깥 창이 터미널이고 그 안에서 일하는 쪽이 에이전트인 거죠.

여기서 중요한 게 하나 있습니다. 터미널 하나에 에이전트 하나입니다. 이 구조는 예전이나 지금이나 같아요.

그러니까 에이전트를 더 쓰려면 터미널부터 더 열어야 하는 겁니다.

## 슬라이드 3/5 — 멀티 에이전트를 쓰려면

셋을 쓰고 싶으면 터미널도 셋을 엽니다. 창마다 에이전트가 하나씩 붙는 거죠.

창을 늘리는 것 자체는 어렵지 않습니다. 각 창에 할 일을 주면 각자 시작해요. 여기까지는 그냥 창이 늘어난 것뿐입니다.

문제는 일을 맡긴 다음입니다. 얘네가 일하는 동안 내가 이 세 창을 어떻게 보고 있을 거냐가 남아 있거든요.

## 슬라이드 4/5 — 터미널 여러 개의 문제

첫 번째는 어디까지 됐는지 모른다는 겁니다. 첫 번째 창 보고 돌아왔더니 두 번째 창이 뭘 하고 있었는지 놓쳐요. 끝난 건지, 멈춘 건지, 나한테 뭘 물어보는 중인지 알려면 창을 하나씩 열어봐야 합니다.

두 번째는 서로 덮어쓴다는 겁니다. 셋이 같은 폴더에서 일하면 같은 파일을 동시에 건드릴 수 있거든요. 한 에이전트가 고쳐놓은 걸 다른 에이전트가 수정하면서 지워버립니다. 창이 나뉘었다고 파일까지 나뉜 건 아닌 거죠.

세 번째는 비교입니다. 같은 일을 셋에게 맡겨도 결과가 각 창에 흩어져 있어요. 한 화면에서 나란히 못 보니까 이 창 봤다가 저 창 갔다가, 결국 기억으로 맞추게 됩니다.

## 슬라이드 5/5 — 무엇이 필요한가

그럼 뭐가 있어야 하냐. 방금 본 세 가지가 그대로 답이 됩니다.

상태를 모르는 게 문제였으니까 여러 에이전트 상태를 한 화면에 놓고 봐야겠죠. 창을 하나씩 오가지 않고 누가 작업 중이고 누가 끝났고 누가 내 승인을 기다리는지 한 번에 아는 겁니다.

상태도 구분이 돼야 합니다. 초록 체크는 완료, 노란 진행 표시는 작업 중, 주황 물음표는 사람 승인을 기다리는 중이에요. 이렇게 갈라놔야 어디를 손봐야 할지 바로 보이거든요.

파일을 덮어쓰는 게 문제였으면 작업 공간을 나눠야 합니다. 에이전트마다 독립된 폴더에서 일하게 하는 거죠. 결과가 흩어지는 게 문제였으면 나란히 놓고 비교할 수 있어야 하고요.
