# Ch02-03. 화면 구조와 보드 읽는 법

제작 목표: 처음 켠 화면에서 무엇을 보고 무엇을 눌러야 하는지 길을 잡아준다

> **이 클립은 화면을 가르친다.** 화면에 실제로 보이는 이름을 그대로 쓴다. 임의로 바꾸지 않는다.
> 실제 화면 캡처는 영상에서 보여주므로, 슬라이드는 **화면의 구조(어디에 무엇이 있는가)**를 도식으로 다룬다.

#### 1. 화면은 세 덩어리다

역할: 처음 켠 사람이 길을 잃지 않게 큰 덩어리부터 나눈다.

말할 내용

- **왼쪽** — 작업 공간 목록. 지금 무엇들이 돌고 있는지
- **가운데** — 선택한 작업의 내용과 에이전트 터미널
- **오른쪽/아래** — 변경된 파일과 결과 검토

슬라이드: 1장 — 3분할 도식

#### 2. 작업 단위가 곧 공간이다

역할: Orca의 핵심 모델. Part 3(워크트리)의 바닥을 여기서 깐다.

말할 내용

- Orca에서 일 하나를 시작하면 그 일만을 위한 **작업 공간**이 생긴다.
- 공간마다 파일이 따로 있어서 다른 일이 건드리지 않는다.
- 그래서 여러 에이전트를 동시에 돌려도 서로 덮어쓰지 않는다.
- 이 공간의 정체가 무엇인지는 Part 3에서 다룬다.

슬라이드: 1장

#### 3. 보드에서 읽어야 할 것

역할: 상태를 읽는 법.

말할 내용

- 각 작업이 **지금 무엇을 기다리는지**가 상태로 표시된다.
- 사람이 봐야 하는 건 두 가지다 — 내 결정을 기다리는 것, 막혀 있는 것.
- 나머지는 굴러가는 중이니 들여다보지 않아도 된다.

슬라이드: 2장 — 상태 흐름 1장 + 사람이 볼 것 1장

#### 4. 결과를 검토하는 자리

역할: 사람의 역할이 어디인지 못 박는다.

말할 내용

- 에이전트가 끝내면 **바뀐 파일**을 보여준다. 사람은 그걸 보고 받아들일지 정한다.
- 이게 Part 1에서 말한 "사람은 목표와 최종 결정만"의 실제 자리다.

슬라이드: 1장

#### 5. 처음엔 이것만 기억한다

역할: 정보 과부하 방지.

말할 내용

- 작업을 만들면 공간이 생기고, 에이전트가 돌고, 결과를 내가 확인한다. 이 한 줄이면 시작할 수 있다.

슬라이드: 1장 — 마무리 선언
