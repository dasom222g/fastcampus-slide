# Ch01-01. 터미널 여러 개의 문제 (6분) · 슬라이드 5장

제작 목표: Orca를 소개하기 전에 그 도구가 왜 필요한지 문제부터 만든다

#### 슬라이드 1 · 표지

> 터미널 여러 개의 문제

부제: 에이전트를 늘릴수록, 사람이 챙겨야 할 작업도 늘어납니다.

이미지: 중앙에서 어지러워하는 남자 주위에 여러 터미널이 둘러선 화면 (`cover.png`)

#### 슬라이드 2 · 에이전트 하나에 터미널 하나

상단: 에이전트가 일하는 자리

역할: 터미널이라는 말이 여기서 처음 나온다. 왜 나오는지부터 설명한다.

말할 내용

- 에이전트는 터미널에서 돌아갑니다. 터미널 하나에 에이전트 하나가 돌아가는 구조는 예전이나 지금이나 같습니다.
- 그래서 에이전트를 늘리면 터미널도 늘어납니다.

슬라이드 내용: 터미널 한 개와 에이전트 한 개가 짝지어진 그림 1장

#### 슬라이드 3 · 그래서 창이 늘어난다

상단: 멀티 에이전트를 쓰려면

역할: 앞의 제약이 만드는 결과를 보여준다.

말할 내용

- 에이전트를 세 개 쓰고 싶으면 터미널을 세 개 열어야 합니다.
- 여기까지는 그냥 창이 늘어난 것뿐입니다. 문제는 그다음입니다.

슬라이드 내용: 터미널 세 개에 에이전트 세 개가 각각 붙은 그림 1장

#### 슬라이드 4 · 창이 늘어나면 생기는 일

상단: 터미널 여러 개의 문제

역할: 이 클립의 핵심. 문제 세 가지를 명확히 짚는다.

말할 내용

- **어디까지 됐는지 모릅니다** — 창을 오가다 보면 두 번째 창이 뭘 하고 있었는지 놓칩니다. 끝났는지, 멈췄는지, 뭘 물어보고 있는지 하나씩 열어봐야 압니다.
- **서로 덮어씁니다** — 세 에이전트가 같은 폴더에서 일하면 같은 파일을 동시에 건드립니다. 하나가 고친 걸 다른 하나가 지웁니다.
- **비교가 안 됩니다** — 같은 일을 셋에게 시켜도 결과를 나란히 볼 수가 없습니다. 창을 오가며 눈으로 맞춰야 합니다.

슬라이드 내용: 문제 3가지 1장

#### 슬라이드 5 · 그래서 필요한 것

상단: 무엇이 필요한가

역할: 문제를 요구사항으로 바꾸고 다음 클립으로 넘긴다.

말할 내용

- 정리하면 세 가지가 필요합니다. 진행 상황을 한눈에 보는 것, 작업 공간을 나누는 것, 결과를 나란히 비교하는 것.
- 완료·작업 중·승인 대기를 서로 다른 색과 기호로 구분해 보여줍니다.
- 이걸 가능하게 하는 도구가 Orca입니다. 다음 영상에서 봅니다.

슬라이드 내용: 필요한 것 3가지와 “이걸 가능하게 하는 도구, Orca” 한 줄. 상태는 초록 체크(완료), 노랑 진행 링(작업 중), 주황 물음표 말풍선(승인 대기).

### 5장 상태 설명 보완

진행 상황을 한눈에 볼 수 있다는 핵심을 “여러 에이전트 상태를 한 화면에”으로 표시한다. 완료·작업 중·승인 대기의 구분은 도식의 색과 기호로 보여준다.

## 5장 상태 도식 — 하나의 창 (2026-09-08)

에이전트 세 명과 완료·작업 중·승인 대기 표시를 하나의 터미널 창 안에 배치한다. 무채색 창 외곽과 상단 바·창 조작점으로 하나의 작업 화면임을 보여준다. “여러 에이전트 상태를 한 화면에” 문구와 나머지 두 도식은 유지한다.
