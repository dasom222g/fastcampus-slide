## 슬라이드 2/6 — Orca 안에서 일하는 AI

메시지: Orca는 여러 에이전트가 함께 일하고 소통하는 작업 공간이며 기존 구독의 에이전트를 연결한다.
타입: 상단 Orca → 하단 에이전트 A/B의 관계 도식. 전체를 회색 테두리 하나로 감싸 작업 공간의 경계를 표시한다. 내부 에이전트별 카드 박스는 없음.
상단 헤더·부제 유지. 본문 상단: Orca 로고 / Orca / 여러 에이전트를 한곳에 두고 소통하게 하는 작업 공간.
하단 두 열: Claude Code 로고 / 에이전트 A / Claude Code / 이미 쓰는 구독을 그대로 연결. Codex 로고 / 에이전트 B / Codex / 이미 쓰는 구독을 그대로 연결.
회색 연결선은 같은 환경에 연결된 두 에이전트를 표현하며 전달 순서의 화살표가 아니다.
중앙 묶음 최대 폭 72rem, 외곽 여백과 두 열 간격 확보. 글자 크기는 기존 공통 규격 유지, 연결선 길이와 주변 여백만 조정한다.
애니메이션: Orca → 연결선 → 에이전트 A·B.
주의: 반복된 업무 설명만 줄인다. 작업 공간의 의미와 기존 구독 연결이라는 핵심 설명을 함께 지우지 않는다.

## 슬라이드 3/6 — 기존 도구의 한계를 깬 도구

타입: TRANSITION_COMPARE. 기존 방식과 Orca의 운영 전제를 좌우로 대비한다.
부제: 에이전트 하나와 일하던 방식에서, 여러 에이전트의 동시 실행이 기본값으로 바뀝니다.
왼쪽: 기존 / 에디터 하나 · 에이전트 하나 / 에디터 한 개 안의 에이전트 한 명과 기다리는 작업들 / 한 에이전트에게 하나씩 맡기고 / 끝나면 확인하고 다음 작업.
오른쪽: Orca / 여러 에이전트가 기본값 / 하나의 앱 창 안에 같은 창에 나란히 배치한 에이전트 세 명 / 여러 에이전트에게 동시에 맡기고 / 한곳에서 실행하고 관리.
가운데: 전환 화살표. 두 영역의 제목·도식·설명은 같은 높이에 맞춘다. 패널 전체를 장식 박스로 감싸지 않는다. 앱 창 테두리만 남긴다. 개별 폴더·공간 구획을 그리지 않는다.
타이포: 기존 2장 항목 제목과 본문 규격. Orca 이름은 브랜드 강조색. 세 에이전트는 브랜드·보라·회색. 양쪽 에이전트 크기는 동일하다.
애니메이션: 기존 제목 → 창 → 에이전트와 대기 작업 → 설명 → 전환 → Orca 제목 → 앱 경계 → 세 에이전트 동시 등장 → 설명. 경계와 내부를 각각 애니메이션하며 부모 전체를 움직이지 않는다.
정확성: ‘기존 도구는 여러 에이전트를 실행할 수 없다’고 단정하지 않는다. 한 에이전트에게 차례로 맡기던 사용 방식과 멀티 에이전트 운영을 갖춘 Orca를 비교한다. tmux·VS Code 터미널에서도 여러 에이전트를 실행할 수 있다는 보충은 대본으로 설명한다. 설치만으로 작업 배정·협업이 자동화된다고 설명하지 않는다.
위치: 실행 에이전트를 소개한 뒤, IDE/ADE 구분 전에 배치해 Orca를 쓰는 이유를 먼저 설명한다.

핵심 구분: 이 장은 워크트리 분리를 설명하지 않는다. 기존의 한 에이전트 사용 방식과 여러 에이전트 동시 실행이 기본값인 Orca를 대비한다. 에이전트들이 같은 작업 공간에서도 실행될 수 있으므로 1인 1폴더를 필수처럼 표현하지 않는다.

## 슬라이드 5/6 — Orca의 작업 단위

핵심 메시지: Orca의 기본적인 작업 단위는 워크트리다.
헤더: Orca의 작업 단위.
부제: Orca는 워크트리 단위로 작업을 나눕니다.
타입: SCENE_PAIR. 왼쪽 큰 폴더 도식, 오른쪽 용어와 짧은 정의. 프로젝트→워크트리 계층과 터미널 도식은 제거한다.
왼쪽: 프로젝트 파일 세 개가 담긴 물리적인 폴더 한 개. 폴더가 실제 파일을 두고 작업하는 자리임을 보여준다.
오른쪽: 워크트리 / 프로젝트 파일을 따로 꺼내 / 작업하는 폴더.
보조 설명: 에이전트는 이 워크트리 안에서 작업합니다.
정확성: 단순 빈 폴더나 프로젝트를 완전히 복제한 별개 저장소로 설명하지 않는다. Git이 선택한 버전의 파일을 실제 작업 폴더에 준비한다는 배경은 대본 한 문장에만 둔다.
범위: 버전·브랜치·명령·병합·터미널 개수는 이 장에서 다루지 않는다. Git 파트로 넘긴다.
애니메이션: 폴더 → 용어와 정의. 타이포는 같은 역할의 템플릿 statement/copy 규격.

## 슬라이드 6/6 — 오케스트레이션까지

메시지: 여러 에이전트에게 일을 나누고 결과를 모으는 흐름을 구성한다.
헤더: 오케스트레이션까지.
부제: 여러 에이전트에게 일을 나누고 결과를 모읍니다.
타입: 열린 분배·취합 흐름. 왼쪽 하나의 목표 → 가운데 에이전트 A/B/C → 오른쪽 모인 결과.
목표는 과녁, 에이전트는 같은 로봇 아이콘 세 개, 모인 결과는 문서 묶음으로 표현한다.
중앙 세 에이전트는 세로로 같은 간격. 목표에서 세 갈래로 나뉘고 결과 쪽으로 모이는 연결선만 사용한다. 선과 주체는 brand/purple/gray로 이어진다.
하단: 작업 배정 · 진행 확인 · 결과 취합. 테두리와 배경 없음.
조율 에이전트·스킬 이름·환경 외곽 박스·왕복 보고선은 제거한다. 설치만으로 자동 협업이 된다는 주장도 하지 않는다.
구체적인 스킬 설정과 실행 방법은 실습 파트에서 다룬다.
애니메이션: 목표 → 분배선 → 에이전트들 → 취합선 → 결과 → 요약.
