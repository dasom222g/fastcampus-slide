## 용어 규칙

이 클립은 **화면을 가르친다.** 화면에 실제로 보이는 이름은 영상 캡처에서 확인하고,
슬라이드는 **위치와 구조**만 다룬다. 소스에 없는 UI 이름·메뉴명·수치는 쓰지 않는다.

| 이 덱에서 쓰는 말 | 무엇을 가리키나 | 쓰지 않는 말 |
|---|---|---|
| 왼쪽 · 가운데 · 오른쪽·아래 | 화면의 세 덩어리를 **위치로만** 부른다 | 사이드바, 패널, 보드 컬럼 이름 등 확인되지 않은 UI 명칭 |
| 작업 | 사람이 시키는 일 하나 | 카드, 티켓, 잡(job) |
| 작업 공간 | 작업 하나에 딸린, 파일이 따로 있는 공간 | worktree(정체는 Part 3에서 다룬다), 워크스페이스 |
| 에이전트 | 작업 공간 안에서 실제로 일하는 쪽 | 봇, AI |
| 상태 | 그 작업이 지금 무엇을 기다리는지 | 스테이터스 이름 목록(소스에 없다) |

- **소스에 없는 고유명사를 쓰지 않는다.** 상태 이름·메뉴 이름·버튼 이름을 한 개도 쓰지 않았다
- `worktree`라는 말은 이 덱에 **넣지 않는다.** 소스가 "이 공간의 정체가 무엇인지는 Part 3에서 다룬다"고 못 박았다
- 화면 구조는 이미지가 아니라 **인라인 SVG 도식**(`.ui-map`)으로 그린다. 생성 이미지는 한글 라벨을 뭉갠다

**버릴 내용**

- 실제 화면 캡처 — 영상에서 보여준다. 슬라이드는 **구조**만 다룬다 (소스 지시)
- 작업 공간의 정체(Git·worktree) — 소스가 Part 3의 몫이라고 명시했다
- 상태 이름 목록 — 소스에 이름이 하나도 없다. 지어내지 않고 "무엇을 기다리는가"로만 다룬다
- 메뉴·버튼·단축키 — 소스에 없다. 조작은 영상에서 다룬다

**감수한 것**

- 표지를 따로 두지 않았다. 골든셋의 "제품·기능 덱은 사용자가 보는 장면에서 시작한다"를 따라 1번을 화면 구조로 열었다 (Part 1의 두 덱도 표지 없이 연다)

## 이번 덱 전용 시각 장치

박스 격자를 새로 만들지 않았다. 아래 둘만 추가한다.

| 클래스 | 무엇을 그리는가 | 왜 기존 타입으로 안 되나 |
|---|---|---|
| `.ui-map` (인라인 SVG) | **화면 안에서의 위치.** 창 하나를 축소해 그리고, 그 슬라이드가 말하는 자리 하나만 색으로 켠다. 1번은 세로 3분할 중 한 칸을, 4번은 목록 줄 여러 개 중 한 줄을 켠다 | 위치는 카드로 말할 수 없다. "왼쪽"이라고 쓰는 것과 왼쪽 칸이 켜진 그림을 보는 것은 다르다. 1번과 4번이 **같은 창 그림**을 쓰기 때문에 4번이 "왼쪽 목록 안의 한 줄"이라는 게 말 없이 읽힌다 |
| `.vs-col--waiting` · `.vs-badge--waiting` | 기존 `vs-col`·`vs-badge`의 **yellow 색 변형**. 템플릿에 brand(pass)·orange(blocked)만 있어 "내 결정을 기다림 = yellow"를 표현할 색이 없다 | 새 레이아웃이 아니라 이미 있는 장치의 빠진 색 한 칸이다. 구조·간격·타이포는 그대로 쓴다 |

`.split-list`(2번 오른쪽 나열의 세로 간격만 좁힌다)는 크기 조정용 국소 modifier다.
