## 2. 모바일 접속 구조

- 질문: 모바일에서 새 작업을 시키면 어디서 실행되는가?
- 헤드메시지: 컴퓨터와 모바일에서 보낸 요청과 대화는 같은 세션에 반영됩니다.
- 구조: 컴퓨터 ↔ 모바일의 양방향 연결. 가운데 ‘같은 세션 / 요청·대화 동기화’를 표시한다. 컴퓨터에는 파일·터미널·에이전트, 모바일에는 작업 지시·확인·응답을 배치한다.

## 3. 상태에 따른 행동

- 질문: 상태 표시를 본 뒤 무엇을 확인하는가?
- 헤드메시지: 세션의 상태 표시를 보고 진행 보고·질문·결과물을 확인합니다.
- 구조: 네 상태의 열린 4열. 작업 중은 노랑, 응답 대기는 주황, 완료는 초록으로 강의 도식 색을 통일한다. 모바일 UI의 표시 색을 강의 도식에 그대로 적용하지 않는다. 사용자 요청으로 중단·오류 / 마지막 메시지 확인을 4번째 항목에 유지한다. 아이콘은 기존 진행 링·물음표 말풍선·체크·느낌표를 사용하고 중단·오류는 빨강으로 표시한다.
- 본문: 작업 중 → 진행 보고 읽기 / 응답 대기 → 질문을 읽고 답하기 / 완료 → 완료 보고·결과물 확인.
- 하단: 완료 표시만 보지 말고 보고에 적힌 결과물도 확인합니다.
- 근거: Step 3 작업 상태 보기의 상태 표 및 직후 문장.

## 4. 모바일에서 할 수 있는 일

- 질문: 모바일에서 어떤 행동을 할 수 있는가?
- 헤드메시지: 모바일에서 진행 상황을 확인하고 질문에 답하며 새 작업을 지시할 수 있습니다.
- 구조: 순서가 아닌 세 가지 행동을 열린 3열로 나란히 배치한다. 연결 화살표는 사용하지 않는다. 진행 확인은 노랑, 질문에 응답은 주황, 새 작업 지시는 빨강으로 구분한다.
- 본문: 진행 확인 / 최근 대화·진행 보고, 질문에 응답 / 선택·작업 방향 전달, 새 작업 지시 / 새 에이전트에게 작업 요청.
- 하단: 요청이나 답변을 보낸 뒤 실제로 반영됐는지 확인합니다.
- 근거: 실습자료 Step 3의 작업 상태 보기·질문에 답하기·모바일에서 새 작업 시키기.

## 5. 어디서든 작업 지시

- 질문: 모바일로 에이전트에게 일을 시키면 무엇이 달라지는가?
- 헤드메시지: 컴퓨터 앞에 있지 않아도 모바일로 에이전트에게 일을 맡기고 진행을 확인할 수 있습니다.
- 구조: 모바일로 요청하는 사람 → 연결된 컴퓨터에서 일하는 에이전트 팀. 두 장소의 주체를 큰 그림으로 표현한다. 기능 목록이나 접속 절차를 반복하지 않는다.
- 핵심: 사람의 위치와 관계없이 에이전트에게 일을 맡길 수 있다. 컴퓨터의 실행 조건은 2장에서 설명한다.
- 등장: 모바일로 요청하는 사람 → 요청 화살표 → 컴퓨터에서 실행하는 팀 → 하단 마무리.
- 하단: 이제 어디서든 에이전트에게 일을 시킬 수 있습니다.

## 추가 수정 · 상태 재현과 양방향 세션

- 데스크톱 Orca에서 명령 오류·실패 보고·사용자 중단을 재현했다. Interrupted는 빨강으로 표시되며, 명령 오류와 세션 표시가 항상 일치하는 것은 아니다. 모바일 앱의 중단 표시까지 재현한 것은 아니다.
- 최신 사용자 확정: 기존 4종 아이콘 유지. 4번째 항목은 정확히 **중단·오류 / 마지막 메시지 확인**, 빨강.
- 장소 비유 대신 모바일·컴퓨터와 실제 동작을 직접 명시한다.
- 2장은 양쪽 요청·대화가 같은 세션에 반영되는 관계를 실선 화살표 두 개로 표현한다. 실행은 컴퓨터에 유지된다.

- 최신 시각 조정: 표지 기기 아이콘 약 1.5배 확대. 컴퓨터 도식(2·5장)과 컴퓨터 발신 선은 기존 팔레트의 초록 `--green: #4ade80`. 모바일과 모바일 발신 선은 보라색. 표지는 생성 이미지.
