## 쓰는 법

- **피드백은 차수로 쌓는다.** 새 피드백은 파일을 새로 만들지 말고 **이 파일 아래에 `## N차`를 추가**한다. 한 산출물의 이력이 한 파일에 모여 있어야 골든셋 단계에서 전체를 훑을 수 있다
- 반영이 끝난 차수는 제목에 `— 반영완료`를 붙이고, 그 아래 **반영 결과**를 짧게 남긴다. 무엇을 못 했는지도 적는다
- `## 3. 다음부터 이렇게 해`와 `## 4. 골든셋`은 **차수와 무관하게 파일 맨 아래 하나만** 둔다. 차수마다 반복하지 않는다

## 2차 (2026-10-13) — 반영완료

### 1. 전체

- 사용자 요청으로 기존 5장 “판단에 필요한 맥락” 삭제. “책상 안과 밖”을 5장으로 이동하여 총 5장. 소스·스토리보드·목록·제작 현황의 장수 갱신.

### 2. 개별

#### 슬라이드 4 — 승인 응답의 흐름

- 원인: 요청·판단·후속 진행만 등장 대상으로 지정되어, 화살표 두 개는 진입 즉시 보였음.
- 수정: 요청 확인 → 첫 화살표 → 사람의 판단 → 둘째 화살표 → 후속 진행을 명시적 단계 0~4로 지정. 기존 150ms 시작·260ms 간격과 fade 규칙 적용.
- 검수: 1920×1080·1280×800에서 시작·800ms·종료 프레임 확인. 첫 진입과 5장→4장 재진입 모두 화살표가 처음에는 숨겨지고 순서대로 등장함. 탐색점 5개와 마지막 장 연결 확인.

## 3차 (2026-10-13 공통 피드백 재점검) — 반영완료

### 1. 전체

- 본문 중앙 배치·짧은 연결선·아이콘 중심 정렬·제목 강조 한 곳·위치 고정 페이드를 적용했다. 소스와 스토리보드는 현재 화면에 맞췄다. 기존 승인 상태와 대본은 유지한다.
- 회고·재발 방지: `docs/slide-style-handoff.md`의 2026-10-13 항목. 최신 해당 파트 실습자료와 앞선 승인 화면을 대조했다.

### 2. 개별

#### 슬라이드 1 — 모바일의 역할

- 컴퓨터 실행→상태 보고→모바일 확인→지시·응답을 순차 표시한다. 부모와 자식의 중복 등장 제거.

#### 슬라이드 2 — 모바일 접속 구조

- ‘모바일 접속 구조’로 제목을 구체화하고 연결된 컴퓨터에서 실행된다는 헤드 메시지를 반영했다. 컴퓨터 Orca·네트워크 유지 조건을 하단에 배치했다.

#### 슬라이드 3 — 상태에 따른 행동

- 작업 중·응답 대기·완료·중단/오류의 네 상태를 색과 아이콘으로 구별하고 상태별 행동을 대응시켰다.

#### 슬라이드 4 — 승인 응답의 흐름

- 질문에는 방향을 답하고 권한 요청에는 허용·거절을 선택하도록 구분했다. 요청 확인→사람의 응답→후속 확인의 아이콘 중심에 짧은 직선 화살표를 배치하고 노드·선의 등장 단계를 지정했다.

#### 슬라이드 5 — 책상 안과 밖

- 컴퓨터의 준비·상세 검토와 모바일의 진행 확인·응답을 구분했다. 제거된 ‘판단에 필요한 맥락’ 장은 복원하지 않고 전체 카운터를 5장으로 맞췄다.

### 검수

- 5장 전체를 1920×1080·1280×800에서 렌더링하고 캡처를 검토했다. 본문 넘침·검사 대상 선/텍스트 겹침·누락 SVG·이미지 오류 없음.
- 실제 진입·중간 프레임·재진입에서 순서와 위치 고정을 확인했다. 중첩 애니메이션 없음. 모션 감소 설정에서 모든 본문 요소가 표시된다.
- 키보드 앞/뒤/스페이스·빠른 연속 입력·본문 클릭·카운터를 검증했다. 도식의 리사이즈 후 재계산도 확인했다.
- 공통 QA 상세: `artifacts/_maintenance/feedback-review-2026-10-13.md`. 캡처: 해당 파트 `_qa/feedback-final-{1920|1280}-*.png`.
- 자체 수정·브라우저 검수 완료. 사용자 최종 승인은 별도이며 확정 상태로 승격하지 않았다.

## 추가 피드백 — 반영완료

- 기존 진행 링·물음표 말풍선·체크·느낌표 아이콘으로 통일했다. 4개 항목은 작업 중(노랑), 응답 대기(주황), 완료(초록), 중단·오류(빨강)다.
- 4번째 항목의 문구는 사용자 지정대로 ‘중단·오류 / 마지막 메시지 확인’을 사용한다. 상태 재현의 정확한 결과와 한계는 `_qa/status-reproduction-2026-10-14/findings.md`에 기록했다.
- 2장은 컴퓨터와 모바일이 같은 세션을 공유하며 요청·대화가 양방향으로 반영되는 도식으로 수정했다.
- 원본·비교안의 장소 비유를 직접적인 기기·기능 표현으로 변경했다. 표지 선언은 ‘모바일로 / 작업 지시·확인’, 마지막 장 제목은 ‘컴퓨터와 모바일에서 작업 이어가기’다.
- 사용자 요청으로 컴퓨터 유즈 세션을 종료했다. 이후 HTML 검수는 브라우저 자동화로만 진행했다.

### 2장 추가 조정 — 반영 완료

- 컴퓨터·모바일 아이콘을 기존 대비 약 1.6배 확대. 이 장에만 적용.
- ‘같은 세션’은 일반 설명과 같은 `.copy` 스타일로 통일.
- 컴퓨터 설명을 ‘파일·터미널·에이전트’로 복원.
- 하단 문구를 ‘연결된 컴퓨터의 Orca와 네트워크가 켜져 있어야 합니다.’로 복원.
- 1920×1080 및 1280×800 브라우저 검수: 잘림·겹침 없음.

### 표지 크기·컴퓨터 색상 — 반영 완료

- 표지 컴퓨터·모바일 아이콘을 약 1.5배 확대.
- 실행 기기인 컴퓨터를 파란색(#58a6ff)으로 변경하고 1·2·5장의 동일 대상과 컴퓨터 발신 화살표에 통일. 모바일은 기존 보라색 유지.
- 1920×1080 및 1280×800에서 1·2·5장 잘림·겹침 없음.

## 최신 구성 — 4장

#### 슬라이드 1 — 모바일의 역할

- 컴퓨터 색상은 채도를 낮춘 블루그레이로 변경. 확대된 아이콘 유지.

#### 슬라이드 2 — 모바일 접속 구조

- 컴퓨터 색상을 표지와 통일.

#### 슬라이드 3 — 상태에 따른 행동

- 기존 구성 유지.

#### 슬라이드 4 — 모바일에서 할 일

- 진행 확인·질문에 응답·새 작업 지시를 순서 없는 열린 3열로 구성.
- 기존 5장은 동기화 설명과 중복되어 삭제. 기기 이동 과정은 실습에서 다룸.
- 전체 4장과 탐색 점·전체 장수 일치. 1920×1080 및 1280×800에서 잘림·겹침 없음. 4장 재진입 등장 순서 0~3 검증 완료.

- 추가 확정: 컴퓨터와 발신 선은 원래 `tone-gray`로 복원. 클립명 변경에 따른 구성 조정은 검토 후 별도 반영.

## 추가 피드백 — 마무리 장과 행동 표현

#### 슬라이드 4 — 모바일에서 할 수 있는 일

- ‘할 일’을 ‘할 수 있는 일’로 수정. 진행 확인은 노랑, 질문에 응답은 주황, 새 작업 지시는 빨강.

#### 슬라이드 5 — 어디서든 작업 지시

- 마무리 장 추가. 컴퓨터 앞에 있지 않아도 모바일로 일을 맡길 수 있다는 메시지.
- 모바일로 요청하는 사람 → 연결된 컴퓨터에서 실행하는 에이전트 팀.
- 전체 5장 및 탐색 점·장수 일치. 1920×1080과 1280×800에서 수정된 두 장의 잘림·겹침 없음.

## 표지 이미지·마무리 문구 — 반영 완료

- 표지: 템플릿의 왼쪽 선언·오른쪽 생성 이미지. 야외에서 모바일로 일을 시키는 사람과 별도 컴퓨터에서 문서 작업을 하는 팀.
- 클립명을 ‘Orca 모바일로 어디서나 에이전트에게 일 시키기’로 반영. 제목은 ‘어디서나’에 키컬러.
- 마무리 하단: ‘이제 어디서든 에이전트에게 일을 시킬 수 있습니다.’
