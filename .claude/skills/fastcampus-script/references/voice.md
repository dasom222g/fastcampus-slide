# 말투와 문장

강사의 말투는 **설명하는 사람의 구어체**다. 발표문도 아니고 블로그 글도 아니다. 판단 기준은 하나 — 소리 내어 읽었을 때 어색한가.

---

## 어미를 돌린다

같은 어미로 문장이 연달아 끝나면 낭독 티가 난다. 아래를 섞어 쓴다.

| 어미 | 쓰는 자리 |
|---|---|
| `~할 겁니다` / `~볼게요` / `~보겠습니다` | 앞으로 할 일을 예고 |
| `~인데요` / `~한데` | 문장을 다음으로 이어붙일 때 |
| `~거든요` | 이유를 댈 때. 이 대본의 주력 어미다 |
| `~잖아요` | 수강생이 이미 안다고 전제할 때 |
| `~겠죠` / `~겠습니다` | 동의를 구하며 넘길 때 |
| `~인 거죠` / `~한 거예요` | 앞 설명을 정리해 못 박을 때 |
| `~보시면 됩니다` / `~봐주시면 돼요` | 비유나 이해 방식을 제안할 때 |

**같은 어미 3연속이 신호다.** 특히 `~습니다`만 이어지면 읽는 글이 되고, `~거든요`만 이어지면 변명처럼 들린다.

문장 길이도 섞는다. 긴 설명 문장 뒤에 짧은 문장 하나를 놓으면 호흡이 산다.

> 겉으로는 합의가 잘 된 것처럼 보이는데, 합의가 됐다고 해서 결과물이 더 좋아진 건 아니거든요. 수렴은 검증을 거쳤다는 증거가 아니라 그냥 서로 양보한 결과일 수도 있는 거죠.

---

## 단락

한 단락 = 한 논점. 1~3문장이 보통이고, 단락 사이는 빈 줄로 띄운다.

장 하나가 대여섯 단락을 넘어가면 화면 하나에 너무 많은 걸 담고 있다는 뜻이다. 그럴 땐 대본을 줄이는 게 아니라 **화면이 나뉘어야 하는 건 아닌지** 의심한다.

---

## 화면을 읽지 말고 풀어준다

슬라이드에 `모델 독립`이라고 적혀 있으면, 대본에서 "모델 독립입니다"로 끝내지 않는다. 화면의 짧은 문구는 **라벨**이고, 대본은 그 라벨이 무슨 뜻이고 왜 필요한지를 말한다.

**나쁨**
> 첫 번째는 모델 독립입니다. 두 번째는 순서 독립입니다.

**좋음**
> 첫 번째는 모델 독립입니다. 봇들 즉 각 프로필의 provider 모델을 다르게 둡니다. 같은 모델 두 개를 붙여놓으면 편향이랑 답변 패턴이 똑같이 나오니까 반박이 안 되거든요.

### 다만 위치를 중계하지 않는다

화면 얘기를 하되 **라벨·번호·위치를 부르지 않는다.** 부르는 순간 낭독이 된다.

| 이렇게 쓰지 않는다 | 이렇게 쓴다 |
|---|---|
| 왼쪽에 사람의 요청이 있고, 화살표를 따라가면 가운데 AI가… | 사람이 시키면 AI가 글 쓰고 파일 만들고, 결과물이 나오죠 |
| 01번은 … 02번은 … 03번은 … | 요청과 결과물 사이 과정이 짧은 작업, 대화로 고쳐 나가는 작업, 그리고 짧고 명확한 작업입니다 |
| 카드 안의 그림을 보시면 문서 두 개가 뒤에 줄 서 있습니다 | 블로그 다 작성할 때까지 기다리고, 그다음 카드뉴스 기다리고 |

**화면을 중계하지 말고 화면이 말하려는 것을 말한다.**

---

## 이어붙이는 문장

각 장은 앞 장을 받고 다음 장으로 넘긴다. 다만 매 장을 같은 문형으로 열지 않는다. 아래는 샘플에서 쓰인 여러 형태다.

**받는 문장**
- `그럼 여기서 말하는 봇이 뭔지부터 정리하고 갈게요.`
- `앞서 말한것처럼 얘네한테 협업을 시켜봤더니 …`
- `두 번째 문제는 좀 더 근본적입니다.`
- `그럼 이 병합본이 최선이냐 하면 …`

**넘기는 문장**
- `왜 그렇게 해야 하는지부터 순서대로 보겠습니다.`
- `저는 어떻게 풀었는지 실습에서 보여드리도록 하겠습니다.`
- `이 워크트리 개념은 뒤에서 더 보도록 할게요.`

**스스로 묻고 답하는 형태**도 자주 쓴다. 다음 장의 주제를 질문으로 던진다.

> 그럼 오늘 뭘 가지고 경쟁 시킬거냐.

> 그럼 어떻게 비교할거냐 하면, 총 2단계로 할겁니다.

---

## 쓰지 않는 것

**목차 낭독** — "오늘 배울 것은 세 가지입니다, 첫째…". 표지 규칙 위반이다.

**제작 메모** — `여기서 데모 화면 전환`, `(3분)`, `- 핵심 포인트 3개` 같은 불릿 개요. 대본은 읽는 글이다.

**없는 수치** — `제 경우에는 40%가 나왔는데`처럼 측정한 척하는 숫자나 실험 결과.

다만 **1인칭 작업 경험은 쓴다.** 정답 대본이 계속 그렇게 한다 — `실제로 이렇게 쓰시는 분들 꽤 많습니다. 저도 그랬고요`, `상태 확인도 제가, 파일 정리도 제가`. 강사가 겪었을 법한 작업 장면은 공감을 만든다. 지어낸 수치와 다르다.

**대본에서 새로 만든 사실** — 설명이 부족해 보여도 제품 기능이나 수치를 지어내 채우지 않는다. 소스가 얇으면 얇은 대로 쓰고, 보고할 때 그 지점을 알린다.

**소스 문장 복사** — 반대 방향의 실패다. `_source`의 문장을 그대로 옮기면 문어체가 섞인다. 주장과 인과는 지키되 말은 새로 한다.

**과한 비유** — 비유로 시작해 비유로 끝나면 개념이 안 남는다. 정의를 먼저 주고 비유는 보조로만.

---

## 제작 용어를 입에 올리지 않는다

**`클립`은 대본에 쓰지 않는다.** 이건 저장소와 커리큘럼에서 쓰는 제작 단위이지, 수강생이 아는 말이 아니다. 수강생에게는 그냥 영상 하나다.

같은 이유로 대본에서 말하지 않는 것 — `덱`, `슬라이드 3장`, `스토리보드`, `커리큘럼`, `소스`. 전부 만드는 쪽 용어다.

**`파트`는 예외다.** 수강생도 파트 단위로 강의를 듣기 때문에 `다음 파트에서 보겠습니다`는 자연스럽다. 골든셋도 그렇게 끝난다.

| 이렇게 쓰지 말고 | 이렇게 쓴다 |
|---|---|
| 이번 **클립**에서는 | 이번 **영상**에서는 / **오늘은** / **이번에는** |
| 다음 **클립**에서 | **다음 영상**에서 / 이어서 / 뒤에서 |
| 앞 **클립**에서 | **앞에서** / 지난 영상에서 |

가장 자연스러운 건 아예 지칭을 빼는 것이다. "이번 영상에서는 …를 보겠습니다"보다 **"이번에는 …를 보겠습니다"**가 낫다. 매번 무언가를 가리킬 필요가 없다.

`## 슬라이드 3/5 —` 같은 **파일의 제목 줄은 형식이지 대사가 아니다.** 이 규칙은 본문 문단에만 적용된다.

---

## 표기

- 화면·소스에서 인용문(`>`)으로 지정된 문구는 **화면에 그대로 올릴 문구**다. 대본에서 바꿔 말하지 않는다.
- 영문 제품명은 소스와 확정 문구의 표기를 따른다. 한 대본 안에서 `Orca`/`오르카`를 섞지 않는다.
- 명령어·필드명(`worker_done`, `run create`)은 원문 그대로 쓰고, 외울 필요 없다는 안내를 붙이면 부담이 준다.
