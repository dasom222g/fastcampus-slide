# 흐름 패턴과 장치

대본이 지루해지는 이유는 문장이 나빠서가 아니라 **장과 장 사이에 이유가 없어서**다. 좋은 대본은 앞 장이 다음 장을 부른다. 아래 세 패턴은 그 부르는 방식이 다르다.

패턴 A가 기본값이다. 강사가 가장 선호하는 흐름이고, 세 샘플 중 가장 완성도 높은 Hermes 대본이 이 형태다. B와 C는 클립의 성격상 A가 안 맞을 때 쓰는 변형이다.

---

## 패턴 A — 문제 → 원인 → 대응 → 적용 *(기본값)*

**언제 쓰나**: 무언가가 잘 안 되는 이야기로 시작할 수 있는 클립. 도구의 한계, 잘못된 기대, 안 되는 방식이 있고 그걸 푸는 구조를 알려주는 클립.

**예제**: [examples/hermes-bot-mode.md](examples/hermes-bot-mode.md) (7장)

| 장 | 역할 | 샘플에서 |
|---|---|---|
| 1 | **표지 — 뭘/왜만 짧게** | 오늘 다룰 것 + 왜 지금 배우는지. 두 단락으로 끊고 2장으로 넘어간다 |
| 2–3 | **바탕 사실** — 문제를 판단하려면 먼저 알아야 하는 정체와 제약 | 봇 = 기존 프로필 / 그룹 제한 2~6명·3라운드·10메시지 |
| 4 | **문제 ①** — 눈에 먼저 보이는 것 | 작업공간이 분리돼 있다 |
| 5 | **문제 ②** — 더 근본적인 것 | AI가 너무 쉽게 수렴한다 |
| 6 | **대응** — 문제에 하나씩 대응하는 구조 | 6가지 전략 |
| 7 | **적용** — 오늘 실습과 잇고, 내 업무로 일반화 | 교차검증 흐름 + "판단이 필요한 자리 어디에나" |

**핵심은 문제를 두 개로 나누고 순서를 두는 것이다.** 눈에 보이는 문제를 먼저, 근본적인 문제를 뒤에 둔다. 이렇게 하면 대응 장이 나올 때 "왜 이렇게까지 하나"가 이미 설명돼 있다. 문제를 한 장에 몰아넣으면 대응 장이 규칙 나열로 읽힌다.

**주의**: 대응 장이 길어질 때(전략 6개처럼) 각 항목을 "N번째는 X입니다"로만 끝내지 않는다. 샘플은 항목마다 **왜 필요한지**를 한 문장씩 붙인다 — "같은 모델 두 개를 붙여놓으면 편향이랑 답변 패턴이 똑같이 나오니까 반박이 안 되거든요."

## 패턴 B — 개념 도입형

**언제 쓰나**: 새 도구·새 용어가 처음 나오는 클립. 아직 문제를 말할 수 있는 바탕이 없어서, 정체부터 세워야 하는 경우.

**예제**: [examples/orca-judgment-system.md](examples/orca-judgment-system.md) (12장)

| 장 | 역할 | 샘플에서 |
|---|---|---|
| 1 | **표지 — 뭘/왜만 짧게** | 오늘 만들 결과물 한 줄 + 왜 이걸 배우는지 |
| 2 | **정체 — 오해부터 지운다** | "새로운 에이전트로 오해하기 쉬운데 아닙니다" |
| 3 | **배경 — 기존의 무엇을 깼나** | 에디터 1 + 에이전트 1이라는 전제 |
| 4 | **용어** — 이 클립에서 쓸 말 정의 | 에이전트 / 하네스 / Orca |
| 5–6 | **전제 개념 → 작업 단위** | git → worktree |
| 7 | **분류** — 갈래를 나눈다 | 경쟁 패턴 / 협업 패턴 |
| 8–11 | **동작 원리** — 도구·역할·흐름·메시지 | 오케스트레이션의 내부 |
| 12 | **오늘의 구조 + 일반화** | 6개 층 + "판단이 필요한 어디에나" |

**2장의 오해 교정이 이 패턴의 엔진이다.** 새 도구를 설명할 때 "이건 X입니다"보다 "X라고 오해하기 쉬운데 아닙니다, Y입니다"가 훨씬 잘 붙는다. 수강생이 이미 갖고 있는 잘못된 그림을 먼저 지워야 새 그림이 들어간다.

**주의**: 용어 장(4장)은 정의를 나열하는 장이 아니라 **왜 용어를 맞춰야 하는지**부터 말하고 들어간다. 샘플은 "용어가 정리되어 있어야 명확한 소통이 가능하거든요 … 무엇보다 AI와 의사소통이 원활해집니다"로 연다. 이유 없이 정의만 3개 읽으면 수강생이 외우려 들다가 놓친다.

## 패턴 C — 실습 동행형

**언제 쓰나**: 화면이 실습 단계를 따라가는 클립. 이론 장과 실습 장이 번갈아 나오는 구조.

**예제**: [examples/orca-worktree-competition.md](examples/orca-worktree-competition.md) (12장) — ⚠️ 초안이다. [examples-index.md](examples-index.md)를 먼저 읽는다.

| 장 | 역할 | 샘플에서 |
|---|---|---|
| 1–2 | **주제 + 오늘의 과제** | 경쟁 패턴 / 슬라이드 만들기로 붙여본다 |
| 3 | **복습** — 지난 개념 짧게 | Orca, 오케스트레이션 |
| 4–6 | **1단계 구조 → 실습 진입** | "그럼 1단계 경쟁 한번 시켜볼게요!" |
| 7 | **벽** — 1단계 결과로는 부족하다 | 병합본을 고치려니 충돌한다 |
| 8 | **원인** | 같은 파일을 동시에 건드린다 |
| 9 | **새 개념** — 벽을 넘는 도구 | 워크트리 분리 |
| 10 | **2단계 구조 → 실습 진입** | |
| 11–12 | **정리 + 판단 기준 일반화** | "다른 파일이면 같은 공간, 같은 파일이면 다른 공간" |

**핵심은 7장의 벽이다.** 새 개념(워크트리)을 9장에서 처음 꺼내는데, 그 전에 7·8장이 "이게 없으면 안 되는 이유"를 실습으로 보여준다. 개념을 먼저 설명하고 나중에 쓰는 것보다 훨씬 붙는다.

**마지막 장은 규칙 한 줄로 압축한다.** 샘플의 "다른 파일이면 같은 공간, 같은 파일이면 다른 공간"처럼, 수강생이 나중에 기억할 문장 하나를 남긴다.

## 어느 패턴도 아닐 때

억지로 끼우지 않는다. 다만 어떤 흐름이든 아래 셋은 있어야 한다.

- **표지가 이유를 준다** — 왜 이 클립을 지금 배우는지. 짧게, 두 단락
- **장마다 이유가 있다** — 앞 장이 이 장을 부르는 이유
- **마지막이 일반화한다** — 오늘 예제를 넘어 내 업무로

## 반복해서 쓰는 장치 7가지

패턴과 별개로, 세 샘플이 공통으로 쓰는 장치다. 필요한 곳에만 쓴다. 매 장에 다 넣으면 상투구가 된다.

### 1. 오해 교정

새 개념의 첫 장에서 쓴다. 잘못된 그림을 먼저 지운다.

> 얘는 새로운 에이전트로 오해하기 쉬운데 아닙니다. 여러 에이전트들이 일할수 있도록 해주는 작업장에 가깝습니다.

> Bot Mode, 그러니까 봇이라는 새 용어가 나와서 뭔가 새로운 기능처럼 보이는데 아닙니다. 여기서 말하는 봇의 정체는 우리가 원래 쓰던 Hermes의 Profile이에요.

### 2. 정의 먼저, 비유는 보조

낯선 용어는 **실제 뜻을 먼저** 말하고, 그 다음에 비유를 붙인다. 비유부터 시작하면 수강생이 비유만 기억하고 정의를 못 가져간다.

> 하네스라는 개념은 … [에이전트를 실행하고 도구와 파일, 세션을 관리하는 환경]이라고 할수 있겠는데 … 쉽게 비유하자면 작업자의 개인 책상이라고 이해해주시면 되는데

비유는 클립당 한두 개면 충분하다. 계속 붙이면 개념이 흐려진다.

### 3. 개인 체험 앵커

수강생이 겪을 오해를 강사가 먼저 겪었다고 말해준다. 신뢰를 만드는 가장 싼 장치다.

> 저도 처음 써볼 때 얘네가 계속 지들끼리 대화하는 줄 알았거든요. 근데 몇 번 주고받다가 조용히 끝나있더라고요.

**단, 사용자가 실제로 말한 경험만 쓴다.** `_source`나 대화에 근거가 없으면 지어내지 않는다. 강의 진행을 나타내는 "이번에는 … 해볼 겁니다"는 언제든 써도 된다.

### 4. 범위 넘김

지금 장에서 다 설명하면 흐름이 무너지는 내용을 명시적으로 미룬다. 어물쩍 넘어가는 것과 다르다.

> 이 워크트리 개념은 뒤에서 더 보도록 할게요.

> 자세한 설명은 제 강의에서 다룰게요. 내용이 좀 깊어서 여기서 하기엔 너무 길어질것 같고,

### 5. 숫자 고정

제약·한계를 말할 땐 숫자를 정확히 준다. "여러 개"가 아니라 "2명에서 6명까지".

> 한 그룹에 들어가는 봇은 2명에서 6명까지고요. … 봇 응답이 최대 3라운드까지 이어지고, 그 안에서 생기는 봇 메시지가 최대 10개입니다.

숫자는 `_source`에 있는 것만 쓴다. 기억으로 채우지 않는다.

### 6. 실습 진입 신호

이론 장이 끝나고 화면이 데모로 넘어갈 때 짧게 끊는다.

> 그럼 이제 실제로 만들어보겠습니다.

> 그럼 1단계 경쟁 한번 시켜볼게요!

### 7. 마지막 장 일반화

오늘 예제를 넘어 수강생의 업무로 옮긴다. 세 샘플 모두 이 장치로 닫는다.

> 오늘은 Bull하고 Bear로 상승이랑 하락에 대한 교차검증을 하지만, 이 구조 자체는 판단이 필요한 자리 어디에나 씁니다. … 내 업무에서는 어떤 부분에 써야할지 그 관점으로 봐주셨으면 합니다.

이 문장을 그대로 복사하지 않는다. **구조만 가져온다** — 「오늘은 X로 하지만 / 이건 Y가 필요한 어디에나 쓴다 / 그 관점으로 봐달라」.
