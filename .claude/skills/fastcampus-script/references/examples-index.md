# 예제 대본 3편 — 읽는 법

`examples/`의 세 파일은 **강사가 실제로 촬영한 유튜브 영상의 대본**이다. 이 강의의 커리큘럼 클립이 아니다.

그래서 읽는 목적이 정해져 있다.

| 가져오는 것 | 가져오지 않는 것 |
|---|---|
| 장과 장을 잇는 방식 | 기술 설명·주장 |
| 어미와 문장 호흡 | 용어 표기 |
| 오해 교정·비유·일반화 같은 장치 | 개인 경험·수치 |
| 표지를 여는 방식 | 장수·구성 |

## 왜 내용을 가져오면 안 되나

**세 샘플이 서로 모순된다.** 각각 다른 시점에 다른 도구를 다룬 영상이라 그렇다. 그대로 옮기면 강의 안에서 앞뒤가 안 맞는 말을 하게 된다.

- **모델 독립 여부** — Hermes 6장은 "봇마다 provider 모델을 다르게 둬야 반박이 된다"고 한다. 판단 시스템 12장은 정반대로 "관점 차이랑 모델 차이가 섞이면 공정한 비교가 안 된다"며 팀 안에서 모델을 통일한다. 둘 다 맞지만 목적이 다르다(수렴 방지 vs 팀 비교).
- **워크트리 분리 기준** — 판단 시스템 7장은 "경쟁 = 독립 워크트리 / 협업 = 같은 워크트리"로 설명한다. 워크트리 경쟁 12장은 "다른 파일이면 같은 공간, 같은 파일이면 다른 공간"으로 **파일 기준**을 든다. 후자가 더 정확하다 — 실제로 그 대본의 1단계 경쟁이 워크트리 하나 안에서 돌아간다.

이런 판단은 대본이 정하는 게 아니다. `docs/confirmed-copy.md`와 `docs/patterns.md`가 정하고, 대본은 거기 적힌 것을 따른다.

## 파일별 상태

### `hermes-bot-mode.md` — 7장 · **기준 대본**

완성본이다. 형식·말투·흐름 모두 규격을 충족한다. **패턴 A(문제 → 원인 → 대응 → 적용)의 표준 예제**이고, 감이 안 잡힐 때 이것부터 읽는다.

특히 볼 곳:
- 1장 — 반전으로 여는 표지
- 4·5장 — 문제를 두 개로 나누고 근본적인 쪽을 뒤에 둔 배치
- 6장 — 전략 6개를 나열이 아니라 각각 이유와 함께 설명하는 방식
- 7장 — 실습 연결 + 업무 일반화로 닫기

### `orca-judgment-system.md` — 12장 · 정돈 완료

원본에 1~6장이 통째로 중복돼 있었고 Notion 내보내기 잔재(`<aside>` 블록)가 섞여 있었다. 둘 다 제거했고 오타(`워크리트`, `코디테이너`, `시템`)를 고쳤다. **패턴 B(개념 도입형)의 예제**로 쓴다.

특히 볼 곳:
- 2장 — 오해 교정으로 새 도구를 여는 방식
- 4장 — 용어를 왜 맞춰야 하는지부터 말하고 정의로 들어가는 순서
- 12장 — 6개 층을 층마다 목적과 함께 설명하는 방식

### `orca-worktree-competition.md` — 12장 · ⚠️ **초안**

헤딩 형식과 반복 오타는 고쳤지만 **본문에 미완성이 남아 있다.** 문장을 베끼지 말고 구조만 본다.

- 59행에 `??` 자리표시자가 그대로 있다 — 강사가 채울 내용이라 손대지 않았다
- 1장·2장이 문장 중간에서 끊긴다 (`만들어 볼건데.`, `경쟁 시킬거냐.`)

**패턴 C(실습 동행형)의 예제**로는 쓸 만하다. 7장(벽) → 8장(원인) → 9장(새 개념)의 배치와 12장의 한 줄 규칙이 이 파일의 값어치다.
