# Storyboard Format (fastcampus-slide)

`{이름}-storyboard.md`는 아래 형식을 **그대로** 따른다.
HTML보다 먼저 저장하며, 이후 모든 수정 지시의 기준 문서가 된다.

---

## 전체 구조

```markdown
# {덱 이름} 스토리보드

**소스:** (파일이면 경로, 아니면 무엇을 받았는지 한 줄 — 예: 채팅으로 받은 강의 대본)
**출력 슬라이드:** (실제 저장 경로)
**총 슬라이드:** N장 (표지 1장 + 본문 N-1장 — 표지는 COVER_SCENE `scene-cover` 등, 모든 덱의 1번)
**디자인 기준:** fastcampus-slide 스킬 `assets/base-template.html` (다크 · 패스트캠퍼스 레드)

---

## 용어 규칙 (필요할 때만)

| 이 덱에서 쓰는 말 | 원문 표기 | 쓰지 않는 말 |
|---|---|---|
| | | |

| 항목 | 내용 |
|---|---|

| 청중 | (누가 보는가) |
| 핵심 주장 1 | |
| 핵심 주장 2 | |
| 핵심 주장 3 | |

**버릴 내용**
- (소스에 있지만 덱에 넣지 않은 항목) — 이유
- (…)

---

| # | 타입 | 제목 | 핵심 메시지 |
|---|---|---|---|

- **타입:** COVER_SCENE

- **근거:** 소스 「섹션명」 — "인용 문장"

**화면 요소**

| 요소 | 내용 |

**발표 노트**
> 이 슬라이드에서 말할 내용 2~3문장.

## 조작 규칙

- 슬라이드 이동은 **좌우 화살표 버튼 · 하단 점 · 키보드 ←→/스페이스**로만. 화면 아무 데나 클릭해서 넘기지 않는다
- 마지막 슬라이드에서 다음 버튼, 첫 슬라이드에서 이전 버튼은 비활성 처리
```

## 작성 규칙

**용어 규칙 (강의 덱에서 중요)**
- 소스가 특정 제품·시스템을 가르치는 강의라면, 화면 표기가 실제 제품 화면과 일치해야 학습이 이어진다. 원문 표기를 그대로 노출할 용어와 한국어로 옮길 용어를 표로 확정한다
- 가르치지 않는 유사어("카드"를 "작업" 대신 쓰는 것 등)는 "쓰지 않는 말"에 명시한다
- 소스에 그런 용어 체계가 없으면 이 섹션은 생략한다

**타입**
- `references/slide-layouts.md`의 구조별 패턴 이름을 적는다. 예: `SCENE_PAIR`, `OPEN_TRIPTYCH`, `ENVIRONMENT`, `LAYER_STACK`. 같은 골격의 변형은 `SCENE_IMAGE(우측 장면)`처럼 적는다. 같은 역할의 본문은 기준 장과 타이포를 공유한다고 명시한다

**제목**
- 명사/명사구, 최대 12자, 문장형 금지
- O: `다섯 상태`, `작업 연결` / X: `상태가 다섯 개다`
- 여기 적은 제목이 화면 상단 `slide__title`에 **그대로 표시된다.** 강조할 부분을 볼드로 표시해 두면 HTML에서 `.hl`이 된다
- **1번 슬라이드는 표지(COVER)다.** `slide__title`은 커리큘럼의 클립 제목 그대로(12자 규칙의 유일한 예외), 화면 요소는 제목·한 줄 주제·시각 1점이며 목차·학습 항목·번호 목록을 절대 넣지 않는다. 스토리보드 헤딩은 `## 슬라이드 1 / N — 표지`로 적고, 2번(주제 선언)부터 덱이 다루는 주제를 명사구로 적는다

**핵심 메시지**
- 슬라이드가 전달하는 단 하나의 문장. 두 개가 나오면 슬라이드를 쪼갠다

**근거 (가장 중요)**
- 소스 내 실제 문장이나 섹션을 지목한다. 수치를 쓸 때는 반드시 근거를 남긴다
- 소스에 근거가 없는 연결용 슬라이드는 `출처 없음 — 연결용`이라고 적고, 수치·고유명사를 쓰지 않는다

**화면 요소 표**
- 실제 HTML에 들어갈 텍스트를 그대로 적는다. "적당한 설명" 같은 자리표시자 금지
- 아이콘은 사용할 이모지를 확정해서 적는다 (예: `📋`)
- **요소마다 색 톤을 함께 적는다** (`brand`/`orange`/`purple`/`yellow`/`green`/`gray`) — 색이 의미를 나르는 디자인이라 색 배정도 구성의 일부다
- 같은 대상은 덱 전체에서 같은 색을 유지한다 (색 연속성). 앞 슬라이드에서 정한 색을 표에서 확인하며 적는다

**애니메이션 순서**
- 등장 요소를 순서대로 번호로 적는다. **이 순서가 곧 HTML의 DOM 배치 순서다** — 타이밍은 JS가 일괄 처리(150ms 시작, 260ms 간격)한다. ms는 참고용으로 적어도 되고 생략해도 된다
- 요소 10개 초과 금지 (전체 등장 3초 초과) — 넘으면 슬라이드를 쪼갠다

**발표 노트**
- 실제로 말할 내용. 슬라이드 텍스트를 그대로 읽는 문장은 쓰지 않는다
- HTML 생성 시 각 `<article>` 위 주석으로 함께 옮긴다

---

## 완성 예제

**작성 전에 `assets/example-storyboard.md`를 연다.** 위 형식을 실제로 채운 7장짜리 완성본이며, 용어 규칙·근거 칸·버릴 내용·색 배정·감수 기록이 모두 들어 있다. 형식 판단이 애매하면 그 파일을 그대로 따른다.

문서와 예제가 어긋나면 **예제가 기준이다.** 예시를 이 문서에 복사해 두지 않는다 — 두 곳에 두면 반드시 어긋난다.
