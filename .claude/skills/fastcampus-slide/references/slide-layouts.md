# Slide Layouts (fastcampus-slide 다크 디자인)

레이아웃 타입의 **정의는 `assets/base-template.html`에 있다.** 이 문서는 어떤 타입을 언제 쓰는지 고르는 가이드다.

템플릿의 슬라이드 1~6은 각 타입의 완성된 예제다. 제작할 때는 **필요한 타입의 `<article class="slide">`를 복사해 내용만 바꾸고, 쓰지 않은 슬라이드는 삭제한다.** HTML 구조를 이 문서에서 옮겨 적지 않는다 — 템플릿이 유일한 기준이다.

---

## 타입 6종

구성이 실제로 다른 것만 남겼다. 색이나 장식만 다른 것은 타입이 아니라 **변형**이며, 변형은 클래스 교체로 만든다.

| # | 타입 | 핵심 클래스 | 언제 쓰나 |
|---|---|---|---|
| 1 | TEXT | `cover-body` | 표지, 문제 제기, 마무리 한 문장 (이모지 + 선언문 + caption + 축 라벨) |
| 2 | CARD_GRID | `grid-3` + `col-card` | 병렬 요소 소개, 역할 비교, 총정리 |
| 3 | LIST | `list` + `list-num` | 근거 나열, 번호 절차 (번호 원 + 제목 + 부연, 카드 박스 없음. 번호 원·점 마커는 **흰색 통일 — 색 입히지 않는다**) |
| 4 | ICON_ROW | `timeline` + `timeline-card` | 흐름, 단계, 상태 전이 (가로 파이프라인) |
| 5 | TREE | `fan` | 부모 1 → 자식 여럿의 분기·위임·분화 구조 |
| 6 | METRIC | `metric-row` + `metric` | **소스에 실제 수치가 있을 때만** |

## 변형 (새 타입을 만들지 말 것)

| 만들고 싶은 그림 | 기반 타입 | 방법 |
|---|---|---|
| 카드 6장 (3열 2행) | CARD_GRID | `grid-3`에 `grid-3--tight` 추가 — 카드가 작아지고 제목이 모노 서체가 된다 |
| 카드 6장, 각 설명이 한 문장 이상 | CARD_GRID | `grid-3 grid-3--tight grid-3--spacious` — 카드 높이·패딩·제목·본문을 키운다. 글자를 줄이기 전에 이 변형을 쓴다 |
| 이미지 주도 표지 | TEXT | 이미지 자체의 네거티브 스페이스에 선언문을 오버레이한다. 별도 텍스트 열을 만들지 않으며 구현은 `goldenset-hermes-bot.md` 1번을 따른다 |
| 대형 설명 이미지 + 결론 | TEXT | 이미지가 본문을 차지하고 결론 캡션만 이미지 위에 둔다. 피사체·동선과 겹치지 않게 너비를 제한한다 |
| 카드에 정체 배지 (AI/사람/시스템 구분) | CARD_GRID | 카드 첫 요소로 `role-badge role-badge--{색}`, 제목 아래 `role-sub`(영문 원어) |
| 좌우 대비 비교 (안 됨 vs 됨) | CARD_GRID | `vs-grid` + `vs-col--blocked`(orange) / `vs-col--pass`(brand), 상단 `vs-badge` |
| 좌 시각자료 + 우 설명 | CARD_GRID | `grid-2` — 왼쪽에 mock/그림, 오른쪽에 `list` 등 |
| 파이프라인 카드 3·4장 | ICON_ROW | `timeline--3` / `timeline--4` — 카드 수에 맞는 columns 필수 |
| 흐름 속 인용 대사 | ICON_ROW | `timeline-card__body`에 `flow-quote` — 사람의 요청 문장 등 |
| 순서 없는 나열 | LIST | `.list-num` 대신 `.list-dot`, `.list-item`에서 `num` 클래스 제거 (텍스트 상단 정렬) |
| 자식 3갈래 트리 | TREE | `.fan-kids`를 `grid-template-columns: 1fr 1fr 1fr`로 |
| 수치 2개 | METRIC | `.metric-row`를 `repeat(2, 1fr)`로 — 빈 칸을 만들지 않는다 |

**리듬 규칙:** 같은 타입을 3연속 쓰지 않는다. 텍스트형(TEXT·LIST) 뒤에는 그림형(CARD_GRID·ICON_ROW·TREE·METRIC)을 배치한다.

## 색상 시스템 (이 디자인의 핵심)

색은 장식이 아니라 **의미 전달 장치**다. 전부 `:root` 변수로만 쓴다 — 인라인 색상 금지.

- **brand** — 패스트캠퍼스 레드(`#fc1c49`). 덱의 기본 강조색. 제목 `.hl`, 진행바, tip 화살표, "핵심/내가 만드는 것" 묶음
- **orange** — 문제·차단·활성 진행. 대비 비교의 "안 되는 쪽"
- **purple** — 핑크 기 없는 blue-violet(`#9188ff`). 두 번째 묶음, 파생·자식, 반박·검증 계열
- **yellow** — 주의·대기·강조 수치. 제목 강조 대안 `.hl-yellow`
- **green** — 완료·성공. `bullet-list li.ok`의 ✓
- **gray** — AI 아님·시스템·무채 취급

**색 사용 규칙**
- 카드 계열 요소는 세 겹으로 색을 입힌다: **낮은 알파 배경 + 같은 색 테두리(`--border-{색}`) + 색 있는 배지/마커**
- 흐름(timeline)은 진행 방향을 색으로도 읽히게 한다: 무채(대기) → 유채(활성) → green(완료)
- **색 연속성:** 같은 대상은 덱 전체에서 같은 색을 쓴다. 슬라이드 4에서 brand이던 역할이 슬라이드 5에서 purple이 되면 안 된다
- 한 슬라이드에 유채색 묶음은 3개까지. 그 이상이면 묶어서 줄인다
- pink·rose·lime은 일반 강조색으로 쓰지 않는다. orange는 문제·경고처럼 의미가 분명할 때만 쓴다

## 타이포그래피 규칙

- 본문·제목: Pretendard / 표지 선언문·대형 수치: **GmarketSans** (`.cover-stmt`, `.metric__num`, `.display`)
- 라벨·배지·번호: **Monaco 모노 서체** (`slide__label`, `timeline-card__step`, `role-badge`, `cover-axis`)
- 기술 용어·명령어는 `<code>` — brand 배경 처리가 자동으로 붙는다
- 제목 강조는 `<span class="hl">` (brand 기본, `hl-orange`/`hl-yellow` 대안). 한 제목에 강조는 한 곳만
- 모든 크기는 `clamp()`로 이미 반응형이다. **고정 px를 새로 쓰지 않는다** — 조정이 필요하면 해당 클래스의 clamp 값을 고친다

## 간격 규칙

이 디자인에는 간격 변수 스케일이 없다. **간격은 각 컴포넌트 클래스에 clamp()로 내장되어 있다.**

- 새 간격이 필요하면 즉흥 px 대신 **기존 클래스 패턴을 복사**한다
- 요소 사이 간격이 이상하면 슬라이드에 인라인 스타일을 넣지 말고 해당 클래스의 gap/padding을 고친다
- `slide__body`는 기본 `justify-content: center` — 내용이 적으면 저절로 중앙에 온다. 억지로 늘리지 않는다
- 이미지·카드가 주인공인 장은 남는 본문 높이를 충분히 사용한다. 내용이 많다고 높이·패딩·타이포부터 줄이지 않는다

## 헤더·푸터 규칙 (모든 슬라이드 공통)

- 모든 슬라이드는 같은 골격: `slide__header`(label + title + sub) / `slide__body` / `slide__footer`
- **표지도 예외가 아니다** — 헤더를 빼지 않는다
- `slide__label`: `Section N · English Label` 형식 모노 톤. 표지는 `{주제 영문} · {주제 한글}`
- `slide__title`: 명사/명사구 + `.hl` 강조 1곳. 문장형 금지
- `slide__sub`: 제목을 풀어주는 완결된 한 문장
- `slide__footer`: 패스트캠퍼스 로고 `<img class="fastcampus-logo" src="/assets/fastcampus-logo-dark.svg">` 하나. 텍스트를 넣지 않으며 모든 슬라이드에서 동일

## 애니메이션 규칙

이 디자인의 애니메이션은 단순하다: **`anim-item` 클래스가 붙은 요소가 DOM 순서대로 fadeInUp**된다 (첫 요소 150ms, 이후 260ms 간격 — JS `_runSlide()`가 자동 처리).

- **애니메이션 순서 = DOM 순서.** 스토리보드의 "애니메이션 순서"는 곧 HTML 요소 배치 순서다. 별도 타이밍 코드를 쓰지 않는다
- 등장시킬 요소에만 `anim-item`을 붙인다. 헤더·푸터는 슬라이드 전환과 함께 나타나므로 붙이지 않는다
- 등장 단위는 "의미 덩어리"다 — 카드 한 장, 화살표 하나, tip 한 줄. 카드 내부 요소를 쪼개서 등장시키지 않는다
- 요소가 10개를 넘으면 슬라이드 전체 등장이 3초를 넘는다. 요소를 줄이거나 슬라이드를 쪼갠다
- 재진입 시 자동으로 처음부터 재생된다 (JS가 처리 — 손대지 않는다)

## 제작 시 구조 규칙

- `data-index`는 **0부터** 순서대로. 첫 슬라이드에만 `active` 클래스를 붙인다
- 슬라이드 총수는 JS가 `<article class="slide">` 개수에서 자동 계산한다. 단, 하드코딩된 `<span id="tot">N</span>`도 실제 개수로 맞춰 둔다 (JS 로드 전 깜빡임 방지)
- 각 `<article>` 위 주석에 스토리보드의 **발표 노트**를 옮긴다
- 아이콘은 이모지 기본. 로컬 이미지는 **루트 절대경로**만 쓴다 — 공용은 `/assets/…`, 이 덱 전용은 `/artifacts/<slug>/images/…`. 상대경로(`./` `../`)와 외부 URL 이미지 금지
- 웹폰트 CDN 2개(Pretendard·GmarketSans)만 외부 의존 허용. 그 외 스크립트·스타일·이미지는 전부 인라인/로컬 (오프라인에서는 폰트만 시스템 폰트로 대체되고 나머지는 동작해야 한다)

## 조작 규칙 (성공 기준 — 어길 수 없다)

- 페이지 이동은 **좌우 화살표 버튼(`nav-btn`) · 하단 점(`dot`) · 키보드(←/→/스페이스)**로만
- **본문 아무 곳 클릭으로 이동하면 실패다.** `#deck`·`body`·`.slide`에 이동용 click 리스너 금지 (강의 중 화면을 가리키며 클릭해도 넘어가면 안 된다)
- click 리스너는 `_buildDots()`(점)와 `_bindButtons()`(화살표 버튼)에만 존재해야 한다
- 첫 슬라이드에서 이전 버튼, 마지막에서 다음 버튼은 자동 비활성 (JS가 처리)

## 자주 나는 실수

- `timeline` 카드 수와 `grid-template-columns`가 안 맞음 — 카드 4장이면 `timeline--4` 필수. 안 맞으면 열이 밀린다
- `data-index` 누락·중복, `active`를 여러 슬라이드에 붙임 — 첫 장에만
- `id="tot"` 하드코딩 값을 안 고침 — JS가 덮어쓰지만 로드 순간 어긋난 숫자가 보인다
- 같은 대상의 색이 슬라이드마다 바뀜 — 색 연속성 규칙 위반
- 인라인 스타일로 색·크기 지정 — `:root` 변수와 클래스만
- `slide__sub`·카드 본문에 두 문장 이상 욱여넣음 — 넘치면 tip으로 빼거나 슬라이드를 쪼갠다
- 표지에서 `slide__header`를 빼먹음 — 모든 슬라이드가 같은 골격

## 완성 후 확인

브라우저에서 열어 **1280×800 이상**에서 처음부터 끝까지 넘겨 본다.

- 본문 아무 곳을 클릭해도 슬라이드가 넘어가지 않는가 (버튼·점·키보드만 동작)
- 마지막 슬라이드까지 넘어가고 카운터 총수가 맞는가
- 본문이 화면 밖으로 넘치지 않는가 (특히 timeline 5장·카드 6장 슬라이드)
- 카드 6장은 애니메이션이 모두 나온 상태에서도 제목·본문이 충분히 크고 내부 공간이 남는가
- 생성 이미지의 인물 수·출발점·현재 위치·목적지·방향·흔적이 스토리보드와 맞는가
- 표지 이미지의 네거티브 스페이스와 별도 텍스트 영역이 중복되지 않는가
- 슬라이드를 떠났다 돌아오면 애니메이션이 처음부터 재생되는가
