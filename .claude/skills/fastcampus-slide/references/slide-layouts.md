# Slide Layouts — 승인된 구조의 공통 계약

[base-template.html](../assets/base-template.html)은 **제작용 중립 템플릿 29종**이다. 어떤 패턴을 고를지, 무엇을 복사할지는 [패턴 카탈로그](pattern-catalog.md)를 따른다. 메시지를 파악하는 방법과 실제 실패 사례는 [최신 골든셋](goldenset-approved-course.md)에 있다.

## 공통 디자인

- 다크 배경·도트 그리드·브랜드 레드·공통 헤더/푸터를 유지한다. 푸터는 FastCampus 로고다.
- 표지는 클립명과 같은 제목, 부제, 핵심 장면을 갖는다. 목차·학습 항목·번호 목록은 넣지 않는다.
- `--title`, `--statement`, `--heading`, `--body`는 역할 토큰이다. 같은 역할은 font-family·size·weight·line-height·letter-spacing·강조 규격까지 공유한다. 다른 역할까지 같은 크기로 만들지는 않는다.
- 대형 문장이 길면 먼저 영역·문구·배치를 조정한다. 템플릿 복사의 목적은 한 장만 글자를 줄여 끼워 넣는 것이 아니다.
- 열린 구성에 장식 박스·그림자·배너·가로선을 추가하지 않는다. 통합 창·작업 공간·관리 범위는 의미를 설명하므로 경계를 쓸 수 있다.
- 상태는 색+형태로 구별한다. 에이전트 고유색과 완료/진행/대기 상태색은 같은 개념이 아니다.
- 이미지는 실제 피사체가 충분히 크고 SVG는 실제 도형의 여백이 맞아야 한다. 외부 래퍼만 크게 키웠다고 가독성이 커지지 않는다.
- 폴더는 가로 배너가 되지 않도록 폭·높이 비율을 유지한다. 기준 장이 지정됐다면 그 장의 실제 폴더 크기를 비교한다.
- 캡션은 같은 역할끼리 줄 수·중심축·간격을 맞춘다. 주체의 아이콘 중심, 라벨 묶음 중심, 컨테이너 중심을 구별한다.

## 구조와 범위

경계 안팎, 선의 시작·끝, 색과 이름을 새 내용에 맞춘다. 단지 원본이 예쁘다는 이유로 공간·주체·관계까지 복사하지 않는다. 특히 물리적 폴더, 논리적 관리 단위, 순서와 의존 관계를 구분한다.

- **범위:** `motion-scope`의 부모는 배치만 담당한다. `scope-frame.anim-item`이 경계를 따로 그린다. 프레임은 pointer-events:none과 aria-hidden이다.
- **관계:** `tx-graph`는 실제 아이콘 좌표를 기준으로 연결한다. 라벨의 줄 수가 달라도 선의 축이 기울어지지 않아야 한다. 곡선은 같은 기준점에서 대칭 계산한다.
- **전체 흐름:** 단계 크기와 간격을 맞추고, 명령/전환 라벨은 화살표 가까이에 둔다. 아이콘만 나열하면 흐름이 되지 않는다.
- **비교:** 비교 기준이 같은 행에서 읽히도록 정렬한다. 한쪽에만 부연 설명을 늘려 같은 역할의 높이를 깨뜨리지 않는다.

## 애니메이션과 조작

1. `data-anim-step`으로 설명 순서를 정한다. DOM 순서는 대체값일 뿐이다.
2. 경계 → 범위 이름 → 내부 항목을 분리한다. 모든 요소를 감싼 부모 하나에 효과를 걸어 통째 등장시키지 않는다.
3. 줄기가 자라는 동작은 개념을 보여줄 때 쓴다. 조절되지 않는 반복·장식 움직임은 넣지 않는다.
4. 클릭 전환과 이동은 해당 요소에서만 시작한다. 진입 시 자동 실행하지 않는다. 클릭 직후 반응과 재진입 초기 상태를 정의한다.
5. `data-motion="none"`은 같은 지도에서 강조만 달라지는 정지 장에 사용할 수 있다. 촬영 완료 덱의 동작은 요청 없이 바꾸지 않는다.
6. 전체 본문 클릭으로 덱을 넘기지 않는다. 버튼·점·←/→/Space만 페이지를 넘긴다. 조작 중인 탭과 버튼은 키보드 입력을 먼저 처리한다.
7. prefers-reduced-motion에서 이동은 생략하되 클릭 전/후 의미는 유지한다.

## 복사와 검수

- 베이스 전체를 새 클립으로 복사한 뒤 필요한 article만 남긴다. Pattern 라벨·제목·부제·data-slot을 실제 스토리보드로 교체한다.
- 상단 defs, 해당 패턴 CSS, 조작 JS를 함께 유지한다. 빈 이미지 자리표시자는 장면 이미지로 바꾼다.
- `data-index`, 장수, 대본과 짝 문서를 실제 덱에 맞춘다. 한 글의 예시 값을 항목 정의처럼 사용하지 않는다.
- 기본 2133×1200, 보조 1280×800에서 전 장을 확인한다. 작은 브라우저 검수에는 804×512도 사용한다.
- 정적 완성 화면뿐 아니라 등장 직후·중간·클릭 전후·재진입도 본다. 선 끝, 텍스트 잘림, 헤더/푸터 침범, 로고 로딩을 확인한다.
- 새 템플릿 추출이 승인 덱을 다시 디자인할 권한은 아니다. 현재 HTML과 대본을 보존하고 템플릿에서만 중립화한다.

## 기존 패턴의 승계

기존 1~9종을 유지하고 현재 승인 덱에서 20종을 추가했다. 이전에 철회된 실험 예제 12~15번을 복원한 것이 아니다. 현재 번호는 카탈로그의 ID·원본·적용 조건과 함께 읽는다. 삭제된 Part 4 설치 실습 덱을 기준 파일로 다시 요구하지 않는다. 과도기 대비의 현재 기준은 Part 4 오케스트레이션 구조 2장이다.

## 검수 보조 코드

[inspect-slide-layout.js](../scripts/inspect-slide-layout.js)를 브라우저의 evaluate 기능으로 실행하면 활성 장의 본문 넘침·깨진 이미지·등장 단계·탭 상태를 읽을 수 있다. 애니메이션 도중의 위치를 완성 배치로 판정하지 않는다. 이 검사는 화면의 인과관계나 화살표의 뜻을 대신 검증하지 않는다.
