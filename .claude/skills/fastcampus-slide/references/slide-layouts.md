# Slide Layouts — 확정 디자인의 템플릿

`assets/base-template.html`은 **강의 덱이 아니라 제작용 템플릿**이다. 화면에는 교체할 문구와 도식의 역할만 표시한다. 실제 강의 문장·제품명·로고·작업 캡처·임의 수치를 예제로 넣지 않는다. 공통 푸터의 FastCampus 로고는 브랜드 요소이므로 유지한다.

## 현재 제공하는 9개 패턴

기준은 승인된 `artifacts/part2/outputs/ch01-01-terminal-problem.html`의 1~5장이다. 기존 템플릿의 미채택 12~15번(환경 포함·절차 비교·층위·별도 좌우 비교)은 철회했다. 일반적으로 유용해 보인다는 이유로 패턴 목록에 넣지 않는다. 이후 사용자가 구조도와 ‘멀티 에이전트 과도기’ 구성의 템플릿화를 명시적으로 요청하여 6~8번을 추가했다. 철회한 예제를 복원한 것이 아니라 현재 참고 덱의 관계 표현을 중립화한 예제다.

| 예제 | 패턴 | 핵심 클래스 | 구조와 교체 대상 |
|---|---|---|---|
| 1 | COVER_SCENE | `scene scene--cover`, `statement` | 공통 헤더 + 왼쪽 짧은 선언문 + 오른쪽 장면. 목차 없음 |
| 2 | SCENE_PAIR | `scene scene--visual-first`, `scene__visual`, `scene__copy` | 왼쪽 큰 관계 도식 + 오른쪽 대형 본문과 보조 설명 |
| 3 | SCENE_IMAGE | `scene scene--image`, `statement` | 왼쪽 대형 본문 + 오른쪽 큰 장면 이미지 |
| 4 | OPEN_TRIPTYCH | `triptych`, `concept` | 테두리 없는 3열. 도식 → 제목 → 짧은 캡션 |
| 5 | STATUS_TRIPTYCH | `triptych`, `concept`, `handoff` | 같은 3열에서 첫 도식에 상태 창. 하단에 선택적인 한 줄 예고 |
| 6 | STRUCTURE_BRANCH | `structure-tree`, `structure-tree__children` | 상위 대상 → 연결선 → 동등한 하위 대상 둘. 관계 라벨은 HTML |
| 7 | STRUCTURE_EXCHANGE | `scene`, `exchange`, `exchange__node` | 왼쪽 선언문 + 오른쪽 요청·응답 구조도. 실선은 요청, 점선은 반환 |
| 8 | TRANSITION_COMPARE | `transition-compare`, `transition-side` | 과도기 구성에서 추출한 좌우 대비. 양쪽 라벨·제목·도식·캡션의 행 높이 동일 |
| 9 | CONTAINED_STRUCTURE | `scope-panel`, `motion-scope`, `scope-frame` | 하나의 공통 범위와 그 안의 개별 항목·공유 정보. 경계 → 범위 제목 → 내부 항목 순서 |

2번의 이미지/도식과 설명을 나누는 골격은 승인 덱의 같은 역할에도 재사용할 수 있다. 단, 새 덱의 문구·주체·관계를 기준 덱에서 복사하지 않는다. 6~8번의 의미와 다른 비교·포함 관계가 필요하면 그 요구를 먼저 스토리보드에 정의한다. 이번에 철회한 예제를 채택된 기본값처럼 되살리지 않는다.

## 사용법

1. 베이스 HTML 전체를 새 클립의 출력 경로로 복사한다.
2. 필요한 `data-pattern`의 `<article>`만 남긴다. 9장 전부를 새 덱에 넣으라는 뜻이 아니다.
3. 각 장의 제목·부제·`data-slot` 문구·도식·이미지를 확정 스토리보드로 교체한다. `data-slot`은 교체 위치를 찾는 제작용 표식이다.
4. 산 모양 SVG는 **이미지 자리표시자**다. 해당 장면 이미지로 교체하고 `scene__visual > img` 규격을 사용한다. 단순 아이콘으로 장면을 대신하지 않는다.
5. SVG의 `shape-*`는 중립적인 관계 예시다. 관계가 달라지면 도식을 다시 그린다. `<use>`를 유지한다면 상단 공통 `<defs>`도 남긴다.
6. `data-index`, 총수, 발표 노트, 짝 문서를 실제 덱에 맞춘다. `Pattern` 라벨도 클립 식별자로 바꾼다.

## 공통 디자인

- 다크 배경·도트 그리드·브랜드 레드·공통 헤더/푸터는 승인 덱 기준을 유지한다.
- 모든 본문 역할은 Pretendard를 사용한다. 표지·좌우 장면의 큰 본문은 **동일한 `.statement` 규칙**이다. `--statement`를 공유하며 같은 역할의 크기·굵기·행간·자간·강조를 따로 바꾸지 않는다.
- `--title`, `--heading`, `--body`는 각각 헤더·항목 제목·설명 역할이다. 서로 다른 역할까지 같은 크기로 만들지 않는다.
- 긴 문구가 안 들어가면 영역·문구 길이를 먼저 조정한다. 한 장만 폰트를 축소하지 않는다.
- 열린 구성에는 장식 박스·그림자·색 배너·가로선을 추가하지 않는다. 상태 창은 “한곳에 모여 있다”는 의미를 설명하므로 경계가 필요하다. 공통 헤더/푸터 선도 별개다.
- 상태는 초록 체크, 노랑 진행 링, 주황 물음표처럼 색과 형태를 함께 구별한다. 상태 범례로 본래 장의 핵심 메시지를 대체하지 않는다.
- 이미지와 도식은 남은 본문 높이를 충분히 쓴다. 넓은 화면에서 내용 묶음을 무작정 늘리지 않고 최대 폭을 두어 중앙에 배치한다.
- 캡션은 같은 역할끼리 줄 수와 간격을 맞춘다. 5번 첫 창은 실제 내용 경계를 기준으로 상하 여백을 맞춘다.
- `handoff`는 문구와 핵심어만 있는 짧은 예고다. 테두리나 배경을 붙이지 않는다.

## 검수

기본 **2133×1200**, 보조 **1280×800**에서 전체 예제를 확인한다.

- 템플릿에 실제 강의 문구·제품 이미지·작업 세션 캡처가 없는가
- 철회된 패턴이나 사용하지 않는 예전 CSS를 남겨두지 않았는가
- 표지에 제목·부제가 있고 목차는 없는가
- 1·2·3번 `.statement`의 computed style이 같은가
- 모든 요소의 순차 등장이 끝난 뒤에도 본문 넘침·제목 잘림·이미지 깨짐이 없는가
- SVG `<use>`가 실제로 표시되고 이미지 자리표시자가 명확한가
- 버튼·점·←/→/스페이스로 이동하고 본문 클릭은 이동하지 않는가
- 처음·마지막 버튼 비활성과 재진입 애니메이션이 정상인가
- 6번 분기의 선이 각 하위 항목 중심에 맞고 7번 요청·반환의 방향과 라벨이 겹치지 않는가
- 8번 좌우 비교의 라벨·제목·도식·설명 행 높이가 같고 추가 박스나 설명 행이 없는가

템플릿에서 실제 강의 내용을 찾지 않는다. 승인 덱은 디자인 판단의 근거, 소스·스토리보드는 내용의 근거다.

## 추가 구조도와 전환 비교의 사용 기준

- **6번 분기 구조:** `ch01-02-what-is-orca.html`의 이전 ‘작업 단위’ 구성에서 상위 하나와 하위 둘의 관계를 추출한다. 중립 문구는 ‘상위 항목 / 하위 항목 A / 하위 항목 B’. 단순 포함·분류 관계의 선에는 화살표를 붙이지 않는다. 하위 항목 수를 바꾸면 열과 연결선의 끝점도 같이 바꾼다.
- **7번 요청·응답 구조:** 같은 덱의 이전 오케스트레이션 구조도에서 선언문 + 조율 주체 + 두 실행 주체 + 왕복 관계를 추출한다. 문구는 ‘중심 역할 / 담당 역할 A / 담당 역할 B / 요청 / 결과’. 외곽선은 관계가 적용되는 범위를 뜻한다. 실제 주제에 공통 범위가 없으면 외곽선을 제거한다. 실선과 점선 모두 방향을 표시한다.
- **8번 전환 비교:** `part4/outputs/ch02-01-orchestration-skill-setup.html`의 ‘멀티 에이전트 과도기’ 대비에서 추출한다. 왼쪽은 중앙 담당자를 거치는 전달, 오른쪽은 담당자 간 연결과 피드백으로 그린다. 제목은 ‘기존 방식의 이름 / 전환된 방식의 이름’처럼 교체용 문구로 두고 실제 강의 설명과 제품 로고는 넣지 않는다. 양쪽 4행은 같은 규격을 쓰며 가운데에는 전환 화살표만 둔다. 카드 테두리·배경·추가 설명 행은 없다.
- 공통 타이포를 공유한다. 6~8번의 항목 제목은 `.heading`, 설명은 `.copy`이며 7번 큰 선언문은 기존 `.statement`를 그대로 쓴다.
- 라벨은 HTML로 쓰고 선과 도형은 SVG/CSS로 그린다. 새 내용으로 바꿀 때 글자를 축소하기 전에 슬롯 폭과 문구 길이를 조정한다.


## Orca 소개 수정본의 적용 범위

현재 `ch01-02-what-is-orca.html`은 작업 단위를 큰 폴더 하나로 정의하고, 오케스트레이션은 목표→분배→취합으로 소개한다. 위 6·7번의 추출 당시 구성과 현재 승인 화면은 다르다. 템플릿 6·7번은 관계가 맞는 주제에 사용할 수 있지만, 이 입문 클립에 예전 상세 구조를 되살리는 근거로 쓰지 않는다. 판단과 전후 비교는 [Orca 소개 골든셋](goldenset-orca-basics.md)을 따른다. 템플릿 HTML은 이번 등록에서 변경하지 않았다.

## 9번 포함 구조와 경계의 등장 — 2026-09-09

사용자가 확정한 Part 4 Ch01-02 ‘Run이란’의 포함 관계를 중립화한 패턴이다. 실제 Run·Task·Coordinator·강의 예시를 템플릿에 넣지 않는다. 슬롯에는 범위 이름·공통 목적·항목 A/B/C·공유 정보를 넣는다. 예전 철회 예제의 복원이 아니라 사용자가 요청한 현재 승인 구조의 추가다.

- 공간이나 묶음을 정의하는 **경계도 설명 요소**다. 내부 항목만 애니메이션하고 외곽선을 처음부터 노출하지 않는다.
- `.motion-scope`는 레이아웃을 담당하며 부모 자체에 `anim-item`을 붙이지 않는다. 테두리 두께는 유지하되 투명하게 하고, `.scope-frame.anim-item`을 절대 배치해 동일한 경계만 그린다.
- `scope-frame`은 `data-anim-step="0"`. 범위 제목은 1, 내부 항목은 그 이후 단계. 창 이름처럼 경계에 속한 라벨은 0에 함께 등장해도 된다.
- 경계는 이동 없이 opacity로 나타난다. 자식의 이동·등장 순서와 중첩하지 않는다. 프레임은 `aria-hidden="true"`, `pointer-events:none`으로 상호작용과 읽기 순서에 개입하지 않는다.
- 기본 실행기는 `data-anim-step`을 우선하고 DOM 순서를 대체값으로 쓴다. 재진입하면 단계가 처음부터 재생되며, 모션 감소 설정에서는 지연 없이 표시한다.
- **일괄 점검 범위:** `dashboard/clips.json`의 촬영 완료 덱은 수정하지 않는다. 최신 인덱스·사용자 확정으로 대상 덱을 정한다. `data-motion="none"` 등 의도적 정지 장과 클릭 전환은 보존한다.
- **검수:** 0ms(경계 숨김) → 경계 단계 → 내부 단계 → 완료를 따로 확인한다. 완료 스크린샷만으로 판단하지 않는다. 재진입·빠른 이동·reduced-motion을 확인하고, 수정 전후 최종 위치와 글자 크기가 같은지 대조한다.
