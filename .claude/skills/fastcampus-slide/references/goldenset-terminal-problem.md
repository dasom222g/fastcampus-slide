## 적용 범위와 우선순위

같은 골격의 타이포 통일, 표지, 장면 중심 구성, 상태 도식, 짧은 다음 클립 예고를 제작할 때 이 정답을 우선 참고한다. 사용자의 최신 명시적 수정과 승인본이 템플릿·과거 골든셋보다 우선한다. 다른 골든셋에서는 디자인 판단을 배우되 그 덱의 문구·분량·제품 주장을 이식하지 않는다.

이 덱의 5장·인물·정확한 글자 크기·창 좌표는 이 사례의 정답이다. 모든 덱을 5장이나 같은 그림으로 만들라는 규칙이 아니다. Part 4 오케스트레이션 예고 초안은 이번 승인 범위가 아니다.

## 1. 왜 이 구성이 작동하는가

| 장 | 역할 | 정답에서 읽히는 것 |
|---|---|---|
| 1 | 문제의 표지 | 공통 헤더 제목·한 줄 부제 + “창은 여러 개 / 관리는 사람 혼자”. 중앙 인물은 지쳐 있고 주변 터미널은 많다. 목차는 없다. |
| 2 | 제약의 출발점 | “터미널 하나에 / 에이전트 하나”. 터미널과 에이전트를 한 쌍으로 보여준다. |
| 3 | 제약이 만든 결과 | 2장과 같은 본문 타이포로 “터미널 3개 / 에이전트 3개”. 같은 관계의 수만 늘어난다. |
| 4 | 구체적 문제 | 진행을 놓침·파일 덮어쓰기·결과 비교의 어려움을 세 도식으로 보여준다. |
| 5 | 문제에 대응하는 필요 | 진행 상황·독립 작업 공간·나란한 결과를 같은 순서로 대응시킨다. 하단 Orca는 다음 클립으로 잇는 짧은 예고다. |

Orca를 먼저 길게 설명하고 문제를 끼워 맞추지 않는다. 이 덱에서는 문제 → 필요 → 도구 이름까지만 진행한다.

## 3. 정답의 구현 근거

### 같은 역할의 타이포

1장 `.terminal-cover-scene__title`, 2장 `.pair-statement`, 3장 `.three-scene .scene-statement`가 하나의 CSS 규칙을 공유한다.

```css
font-family: inherit; /* 본문 Pretendard */
font-size: clamp(2rem, 3.8vw, 3.7rem);
font-weight: 850;
line-height: 1.35;
letter-spacing: -.035em;
/* 강조 행: brand, weight 900 */
```

1280px에서 48.64px, 1920px에서 59.2px. 이 수치는 해당 본문 역할의 기준이다. 표지라는 이유로 GmarketSans로 바꾸거나 h1·캡션까지 이 크기로 만들지 않는다.

### 의미가 있는 경계

- 1·3장 장면 래퍼와 이미지: border·radius·shadow 없음. 어두운 이미지 바탕은 `mix-blend-mode: lighten`으로 연결한다. 다른 이미지의 색을 망가뜨리면 이 혼합 모드를 무조건 복사하지 않는다.
- 5장 첫 SVG: 창 바깥선과 상단 바는 “하나의 창”이라는 의미가 있어 남긴다. 세 번째 결과물 아래 장식선은 없다.
- 창 좌표: viewBox `0 0 300 180`, 창 y=8~170, 상단 바 아래 y=31. 내용 그룹 `translate(0 21)`, 실제 내용 y=62~139이므로 위·아래 **31 SVG 단위**씩이다.
- `.needs-orca-handoff`: 문구 + 로고 + Orca 이름, border 없음. 공통 헤더·푸터 구분선과는 별개다.

### 최종본과 에셋

HTTP 에셋은 `/assets/...`, `/artifacts/part2/_images/...` 루트 경로를 유지한다. 이 덱은 `file:`에서만 출력 폴더 깊이에 맞춰 프로젝트 루트로 이미지 경로를 해석한다. 직접 열기 지원을 다른 폴더에 복사할 때는 깊이를 다시 확인한다. 서버에서 200을 받는 것과 직접 열기 성공은 다른 검수다.

## 4. 다음 제작·수정 시 검수

1. 현재 승인 HTML과 최신 사용자 문구를 먼저 읽는다. 과거 이력의 중간 결과는 정답이 아니다.
2. 같은 템플릿의 장들을 나란히 보고, 지정된 기준 장과 **computed style**을 비교한다. 글자가 잘리지 않는 것만으로 통일됐다고 판정하지 않는다.
3. 요청된 요소의 화면과 DOM을 함께 확인한다. “1·3번 이미지”를 슬라이드 번호로 단정하지 말고 첨부 화면·선택 요소를 따른다.
4. 상태색·기호·설명 문구가 각각 상태 구별과 핵심 효용을 전달하는지 본다. 실제 데이터 연결이나 제품 스크린샷처럼 과장하지 않는다.
5. 1280×800, 1920×1080에서 전체 장을 캡처해 제목·캡션 줄 수, 이미지 로딩, 본문 넘침, 여백을 확인한다. 검수하지 않은 작은 뷰포트까지 보장하지 않는다.
6. 골든셋 등록 때는 승인 HTML을 재디자인하지 않는다. 정답 경로·해시·화면·실패 이유·적용 범위를 저장한다. 새 최종본이 승인되면 증거와 규칙을 함께 갱신한다.
