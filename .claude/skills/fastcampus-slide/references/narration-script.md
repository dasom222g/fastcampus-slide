# 슬라이드 대본 형식과 말투

사용자가 제공한 「Hermes Bot Mode 슬라이드 대본 (7장)」을 형식과 말투의 기준으로 삼는다. 해당 영상의 기술 내용이나 개인 경험을 다른 강의 대본으로 옮기지는 않는다.

## 형식

```markdown
## {클립 제목} 슬라이드 대본 (N장)

## 슬라이드 1/N — {실제 표지 제목} (표지)

오늘은 … 살펴볼 겁니다.

{실제로 읽을 수 있는 도입 문단}

## 슬라이드 2/N — {실제 슬라이드 제목}

{앞 장을 받아 화면의 내용을 풀어 설명하는 문단}

{다음 장으로 이어지는 문단}
```

- `i/N`은 실제 덱의 장수와 순서를 따른다. 제목은 화면 그대로 쓰며 비교용 v1·v2도 보존한다.
- 문단 단위로 작성한다. 개요 불릿, ‘여기서 설명한다’ 같은 제작 메모, 타임코드가 본문을 대신하지 않는다.
- 분량은 장의 역할에 맞춘다. 표지는 도입, 본문은 이해에 필요한 설명에 집중한다. 목표 시간을 맞추려고 같은 말을 늘이지 않으며, 낭독하지 않은 분량을 정확한 재생시간으로 단정하지 않는다.

## 말투와 흐름

- `~할 겁니다`, `~인데요`, `~거든요`, `~보겠습니다`, `~인 거죠`가 자연스럽게 섞이는 한국어 강의 구어체를 쓴다. 모든 문장을 같은 어미로 끝내지 않는다.
- 화면의 짧은 문구를 읽고 끝내지 않는다. 수강생이 화면에서 무엇을 봐야 하는지, 왜 그 내용이 다음 설명으로 이어지는지 풀어준다.
- 앞 장을 받아 개념을 설명하고 다음 장으로 이어간다. 이 흐름을 모든 장에 같은 상투 문장으로 찍어내지는 않는다.
- 낯선 용어는 실제 뜻부터 말한다. 비유나 업무 예시는 필요한 곳에서만 보조로 사용한다.
- 사용자 설명을 문장 그대로 복사하거나, 반대로 핵심 현상을 다른 사례로 바꾸지 않는다. 먼저 소스가 말하려는 주장과 인과를 보존한다.
- 사용자가 강조한 내용은 대본에서도 빠뜨리지 않는다. 이 프로젝트의 CH02-01에서는 현상 → 구조적 원인 → 원인별 해결이 그 축이다.
- `저도 써보니`, `직접 실험했더니` 같은 개인 경험·실험·수치는 사용자가 제공한 근거가 있을 때만 쓴다. 강의 진행을 나타내는 `이번에는 … 해볼 겁니다`는 사용할 수 있다.
- 새 제품 기능·사실·주장을 대본 작성 중 끼워 넣지 않는다. 자세한 설명이 필요해도 클립 소스의 범위와 확정 용어를 지킨다.
- ‘슬라이드 없음, 말로 전달’인 예고는 마지막 장 대본 끝에 자연스럽게 붙인다. 화면에 없는 예고 장을 추가하지 않는다.

## 완료 전 대조

최종 HTML을 기준으로 장수·번호·제목과 대본을 맞춘다. 각 장의 핵심과 시각이 말로 설명되는지, 소스의 원인·결과가 뒤바뀌지 않았는지 읽어 본다. 수정된 화면과 이전 대본이 섞인 채로 전달하지 않는다.
