# 골든셋 — 이미지·시각 밀도 기준 (7장 덱)

**출처:** 다른 프로젝트에서 1~9차 피드백을 거쳐 확정된 7장짜리 제품 설명 덱.
주제(Hermes)는 이 강의와 무관하지만 **이 문서가 가르치는 것은 주제가 아니라 시각 처리 기준**이다 —
이미지를 언제 어떻게 쓰는지, 카드에 무엇을 얼마나 담는지, 무엇을 크게 둘지.

> **이 문서를 주제가 다르다고 건너뛰지 마라.** 실제로 한 번 빠뜨렸다가
> 카드만 있는 화면과 검증 안 된 생성 이미지가 그대로 나왔다.

개념 사다리와 용어 정확성은 `goldenset-orca-judgment.md`를,
**시각적 크기·이미지·카드 밀도는 이 문서**를 기준으로 삼는다.
색 이름은 이 저장소 기준으로 옮겼다 — 원본의 teal이 여기서는 **brand(`#fc1c49`)**다.
---

## 1. 이 덱이 작동하는 이유

### 사용자가 보는 화면에서 시작해 내부 구조로 내려간다

```text
1  AI 단체 채팅방       사용자가 처음 보는 장면
2  봇의 정체            Bot은 사실 Profile
3  그룹의 제한          한 번의 사용자 메시지가 만드는 응답 상한
4  분리된 작업공간      같은 채팅방이어도 파일 공간은 분리
5  평범한 수렴          협업을 시켰을 때 실제로 드러난 품질 문제
6  수렴 방지 전략       문제를 막는 여섯 규칙
7  교차검증 흐름        규칙이 라운드에서 작동하는 방식
```

기능 목록으로 시작하지 않는다. 먼저 “여러 Bot이 한 채팅방에서 일한다”는 사용자의 화면을 보여주고, 다음 장에서 “그 Bot은 사실 Profile”이라고 내부 구조를 밝힌다. 정체를 이해한 직후 Group의 제한과 작업공간 분리를 붙여야 뒤의 실패가 제품 구조에서 나온다는 사실이 자연스럽게 읽힌다.

### 문제와 해결의 중심을 한 장씩 세운다

- 문제의 중심은 5번 `평범한 수렴` 한 장이다. 빠른 동의가 검증이 아니라 양보일 수 있다는 주장만 남긴다.
- 해결의 중심은 6번 `수렴 방지 전략` 한 장이다. 모델·순서 독립, 철회 기준, 원본 검증, Judge 재검증, 미해결 이견 보존을 흩뜨리지 않는다.
- 7번은 새로운 해결책을 추가하지 않고 6번 규칙이 라운드에서 어떻게 실행되는지만 보여준다.

초안의 `호출과 판단`, `채팅과 파일`은 기능 설명은 되었지만 이 중심축을 강화하지 않았다. 삭제 후 덱이 짧아진 것이 아니라 주장이 선명해졌다.

### 크게 보여줄 것은 카드 수가 아니라 메시지다

이 덱은 텍스트·이미지·카드를 모두 작은 안전 영역 안에 가두지 않는다.

- 표지 이미지는 본문 높이를 거의 모두 사용한다.
- 이미지 안에 이미 존재하는 왼쪽 네거티브 스페이스를 선언문 자리로 쓴다.
- 작업공간 장면은 이미지가 본문을 차지하고 결론 캡션만 오버레이한다.
- 6개 카드도 “tight”라는 이름만 믿고 줄이지 않고, 높이·패딩·제목·본문 크기를 다시 확보한다.

### 생성 이미지를 장식이 아니라 상태도로 검증한다

`분리된 작업공간` 이미지는 다음 상태가 동시에 맞아야 한다.

1. 회의실에는 아직 일하는 Bot이 남아 있다.
2. 파란 Bot은 자기 책상 쪽에서 회의실로 돌아간다.
3. 보라색 Bot은 회의실에서 파란 Bot의 자료를 보러 반대 방향으로 간다.
4. 발자국은 각 Bot의 출발점부터 현재 위치까지만 존재한다.
5. 이동 자세는 “자료를 찾느라 급한 상황”과 맞는다.
6. 결론 캡션이 달리는 Bot과 동선을 가리지 않는다.

그림이 예쁘더라도 이 여섯 조건 중 하나가 틀리면 설명 이미지로는 실패다.

### 기술 문장의 기준점은 시스템이 아니라 사용자다

초안의 `전송 한 번`은 무엇을 전송하는지 알 수 없고, `한 라운드 전체가 침묵`은 제품 동작을 전문적으로 설명하지 못한다. 최종본은 모두 `사용자 메시지 한 번`을 기준점으로 바꿨다.

```text
사용자 메시지 한 번
├ 최대 3개의 순차 Bot 응답 라운드
├ 최대 10개의 Bot 메시지
└ 한 라운드에서 모든 Bot이 응답하지 않거나 패스하면 조기 종료
```

정확한 용어를 유지하면서도 사용자가 실제로 하는 행동에 붙여 설명하면 문장이 쉬워진다.

### 색은 두 축만 남긴다

| 역할 | 색 | 용도 |
|---|---|---|
| 기본·Hermes·정의 | brand `#fc1c49` | 제목, 테두리, 기본 카드, 핵심 구조 |
| 대비·반박·수렴 방지 | blue-violet `#9188ff` | 문제의 수렴, 반박, 방지 전략 강조 |
| 보조 정보 | gray / pastel sky | 시스템 제한, 세 번째 묶음 |

pink·rose·lime은 일반 AI 장식처럼 보이거나 덱의 색축을 흔들어 사용하지 않는다. orange는 오류·경고처럼 의미가 분명하거나 실제 장면 속 물체의 고유색일 때만 쓴다.

## 2. 초안 → 최종 비교

| 축 | 초안 | 최종 | 판단 |
|---|---|---|---|
| 장수 | 9장 | 7장 | 설명을 더한 것이 아니라 핵심 서사에 필요 없는 2장을 제거했다 |
| 순서 | 제한이 뒤쪽에 있고 역할·호출 설명이 중간을 차지 | 채팅방 → 정체 → 제한 → 작업공간 → 수렴 → 전략 → 흐름 | 정체 다음에 구조적 제약을 붙여 문제의 원인을 먼저 이해시킨다 |
| 표지 | 이미지 왼쪽 여백 + 별도 텍스트 열 | 전체 프레임 이미지 + 내부 오버레이 | 이미지의 빈 공간을 두 번 만들지 않는다 |
| 표지 크기 | 낮은 이미지 박스와 작은 텍스트 | 본문 높이 100%, 큰 선언문, 넓은 프레임 | 초반부는 정보량보다 시각적 확신이 먼저다 |
| 작업공간 이미지 | 빈 회의실, 현재 위치보다 앞선 발자국, 느긋한 이동 | 회의실 Bot 2명, 교차 동선, 정확한 출발점과 현재 위치, 뛰는 자세 | 서사 이미지의 공간 논리를 검증한다 |
| 작업공간 설명 | 별도 `workspace-copy` + 하단 tip | 이미지 위 `THE REAL COST` 결론 캡션 | 한 장의 메시지를 이미지와 분리하지 않는다 |
| 협업 문제 | 여러 기능 장 사이에 핵심이 분산 | `평범한 수렴` 한 장 | 문제는 하나의 인과 흐름으로 보여준다 |
| 해결책 | 역할과 기능별 설명으로 흩어짐 | 6개 수렴 방지 규칙을 3×2 카드 한 장에 압축 | 해결의 본체가 규칙이면 역할보다 규칙을 먼저 보여준다 |
| 카드 밀도 | 작은 tight 카드 | 전용 spacious grid, 큰 높이·패딩·제목·본문 | 6장이라고 무조건 작게 만들지 않는다 |
| 제한 문장 | `전송 한 번`, 모호한 침묵 조건 | `사용자 메시지 한 번` 기준의 상한과 조기 종료 | 사용자 행동을 기준점으로 삼는다 |
| 색 | orange → rose → lime으로 흔들림 | brand + blue-violet | 역할이 없는 장식색을 추가하지 않는다 |

## 3. 최종 7장 구조

### 1 / 7 · AI 단체 채팅방 — 이미지 주도 표지

- 회의실 Bot 5명 이미지를 프레임 전체에 사용한다.
- 선언문은 이미지 왼쪽 네거티브 스페이스에 크게 겹친다.
- 이미지와 텍스트의 중심이 서로 멀어지지 않도록 이미지를 의도적으로 확대·우측 정렬했다.

### 2 / 7 · 봇의 정체 — TEXT

- `Bot = Profile` 등식 하나가 주인공이다.
- Model·Memory·Role·Skills는 속성 칩으로만 보조한다.

### 3 / 7 · 그룹의 제한 — METRIC

- `2–6 Bots`, `3 Rounds`, `10 Messages`를 사용자 메시지 한 번이라는 같은 기준으로 읽게 한다.
- 조기 종료 조건은 하단 한 문장으로 풀어 쓴다.

### 4 / 7 · 분리된 작업공간 — 대형 이미지 + 결론 캡션

- 이미지가 공간 분리와 왕복 비용을 설명한다.
- 캡션은 `자료를 찾고 다시 읽는 데 시간과 토큰을 더 쓴다`는 비용만 크게 말한다.

### 5 / 7 · 평범한 수렴 — ICON_ROW

- 요청 → 동조 → 무난한 합의의 한 방향 흐름이다.
- tip은 `수렴 ≠ 검증`이라는 해석만 남긴다.

### 6 / 7 · 수렴 방지 전략 — spacious CARD_GRID(6)

- 모델 독립, 순서 독립, 확신도 40%, 동의 전 검증, Judge 재검증 지시, 미해결 이견 보존.
- 카드 높이와 내부 여백을 충분히 주고 제목과 설명을 줄이지 않는다.

### 7 / 7 · 교차검증 흐름 — ICON_ROW

- R1 독립 판단 → R2 교차 반박 → R3 합의 감사.
- 앞 장의 규칙을 실행 순서로만 정리하고 새로운 개념을 추가하지 않는다.

## 4. 다음 덱 제작 체크리스트

### 구성 전에

- [ ] 사용자가 처음 보는 장면이 무엇인지 정했는가
- [ ] 기능 목록이 아니라 하나의 실패와 하나의 해결로 줄거리가 이어지는가
- [ ] 핵심 해결책이 여러 장에 흩어져 있지 않은가
- [ ] 삭제해도 주장이 유지되는 부가 슬라이드를 걷어냈는가

### 이미지 생성 전에

- [ ] 등장 인물 수와 각자의 역할을 적었는가
- [ ] 출발점·현재 위치·목적지·이동 방향을 적었는가
- [ ] 발자국·시선·자료 위치가 시간 순서와 맞는가
- [ ] 텍스트가 들어갈 네거티브 스페이스를 프롬프트에서 확보했는가

### HTML 제작 전에

- [ ] 이미지가 이미 가진 빈 공간과 별도 텍스트 열을 중복하지 않았는가
- [ ] 이미지·카드 높이를 먼저 확보했는가
- [ ] 6개 카드라 해도 제목·본문·패딩을 과도하게 줄이지 않았는가
- [ ] 기본 brand, 대비 blue-violet, 보조 gray/sky 안에서 색을 끝냈는가

### 완료 전에

- [ ] 1280×800에서 모든 슬라이드를 확인했는가
- [ ] 촬영 화면 비율에서도 표지 crop과 캡션 가림을 확인했는가
- [ ] 애니메이션이 모두 나타난 상태로 카드 6장과 이미지 슬라이드를 확인했는가
- [ ] 스토리보드·HTML·카운터·발표 노트·피드백의 장수와 순서가 일치하는가

## 5. 이 덱에만 맞았던 것 — 규칙화 금지

- **7장이라는 분량** — 핵심 서사가 이 길이에서 끝났을 뿐 다음 덱의 목표 장수가 아니다.
- **표지 이미지 `width: 113%`, `right: -1%`** — 해당 이미지의 인물 위치와 빈 공간에 맞춘 값이다.
- **Bot별 파랑·보라·주황 색과 발자국 모양** — 설명 장면의 캐릭터 연속성을 위한 선택이다.
- **2–6 Bots·3 Rounds·10 Messages** — Hermes 공식 동작 수치다.
- **확신도 40% 기준** — 이번 교차검증 프로토콜의 반론 유지·철회 기준이다.
- **`THE REAL COST` 문구** — 이 이미지의 결론 캡션에만 맞는 표현이다.
