# 제작 현황 대시보드

이론과 실습 72클립의 **자료 제작부터 편집까지** 진행 상황을 납품 차수별로 모은다.
**커밋할 때마다 자동으로 다시 만들어진다.**

## 켜기

저장소를 새로 클론했을 때 한 번만 실행한다.

```bash
sh dashboard/install.sh
```

`git config core.hooksPath dashboard/hooks`를 걸어 훅을 켠다. 끄려면 `git config --unset core.hooksPath`.

## 무엇이 자동이고 무엇이 수기인가

| 공정 | 어떻게 정해지나 |
|---|---|
| **슬라이드 제작** | 이론만 자동 — 덱 HTML이 없으면 미착수, 있으면 `작업중`, `CONFIRMED.md`에 있거나 소스 `상태`에 확정이 있으면 `완료` |
| **대본** | 자동 — 파일이 없으면 미착수, 있으면 `작업중`(초안), 촬영을 마쳤으면 `완료`. 강사 검수는 촬영 때 이뤄지므로 촬영 완료를 대본 확정으로 본다 |
| **실습자료 제작** | 실습만 수기 — `clips.json`의 `실습자료` 상태를 지정한다. 파일 존재나 촬영 완료에서 추정하지 않는다 |
| **촬영** | **수기** — 저장소에 촬영 기록이 없다. `clips.json`에서 직접 적는다 |
| **편집** | **수기** — 실습 기본값은 `편집 안 함`. 필요한 클립만 `시작전`·`예정`·`작업중`·`완료`로 지정한다 |

## 상태 다섯 가지

| 상태 | 뜻 |
|---|---|
| `완료` | 끝났다 |
| `작업중` | 손대고 있다 |
| `예정` | 미착수인데 곧 해야 한다 — **앞 공정이 끝났거나** 지금 납기의 파트다 |
| `시작전` | 미착수이고 아직 차례가 아니다 |
| `해당없음` (`—`) | 그 공정이 애초에 없다. 실습 클립의 대본, 필요 없는 실습자료 |

실습자료에는 `촬영용 완료`도 쓸 수 있다. 수강생에게 제공하지 않고 촬영 진행용으로만 만든 참고자료를 마쳤다는 뜻이다. 집계·다음 공정 판정·색상은 `완료`와 같고 칩의 글자만 다르다.

```json
{ "파트": 4, "클립": "Ch02-01", "슬라이드": false, "실습자료": "촬영용 완료", "촬영": "작업중" }
```

미착수 칸이 예정인지 시작전인지는 두 가지로 정해진다.

**첫째, 앞 공정이 완료면 다음 공정은 예정이다.** 제작을 마치면 대본이, 대본을 마치면 촬영이
곧 할 일로 올라온다. 이미 완료했거나 작업중인 칸은 건드리지 않는다 — 완료한 개별 공정은
그대로 완료다.

**둘째, 그 밖의 미착수는 `납기`를 보고 갈린다.** 남은 일이 있는 파트 중
**가장 이른 납기**가 지금 납기이고, 그 날짜를 가진 파트가 `예정`이 된다. 비워두면 전부 `시작전`이다.

```json
"납기": { "1": "2026-09-30", "2": "2026-09-30", "3": "2026-10-15" }
```

## 실습 클립

`슬라이드: false`인 클립은 **실습자료 제작 → 촬영 → 편집(필요 시)**으로 진행한다. 대본은 `해당없음`이며, 자료가 필요 없으면 실습자료도 `해당없음`으로 지정한다.
이론은 **슬라이드 제작 → 대본 → 촬영 → 편집**으로 진행한다. 실습자료 완료 후에는 대본을 건너뛰어 촬영이 `예정`이 된다.
촬영과 편집이 끝났으면 클립은 최종 완료다. `편집 안 함`이면 촬영 완료가 최종 완료다. 실습자료 자체의 기록을 임의로 완료나 해당없음으로 덮어쓰지는 않는다. 값이 없으면 미착수로 처리한다.

실습자료가 필요 없는 경우:

```json
{ "파트": 3, "클립": "Ch02-01", "슬라이드": false, "실습자료": "해당없음", "촬영": "작업중" }
```

```json
{ "파트": 3, "클립": "Ch02-01", "슬라이드": false, "실습자료": "작업중", "촬영": "시작전" }
```

번호·제목·계획 분량은 `docs/curriculum.md`가 정한다. 편집 완료 클립은 최종 영상에서 확인한 실제 분량을 표시한다.

비고에는 공개본명만 적는다. 공개본과 제목이 달라지면 `clips.json`의 해당 클립 `비고`에 `공개본 클립명: 원래 제목`을 남긴다. 챕터명이 바뀌면 해당 챕터의 클립 비고에 `공개본 챕터명: 원래 제목`도 함께 적고, 두 항목은 ` / `로 구분한다. 날짜·작업 설명을 앞뒤에 붙이지 않는다. `docs/curriculum.md`의 공개본 변경 목록도 갱신하고, 빌드 후 변경된 제목의 금색 표시를 확인한다.

## 배포 실습자료 상태 갱신

실습자료는 `fastcampus-orca-course/edu-note/`에서 작성한다. 작성·수정·검토를 맡은 에이전트가 실제 작업 후 해당 클립의 `실습자료` 상태를 직접 갱신하고 `python3 dashboard/src/build.py`를 실행한다. 자료와 클립의 대응, 승인·노션 반영 근거는 해당 폴더의 `status.md`에서 관리한다.

- 초안 작성·수정·자체 검토·최종 승인 대기·노션 반영 대기: `작업중`. 실제 수행 내용과 남은 단계는 `fastcampus-orca-course/edu-note/status.md`에 기록한다. 비고에는 작업 이력을 넣지 않는다.
- `완료`: 사람의 최종 승인과 노션 승격 요청을 받고 실제 노션 추가까지 확인한 상태. 승인·요청 근거와 실제 페이지 URL을 남긴다. 로컬 파일·촬영 완료만으로 추정하지 않는다.
- 제목 변경의 공개본 비고는 보존한다. 자료 작성만으로 촬영·편집·슬라이드·대본 상태를 바꾸지 않는다.
- 기존 1차 납기 기록은 재판정하지 않는다. 촬영 전용 참고자료의 `촬영용 완료`는 별도 용도이며 배포 자료를 완료 처리하는 대안으로 쓰지 않는다.
- 이 규칙은 노션 게시 지시가 아니다. 최종 승인과 승격 요청 없이 노션에 추가하지 않는다.

## 화면 테마

Palenight 계열의 푸른 회색 다크 테마를 기본으로 사용한다. 배경 `#292d3e`, 본문 `#d2d7eb`, 보조 텍스트 `#b0b7cf`이며 OS 라이트 모드에도 바뀌지 않는다. 차수는 파랑·보라·청록, 작업 상태는 초록·노랑·파랑으로 구분한다.

본문 16px, 클립 제목 17px, 상태 14px를 기준으로 한다. 이론(보라·책)과 실습(분홍·클릭)은 배경 없는 아이콘·텍스트로, 작업 상태는 채워진 배지로 구분한다. 글자를 줄여 표에 맞추지 않고 열 너비와 행 간격을 확보한다.

2차 납기부터 공개본과 달라진 클립명·챕터명은 글자 색상만 차분한 금색으로 바꾼다. 추가 문구·세로선·굵기 변경은 넣지 않는다. `비고`의 공개본 이름과 현재 제목을 비교해 자동 적용하며, 챕터 변경과 클립 변경은 별도로 판정한다. 1차 납기본은 강조하지 않는다. 제목이 공개본과 같아지면 강조를 해제한다. 원래 제목은 비고에 그대로 남긴다.

## 납품 차수와 필터

1차는 Part 1–4, 2차는 Part 5–7, 3차는 Part 8–10이다. `clips.json`의 `납품차수`에서 관리한다.
날짜를 몰라도 차수별 필터는 작동한다. 날짜를 정하면 `납기`에 적는다.

```json
"납품차수": [
  { "차수": 1, "납기": "", "파트": [1, 2, 3, 4] },
  { "차수": 2, "납기": "", "파트": [5, 6, 7] },
  { "차수": 3, "납기": "", "파트": [8, 9, 10] }
]
```

파트 중복 배정이나 잘못된 날짜는 빌드에서 거부한다. 미배정 파트는 별도 선택 영역에 표시한다.
기존 `납기`의 파트별 날짜도 호환하며, 차수 날짜가 있으면 차수 설정을 우선한다.

- 차수 버튼: 해당 납품의 클립만 표시. 다시 누르면 전체로 돌아간다.
- 유형·상태·검색: 함께 적용되며, 목록과 공정 집계가 같은 범위를 따른다.
- `전체 보기`: 차수와 필터를 모두 해제한다. 선택 조건은 URL에 유지된다.
- 차수 카드 집계: 필터와 무관하게 그 차수 전체 진행을 표시한다.
- 차수 카드 시간: 배정된 파트의 전체 클립을 합산해 `계획 시간`과 `실제 시간`을 시·분·초로 표시한다. 확인된 실제 분량이 없으면 `—`, 일부만 있으면 `N/M클립 집계`를 표시한다. 검색·유형·상태 필터로 카드의 합계는 바뀌지 않는다.
- `최종 완료`: 촬영 완료이며 편집이 `완료` 또는 `편집 안 함`인 클립. 편집이 남아 있으면 미완료다.
- `미완료`: 촬영 또는 필요한 편집을 마치지 않은 클립. 최종 완료와 더하면 그 납품의 전체 클립 수다.
- 차수 카드: 최종 완료와 미완료 클립 수를 나란히 표시한다. 미완료는 경고색으로 표시하고, 0이 되면 색을 뺀다. 진행 막대의 남은 구간도 같은 색으로 칠한다.
- 실습자료가 `해당없음`인 클립은 실습자료 집계의 분모에서 제외한다.

상태 변경은 파일에서 관리한다. 화면 필터는 상태를 수정하지 않는다.

## 촬영을 끝냈을 때

`dashboard/clips.json`에서 해당 클립의 `촬영`을 `완료`로 바꾸고 커밋하면 끝이다.

```json
{ "파트": 3, "클립": "Ch01-01", "슬러그": "ch01-01-what-is-git", "촬영": "완료" }
```

## 실제 영상 분량

편집 완료 또는 촬영 완료된 `편집 안 함` 클립은 `실제분량_초`에 저장 영상의 재생 시간을 초 단위로 기록하고, `영상파일`에 확인한 경로를 남긴다(저장소 기준 상대경로 가능).
`계획 / 실제` 열에 `11분 / 13분 06초`처럼 함께 표시한다. 계획 분량은 커리큘럼 기준이며 항상 유지한다.
실제 분량은 저장 영상에서 확인한 분·초다. `편집 안 함`도 촬영 완료 후 실제 파일을 확인했으면 분량을 표시하고 합계에 포함한다. 편집 완료 후 분량을 확인하지 않았으면 `확인 필요`, 아직 편집 전이면 `—`로 표시한다. 파일을 교체하면 실제 분량도 다시 확인해 갱신한다.
파트 헤더에도 클립 수와 `계획 36분 / 실제 29분 22초`처럼 구분을 붙인 총 시간을 표시한다. 필터를 적용하면 보이는 클립 기준으로 합산한다. 실제 시간이 없으면 `—`, 일부만 확인됐으면 `N/M클립 집계`를 덧붙인다.
제작·대본의 `_사유`는 내부 기록으로만 보존하고 화면이나 현황 문서의 비고에 자동으로 붙이지 않는다.

## 편집 상태

`clips.json`에 `편집`을 지정한다. 실습은 생략하면 `편집 안 함`, 이론은 미착수로 처리한다.
파일이 분리되어 합쳐야 하는 등 편집이 필요한 실습만 `작업중`으로 바꾸고, 끝나면 `완료`로 바꾼다.
`편집 안 함`은 미완료 작업이 아니며 편집 집계의 분모에서도 제외한다.
촬영 전인 클립은 편집이 필요 없어도 최종 완료가 아니다.

```json
{ "파트": 3, "클립": "Ch02-01", "슬라이드": false, "촬영": "완료", "편집": "편집 안 함" }
```

Part 1–4의 편집 초기값은 이론 `작업중`, 실습 `편집 안 함`으로 설정했다. 현재 상태는 `clips.json`에서 관리한다.

## 새 클립에 슬라이드를 만들기로 했을 때

`clips.json`의 `클립` 배열에 한 줄 더한다. `슬러그`는 소스를 만들기 전이면 `null`로 둔다.

```json
{ "파트": 5, "클립": "Ch02-02", "슬러그": null, "촬영": "시작전" }
```

## 저장소 밖에서 만든 덱

Google Slides처럼 저장소에 파일이 없는 덱은 `슬러그`를 `null`로 두고 `장수`를 직접 적는다.

```json
{
  "파트": 1, "클립": "Ch01-01", "슬러그": null, "장수": 8,
  "촬영": "시작전",
  "제작": "완료",
  "제작_사유": "Google Slides로 제작·확정"
}
```

## 자동 판정이 틀렸을 때

`제작` 또는 `대본` 키를 직접 적으면 그 값이 이긴다. 왜 덮어썼는지 `_사유`에 남긴다 —
남기지 않으면 「맞물림 검사」가 어긋난 것으로 잡는다.

```json
{
  "파트": 1, "클립": "Ch01-01", "슬러그": "ch01-01-course-intro",
  "촬영": "시작전",
  "제작": "완료",
  "제작_사유": "Google Slides로 제작·확정. 저장소에 HTML 덱이 없다"
}
```

## 맞물림 검사

빌드할 때마다 아래를 확인하고 대시보드 「맞물림 검사」와 커밋 로그에 띄운다.

- 소스 frontmatter의 `슬라이드: N장` ↔ 덱 HTML의 실제 장수
- 대본 첫 줄의 `(N장)` ↔ 덱의 장수
- `제작`이 완료·작업중인데 덱 HTML이 없는 경우
- `clips.json`에 있는데 커리큘럼에 없는 클립

| `dashboard/index.html` | 보기용 대시보드. 배포되면 `/dashboard` |
| `docs/production-status.md` | 같은 표의 마크다운본. 커밋 diff로 무엇이 진행됐는지 읽는다 |

둘 다 생성물이다. **직접 고치지 않는다** — 다음 커밋에서 덮어쓴다.

## 구조

```
dashboard/
  clips.json        수기 데이터 — 클립 목록 · 촬영 · 예외
  index.html        생성물
  install.sh        훅 켜기
  hooks/pre-commit  커밋 트리거
  src/build.py      스캔하고 그린다
  src/template.html 화면 껍데기
```

## 손으로 돌리기

```bash
python3 dashboard/src/build.py
```

## 검증

```bash
python3 -m unittest discover -s dashboard/tests -v
python3 dashboard/src/build.py
```

실습의 공정 건너뛰기, 촬영·자료 상태 분리, 차수 배정과 날짜 판정을 검증한다.
