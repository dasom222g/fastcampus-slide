# 패캠 슬라이드 작업 스타일 — 2026-10-06 인계

## 범위와 우선순위

이번 Part 5 슬라이드 대화에서 반복 확인된 사용자 요구다. Hermes 실습자료·LLM Wiki 차시 설계의 규칙은 가져오지 않았다. 최신 직접 지시 > 이 문서의 재사용 원칙 > 과거 사례 순으로 적용한다. 특정 장의 선택을 모든 장에 강제하지 않는다.

## 핵심 메시지와 내용

- 한 장은 하나의 결론을 전달한다. 구성 제안 요청 시 장별 헤드메시지를 최종 결론 한 문장으로 먼저 제시하고, 실습자료에 근거를 붙인다. 이 문장과 화면의 짧은 제목은 다른 역할이다.
- 실습 프롬프트의 모든 세부 조건을 슬라이드에 나열하지 않는다. 구조·판단·변경 영향처럼 설명할 핵심을 남긴다. 실습에서 할 실행 절차는 중복 장으로 늘리지 않는다.
- 사용자 고정 범위는 유지한다. 품질 게이트 덱은 ‘작업 기준과 품질 기준의 구분’까지 유지하고 그 뒤를 개편했다. 한 장 변경을 덱 전체 개편으로 확대하지 않는다.
- 실습자료·제공 양식과 실제로 대조한다. 별도 테스트 프로젝트의 조건을 강의 기준으로 혼용하지 않는다. 현재 아이템 후보 비교표의 총점 검사는 실제 제공 양식에 있는 항목이다.
- 사업 조건은 참고자료이고 시장 조사 노트·아이템 후보 비교표·판매 아이템 기획서는 산출물이다. 입력 변경과 산출물 변경을 혼동하지 않는다.
- 사용자에게 대조될 기준문서가 있으면 관련 구조에 드러낸다. 출처·선정 기준·사업 조건 등 실제 대조 대상을 구체적으로 명명한다.

## 제목·본문·문구

- 서브텍스트·하단 문구는 한 문장을 기본으로 하고, 쉼표는 의미 구분에 필요한 경우에만 쓴다. 호흡을 나눈다는 이유로 연결 어미 뒤에 반복해서 넣지 않는다.

- 의미 있는 짧은 제목과 한 줄 설명을 쓴다. ‘작성·수정 후 제출’, ‘검사·재검사’처럼 무엇을 하는지 빠진 추상적 축약은 피한다.
- ‘결과 문서 작성’, ‘품질 기준 대조·이유 기록’처럼 대상과 행위를 보존한다. 사용자가 단어를 고치면 확정 표현을 그대로 사용한다.
- 8장 최종 제목은 ‘품질 게이트 구조’. 화살표는 ‘완료 보고’와 ‘검사 통과’. 후자는 결과명 나열이 아니라 다음 작업으로 넘기는 조건을 표현한다.
- ‘서브텍스트’가 화면 상단 부제인지, 특정 요소 아래 설명인지 현재 장·요소로 구분한다. 반려 설명 수정 때 상단 부제로 잘못 옮긴 실패가 있었다.
- 제작자에게 준 수정 이유를 학습자 문구에 그대로 쓰지 않는다. 화면에 불필요한 안내·조건 설명을 추가하지 않는다.
- 사용자 질문은 먼저 짧게 답한다. 평가·이유 질문만으로 수정하지 않는다. 승인·수정 요청이 오면 해당 범위만 실행한다.

## 구조를 그리는 기준

- 구조가 핵심인 표지는 관계가 읽히는 도식이 우선이다. 생성 이미지가 순서·검사·반려를 설명하지 못하면 기존 구조형 표지를 유지한다. 단순 장면에는 이미지가 적합할 수 있으므로 이미지 자체를 금지하지 않는다.
- 순차·병렬·분기·반려·유지의 차이를 화살표와 배치로 읽히게 한다. 텍스트로 관계를 설명했다는 이유로 도식 의미 검수를 생략하지 않는다.
- 반려는 담당 워커에게 되돌아가는 점선과 반려 아이콘으로 표현한다. ‘담당 워커 수정’이라는 독립 박스를 만들어 별도 단계/주체처럼 보이게 하지 않는다.
- 반려 구간의 승인 문구: ‘반려·재작업 요청’ / ‘반려 항목·근거 전달’. 후자는 한 줄. 점선 바로 위에 두어 연결된 설명으로 보이게 한다.
- 통과는 초록 원형 체크 아이콘. 품질 기준 문서는 Coordinator 위, 역할 이름과 설명은 에이전트 아이콘 아래.
- 단계 전체를 한꺼번에 설명하는 복잡한 그림보다 한 단계의 검사·통과·반려가 읽히는 그림을 선호했다. 후보로 추가해 달라고 하면 기존 장은 유지하고 후보만 별도 추가한다. 채택 전 교체하지 않는다.
- 세 문서의 검사 기준을 한 요약 장에 뭉치기보다 문서별 세 장의 동일 UI를 택했다. 왼쪽 검사 대상·대조 자료 → Coordinator → 오른쪽 검사 항목. 세 장이 같은 문법을 써 비교하기 쉽게 한다.
- 영향 없는 문서는 회색의 비활성 느낌과 ‘영향 없음 · 기존 유지’로 표현한다. 모든 문서를 재작성하는 것처럼 보이지 않게 한다. 사용자가 선택한 9장 사례의 상태를 모든 조건 변경에 대한 보편 규칙으로 확대하지 않는다.

## 간격·색·화살표

- 소제목은 해당 콘텐츠 가까이에 붙인다. 남는 높이를 채우는 그리드 행 때문에 제목과 박스가 멀어지면 안 된다. 5~7장 최신 승인 간격은 20px다.
- ‘화살표를 짧게’라는 요청을 요소 사이 간격 축소로 해석하지 않는다. 품질 게이트 8장은 요소 위치를 유지하고 선 양끝을 줄여 요소와 화살표 사이 여백을 늘렸다. 사용자가 다른 장에서 에이전트 간격까지 줄이라고 명시했다면 그 장의 직접 지시를 따른다.
- Coordinator 명칭만 화면 위에 떨어뜨리지 않는다. 기준 장과 같은 아이콘 크기, 이름·설명 스타일, 정렬·간격을 적용한다.
- 겹치지 않는다고 적절한 여백인 것은 아니다. 연결 설명이 선에서 너무 멀면 관계가 끊겨 보인다. 반려 문구는 반환 가로선 위 20px로 맞췄다.
- 콘텐츠 영역을 충분히 쓴다. 의미 없는 자동 상단 마진으로 도식이 내려가면 줄인다. 9장은 사용자 지시로 콘텐츠 상단 여백 8px를 적용했다. 모든 장에 일괄 강제하지 않는다.
- 동일한 문서 역할은 같은 크기의 아이콘과 제목을 사용한다. 상단 사업 조건 변경을 작은 라벨처럼 만들지 않는다.
- 겹치는 직각 분기선은 독립 곡선으로 풀고, 출발점·도착점·화살촉 간격을 확보한다. 9장은 유지 회색, 재검토 낮은 채도 노랑, 수정 낮은 채도 주황. 선이 콘텐츠보다 강해지지 않게 한다.
- 9장 상단 문구는 ‘사업 조건 변경’ 한 줄뿐이다. 삭제 승인된 ‘초기 예산 축소’를 다시 넣지 않는다.

## 애니메이션과 실제 검수

- 읽는 순서대로 요소와 화살표를 함께 설계한다. 5~7장: 문서 묶음 → 입력 화살표 → Coordinator → 출력 화살표 → 확인 항목 → 하단 문장.
- 제목·아이콘·설명은 같은 의미 묶음으로 함께 등장한다. 본문 일부가 입장부터 고정 표시되거나 모든 노드가 나온 뒤 화살표만 늦게 등장하면 실패다.
- 도식은 페이드 중에도 좌표를 유지한다. 이동하는 요소를 기준으로 선을 계산해 화살표가 출렁이거나 어긋나지 않게 한다.
- 복사한 기존 UI도 다시 검수한다. 화살표 중심·끝 간격, 제목-콘텐츠 간격, 캡션 위치, 색의 의미, 순차 등장·재진입을 실제 화면에서 확인한다.
- 1920×1080 기본, 1280×800 보조. DOM 경계 검사와 캡처 시각 판단을 함께 사용한다. 마지막 프레임만 보지 않고 실제 진입·중간·완료·재진입을 확인한다.
- 컴퓨터유즈 검수는 하지 말라는 사용자 지시가 있다. 이번에는 로컬 미리보기와 agent-browser로 검수했다.

## 용어·승인·인계

- 도식 라벨: Coordinator, Worker, Worker A, Worker B. 설명: 코디네이터, 워커, 담당 워커. WorkerA·워커A·코디 등을 섞지 않는다. 기준은 앞선 승인 슬라이드와 docs/confirmed-copy.md다.
- 슬라이드 검수 완료와 대본 완료를 분리한다. 이번 PART 5 승인에는 대본이 포함되지 않는다. 기존 대본은 보존하고 후속 요청 전 자동 작성·동기화하지 않는다.
- 제작·사용자 검수·촬영·편집·배포를 구분한다. 파일 존재나 대시보드 갱신으로 촬영/배포 완료를 만들지 않는다.
- 완료 보고는 바꾼 위치와 실제 확인한 범위를 짧게 말한다. 미확인 결과를 검증됐다고 말하지 않는다. 사용자가 더 묻지 않았으면 설명을 길게 반복하지 않는다.
- 다른 에이전트와 같은 파일을 만질 때 최신 상태를 먼저 읽고 대상 부분만 수정한다. 현재 파일과 상대 세션의 완료 보고가 다르면 어느 한쪽을 자동 복원하지 말고 근거를 대조한다.

## 2026-10-13 피드백 회고와 재발 방지

### 무엇을 잘못했는가

- 앞 파트의 승인 화면을 실제로 대조하지 않고 익숙한 템플릿을 복사했다. 팀 소개의 앞 3장, 사람을 포함한 팀 구조, 보고선 표현까지 서로 달라졌다.
- 최신 실습자료와 최종 파일을 먼저 읽지 않아 없어진 blog.html, 임의의 근거 점수, 오래된 역할 배정을 설명했다. 플랫폼 역할의 예시를 고정 규칙처럼 쓴 것도 같은 실패다.
- 제목의 마지막 단어를 기계적으로 강조하고 부제를 보조 설명으로 채웠다. 그 장의 핵심 개념과 한 문장 결론이 약해졌다.
- 요소의 DOM 경계만 검사하고 실제 화면의 중심·간격·선 끝을 보지 않았다. 화살표가 텍스트 묶음과 겹치거나 너무 길었고, 상단에 몰린 배치와 빈 하단을 놓쳤다.
- 완성 프레임만 보고 애니메이션 검수를 끝냈다. 부모와 자식의 중복 등장, 연결선 선노출, 왼쪽 설명 뒤 불필요한 대기, 반복을 일회성으로 그린 오류를 놓쳤다.
- 승인·제작 완료·대본 완료를 섞고 변경된 클립명을 목록에 늦게 반영했다. 사용자에게 같은 지적을 반복하게 만들었다.

### 다음 작업에서 적용할 기준

1. 최신 커리큘럼 → 해당 실습자료·실행 요청문 → 실제 최종 결과물 → 같은 역할의 승인 슬라이드 순서로 대조한다. 현재 파일이 과거 회고보다 우선한다.
2. 제목은 무엇을 설명하는지, 부제는 이 장의 결론을 한 문장으로 쓴다. 키컬러는 핵심 의미 단위 한 곳에만 적용한다. 설명을 위한 예시에는 예시임을 짧게 표시하고 고정 조건으로 가르치지 않는다.
3. 팀 소개의 앞 3장은 표지 → 최종 결과물 → 협업 패턴이다. 협업 패턴과 실제 팀 운영 구조를 구분한다. 운영 구조는 사람·코디네이터·모든 담당 및 실제 산출물까지 확인하되 범례·부연을 임의로 늘리지 않는다.
4. 같은 주체를 순서 설명 때문에 두 번 그리지 않는다. 선행 결과가 있어야 후속 작업이 시작하는 의존, 코디네이터의 전달·배정, 워커의 보고를 각각 구분한다. 실제 보고·사람에게 전달하는 선은 기존 승인본의 실선 규칙을 따른다.
5. 단순 가로 연결은 직선으로 그린다. 선의 중심은 아이콘 기준으로 맞추고, 끝점 여백은 아이콘뿐 아니라 제목·설명을 포함한 요소 전체와 대조한다. 선을 짧게 할 때 요소 사이 간격까지 줄이지 않는다. 반복은 실제 출발 단계로 돌아오는 선을 그린다.
6. 본문 묶음은 남은 영역의 중앙에 두고 하단 문장은 별도 행으로 둔다. 하단 문장이 없는 장에 빈 하단 패딩을 예약하지 않는다. 카드 모서리·아이콘·타이포는 같은 역할끼리 일치시킨다.
7. 왼쪽 설명이 끝나면 오른쪽을 바로 순차 전개한다. 동시에 띄우라는 뜻으로 바꾸지 않는다. 의미 묶음 하나에 등장 효과 하나를 두고 부모·자식 중복 효과를 제거한다. 노드와 연결선은 위치 고정 페이드로 검수한다.
8. 1920×1080과 1280×800에서 전 장의 완성 화면을 본다. 진입·중간·완료·재진입·빠른 이동·리사이즈·모션 감소를 별도로 확인한다. DOM 넘침 0건만으로 검수 완료라 하지 않는다.
9. 앞 클립 내용을 중복하는 장과 불필요한 ‘다음 실습’ 문구는 넣지 않는다. 모델 선택 일반론 대신 이 강의의 팀 운영·실행 기록·결과 확인에 연결한다. 필요한 확인과 중복 낭비를 구분한다.
