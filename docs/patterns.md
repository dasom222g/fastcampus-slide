# 멀티에이전트 패턴 4가지

이 강의의 뼈대다. Part 5~8이 각각 하나씩 다루고, Part 1 Ch01-01에서 예고하며 Part 5 Ch01-01에서 다시 펼친다.
**모든 덱에서 이름·구조·색이 같아야 한다.** 슬라이드를 만들 때 이 표를 먼저 연다.

> 이름·정의는 `docs/confirmed-copy.md`(강사 확정 자료)에서 왔다. **바꾸지 않는다.**
> 프로젝트 매핑도 확정이다 — 01 판매 아이템 기획서 · 02 클라이언트 제안서·견적서 ·
> 03 프로모션 랜딩페이지 · 04 블로그·카드뉴스·스레드.

| # | 패턴 | 팀 | 한 줄 정의 | 난이도 | 파트 |
|---|---|---|---|---|---|
| 1 | **순차 파이프라인** | 기획팀 | 선행 에이전트가 결과물을 후행 에이전트로 넘기는 구조 | ★☆☆ | Part 5 |
| 2 | **교차 검증** | 영업팀 | 생성과 평가를 서로 다른 에이전트에 분리하는 구조 | ★★★ | Part 6 |
| 3 | **병렬 실행** | 디자인팀 | 동일 요청을 여러 에이전트에 동시 배분하는 구조 | ★★☆ | Part 7 |
| 4 | **R&R 분배** | 콘텐츠팀 | 하나의 소재를 역할별로 나눠 확장하는 구조 | ★★★ | Part 8 |

> **커리큘럼 순서와 난이도 순서가 다르다.** 커리큘럼은 순차 → 교차 검증 → 병렬 → R&R 순이고,
> 난이도는 순차(1) → 병렬(2) → 교차 검증(3) → R&R(3) 순이다. 표를 그릴 때 어느 축으로 정렬했는지 밝힌다.

## 색 배정 (덱 전체 고정)

| 패턴 | 색 |
|---|---|
| 순차 파이프라인 | brand (`#fc1c49`) |
| 교차 검증 | purple |
| 병렬 실행 | yellow |
| R&R 분배 | green |

`gray`는 사람·시스템·AI 아님, `orange`는 문제·반려·차단에 계속 쓴다. 패턴 색으로는 쓰지 않는다.

## 구조 — 도식으로 그릴 때

**구조 이해용 도식에서는 산출물의 구체적 이름을 넣지 않는다.** `시장 조사 노트`·`판매 아이템 기획서` 같은 프로젝트별 결과물은
Part 5~8의 해당 덱에서 쓰고, 패턴을 소개하는 자리에서는 **흐름의 모양만** 보인다. 결과물 이름이 들어가면
"이 패턴이 무엇인지"가 아니라 "이 프로젝트가 무엇을 만드는지"가 읽힌다.

### 1. 순차 파이프라인 — 한 줄로 이어지는 사슬

```
[에이전트 A] → [에이전트 B] → [에이전트 C] → 결과
```

- 핵심: **앞 단계의 산출물이 다음 단계의 입력이 된다.** 한 번에 하나씩 지나간다
- 도식: 가로 파이프라인. 단계 사이 화살표가 방향을 만든다 (`timeline` 타입)
- 강조할 것: 순서가 있다는 것. 되돌아오는 화살표가 없다

### 2. 교차 검증 — 되돌아오는 화살표가 있는 두 축

```
[Generator] ──작성──▶ [Evaluator]
     ▲                     │
     └────반려·수정 요청─────┘
                ↓
             통과 → 결과
```

- 핵심: **만드는 쪽과 검사하는 쪽이 다른 에이전트다.** 통과할 때까지 돈다
- 도식: 좌우 두 축 + **양방향 화살표**. 되돌아오는 화살표가 이 패턴의 정체다
- 강조할 것: 루프. 한 번에 끝나지 않는다
- 원문 용어 `Generator` · `Evaluator`를 타이틀에, 한국어를 딱지에 둔다

### 3. 병렬 실행 — 하나에서 갈라져 사람에게 모이는 부채꼴

```
        [같은 요청 하나]
         ╱          ╲
   [에이전트 A]   [에이전트 B]
         ↓            ↓
      [결과 A]     [결과 B]
         ╲          ╱
        [사람이 선택]
```

- 핵심: **같은 요청, 다른 에이전트.** 결과가 갈리고 **사람이 고른다**
- 도식: 위에서 갈라져 아래에서 다시 모이는 형태 (`fan` 타입 변형)
- 강조할 것: 두 갈래가 **동시에** 돈다는 것, 마지막 결정이 **사람**이라는 것 (gray로)

### 4. R&R 분배 — 하나의 재료가 역할별로 갈라지는 부채꼴

```
[조사·정리] ─┬─▶ [역할 A] ─▶ 산출물 A
             ├─▶ [역할 B] ─▶ 산출물 B
             └─▶ [역할 C] ─▶ 산출물 C
```

- 핵심: **같은 재료를 서로 다른 역할이 받아 각자의 산출물을 만든다.** 결과를 합치지 않는다
- 도식: 왼쪽 뿌리 → 오른쪽 여러 갈래 (`fan`을 가로로)
- 강조할 것: 병렬 작업과 **다른 점** — 병렬은 같은 일을 여럿이 하고 하나를 고르지만, R&R은 다른 일을 여럿이 하고 전부 쓴다

### 병렬 실행 vs R&R 분배 — 가장 헷갈리는 지점

둘 다 갈라지는 모양이라 나란히 놓으면 구분이 어렵다. **같은 시각 구조에서 뿌리와 잎만 바뀌게** 그린다.

| | 병렬 실행 | R&R 분배 |
|---|---|---|
| 갈라지는 것 | 같은 일 | 다른 일 |
| 에이전트 차이 | 서로 다른 에이전트 | 서로 다른 역할 |
| 결과 | 여럿 중 **하나를 고른다** | 여럿을 **전부 쓴다** |
| 마지막 | 사람의 선택 | 자동 완료 |
