### 강의 목표 — 확정

- 멀티 에이전트 오케스트레이션으로 내 업무를 나 대신 처리하는 에이전트 팀 구축
- 사람은 결정만 하고 실행은 에이전트가 맡도록, AI의 작업 환경과 위임 구조를 설계하는 능력 확보
- 가상의 오피스가 아닌 내 책상에서, 내 실제 업무 그대로 작동하는 시스템 완성

### 학습 목표 — 확정

- 에이전트 하나가 아닌 팀 단위로 일을 나누는 오케스트레이션 원리 이해
- 멀티 에이전트가 실패하는 세 지점을 파악하고 각각에 대응하는 구조 설계
- 워크트리로 결과물을 병렬로 받고 비교해서 선택하는 워크플로우 구축
- 내 업무 중 무엇을 맡기고 무엇을 직접 할지 판별하는 기준 확보

### 수료 후 기대효과 — 확정

- 내 업무를 아는 에이전트 팀 세팅이 담긴 결과물 폴더 확보
- 리서치, 기획서, 시안 비교, 콘텐츠 생산 공정을 에이전트에게 위임
- 회사 밖에서도 모바일로 작업 지시 및 진행 상황 확인
- 새 오케스트레이션 툴이 나와도 스스로 적용 가능한 기본기 탑재

**슬라이드에 미치는 영향**

- 표지 선언문과 마무리 문장은 위 세 블록에서 나온다. "가상의 오피스가 아닌 내 책상", "사람은 결정만 하고 실행은 에이전트가"가 강의를 관통하는 대비다
- 「멀티 에이전트가 실패하는 세 지점」은 Part 5 Ch01-02의 세 가지 이유(맥락 붕괴·유령 위임·검증 오류)와 같은 것을 가리킨다. 이름을 새로 만들지 않는다
- 「모바일로 작업 지시 및 진행 상황 확인」은 Part 9가 회수한다. 앞 파트에서 미리 설명하지 않는다

## 2. 청중 — 확정

수강 대상은 아래 넷이다.

- 기획도 마케팅도 실행도 혼자 다 하는 1인 사업가, 프리랜서, 크리에이터
- 사내에서 그 업무를 혼자 맡고 있어, 시작부터 끝까지 전부 본인 손을 거쳐야 하는 실무자
- AI 에이전트를 쓰고 있지만 여전히 모든 공정에 본인이 붙어 있는 비개발자
- 터미널 창 여러 개를 띄워놓고 무엇이 돌아가는지 놓쳐본 사용자

| 항목 | 내용 |
|---|---|
| 누구인가 | 위 네 갈래. 공통점은 **업무의 처음부터 끝까지가 한 사람 손을 거친다**는 것이다 |
| 선수 지식 | 클로드 코드나 코덱스를 **한 번이라도 실행해 본 정도**. 그 이상 요구하지 않는다 |
| 개발 경험 | **프로그래밍 지식 없어도 된다.** 코드를 읽을 줄 몰라도 되고 터미널을 잘 다룰 필요도 없다 |
| 이미 아는 것 | AI 에이전트를 써 본 경험. 터미널 창을 여러 개 띄워놓고 무엇이 돌아가는지 놓쳐본 경험 |
| 처음 보는 것 | 오케스트레이션, Orca, 워크트리, Git 저장소 개념, 멀티에이전트 패턴 |
| 안 오는 사람 | (미기재 — 필요해지면 채웁니다) |

**슬라이드에 미치는 영향**

- 청중이 개발자가 아닐 수 있으므로 **도메인 용어(브랜치·clone·체크아웃 등)를 제목에 쓰지 않는다.** 개념 하나만 남기고 정의부터 깐다
- 반대로 AI CLI 경험은 있으므로 "AI가 파일을 열어 작업한다" 수준은 길게 설명하지 않는다
- 터미널 화면이 자주 나오는 것을 부담으로 느낄 수 있다. 겁주는 표현을 쓰지 않는다

## 3. 톤과 문장

- **문체:** 담백한 서술체. 사실만 적고 수사·감탄을 넣지 않는다
- **단일 에이전트를 깎아내리지 않는다.** 되는 것을 먼저 인정한 뒤 안 되는 것을 말한다
- **현상보다 원인을 짚는다.** 원인을 알아야 해결책이 납득된다
- **수강생이 겪었을 상황으로 말한다.** "이 창 저 창 옮겨 다니며 결과를 넘겨주고 있다"처럼 자기 얘기로 읽혀야 한다
- **하지 말 것:** 과장, 검증 안 된 수치, "혁신적인"·"게임체인저" 같은 마케팅 어휘, 시적 표현

## 6. 강의를 관통하는 축

슬라이드가 반복해서 회수해야 할 메시지입니다. 표지 선언문과 마무리 문장이 여기서 나옵니다.

1. **'나처럼 일하는'이 아니라 '나 대신 일하는'** — 차이는 하나다. 내가 붙어 있어야 하는가
2. **다루는 것은 프롬프트가 아니라 구조** — 일을 나누고 넘기고 검사하는 구조
3. **패턴은 Orca에만 있는 개념이 아니다** — 그래서 도구가 바뀌어도 그대로 쓸 수 있다
4. **AI 활용의 핵심은 설계** — 어떤 에이전트를 어디에 배치하고 어떤 패턴으로 굴릴 것인가
